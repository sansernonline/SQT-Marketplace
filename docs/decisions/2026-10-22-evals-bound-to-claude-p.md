# ชุดวัดผลผูกกับ `claude -p` จริง · 2026-10-22

สถานะ: accepted

## ตัดสินใจ

ชุดวัดผลทุกชุดใน `evals/` (`triggers` · `speed` · `coding`) เรียก `claude -p` จริง ใช้บัญชีที่ล็อกอินอยู่ มีค่าใช้จ่าย · โหลดเฉพาะ plugin จาก repo (`--setting-sources project` · `--plugin-dir`) ไม่โหลด plugin ที่ติดตั้งในเครื่อง · รุ่นก่อนคือ git ref ที่ตัวรันแตก worktree ออกมาเอง `จากแหล่ง` (`scripts/evals/README.md` กติการ่วม)

## ทำไมไม่ใช้ทางที่ใครก็คาด

ทางปกติคือวัดด้วยของที่ถูกและซ้ำได้ — เรียก API ตรง จำลองคำตอบ หรือตรวจแค่ข้อความใน skill

- สิ่งที่วัดคือพฤติกรรมของ Claude Code ทั้งชุด: เปิด skill ที่ควรเปิดไหม (`triggers` — "ผ่าน = เปิดครบทุกตัวใน `expect_all`") · hook บอก skill ทำงานไหม · ทีมแบ่งงานกี่ตัว · test ที่ซ่อนไว้ผ่านไหม (`speed`) — ของพวกนี้เกิดในตัว harness ไม่ได้เกิดใน API `อนุมาน` จาก `scripts/evals/README.md` ตาราง "วัดอะไร" และ `scripts/evals/triggers/README.md` บรรทัด "ห้ามเครื่องมือเขียนไฟล์ รันคำสั่ง และส่ง agent จึงวัดแค่การเลือก skill ช่วงต้นงาน"
- ต้นทุนที่ยอมรับ: มีค่าใช้จ่ายต่อรอบ (triggers $0.05–0.15 · speed $0.5–2.5 · coding ไม่เกิน `--budget` ค่าเริ่ม $8 + ผู้ตัดสิน $1) `จากแหล่ง` · ผลแกว่ง จึงตัดสินจริงต้อง 2 รอบขึ้นไป (triggers 3 · speed 5) `จากแหล่ง`
- เหตุผลที่เลือก `claude -p` แทนการเรียก API ตรงหรือจำลอง **ไม่ได้เขียนไว้ใน README** — ข้อข้างบนเป็นการอนุมานจากสิ่งที่ชุดวัด `(ยังไม่ได้ตรวจ)` · ผลวัดรุ่นก่อนอยู่ใน `docs/research/skill-triggering.md` และ `docs/research/เร่งความเร็วงาน agent Claude Code.md` ตามที่ README ชี้ ยังไม่ได้เปิดอ่านในรอบนี้ `(ยังไม่ได้ตรวจ)`

## ขอบเขต

- ใช้กับทุกชุดใน `evals/` · แก้ skill agent หรือ hook ที่กระทบทั้งทีมแล้วต้องรันชุดที่เกี่ยวก่อนปล่อย
- ไม่ใช้กับ `validate-marketplace.mjs` และ `--verify` ของ `coding` ซึ่งไม่เรียก claude และฟรี

## ทบทวนเมื่อ

- Claude Code มีวิธีรัน harness แบบไม่เสียเงิน หรือแบบที่ผลไม่แกว่ง
- ค่าใช้จ่ายต่อรอบทำให้ไม่มีใครรันก่อนปล่อย (สัญญาณ: `RESULTS.md` ไม่มีแถวใหม่ 3 รุ่นติด)
