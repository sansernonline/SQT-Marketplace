## 1 · โครงที่ทุกระดับใช้เหมือนกัน

```
<ชื่อ-skill>/              ← ชื่อโฟลเดอร์ = ค่า name: ใน frontmatter (ห้ามต่างกัน)
├── SKILL.md              ← บังคับ · ไฟล์เดียวที่ต้องมี
├── scripts/              ← ไม่บังคับ · ไฟล์ที่ "รัน" ไม่ใช่ "อ่าน"
├── references/           ← ไม่บังคับ · ไฟล์ที่ "อ่านเมื่อต้องใช้"
└── assets/               ← ไม่บังคับ · เทมเพลต รูป ข้อมูล ที่คัดลอกไปใช้ทั้งไฟล์
```

`SKILL.md` หน้าตาแบบนี้เสมอ:

```markdown
---
name: srs-writing
description: Use when writing or reviewing a Software Requirements Specification …
---

# SRS Writing

เนื้อหา …
```

### สามชั้นของการโหลด — เหตุผลที่ต้องแยก 3 โฟลเดอร์

| ชั้น | อะไร | โหลดเมื่อไหร่ | ราคา |
|---|---|---|---|
| 1 | `name` + `description` | **ทุก session เสมอ** | ~100 token ต่อ skill |
| 2 | เนื้อหาใน `SKILL.md` | ตอนถูกเรียกใช้ | ควรต่ำกว่า 5,000 token |
| 3 | ไฟล์ใน `references/` `assets/` | ตอนถูกอ่านจริง | 0 จนกว่าจะอ่าน |
| — | โค้ดใน `scripts/` | **ไม่เข้า context เลย** | 0 · เข้าเฉพาะ output |

**นี่คือเหตุผลที่ `description` สำคัญที่สุด** — มันคือส่วนเดียวที่โหลดตลอดเวลา
และเป็นส่วนเดียวที่ใช้ตัดสินว่าจะเรียก skill นี้ไหม

### ข้อจำกัดที่เป็นทางการ

| | |
|---|---|
| `name` | ≤ 64 ตัว · a-z 0-9 และ `-` · ห้ามมีคำว่า `claude` หรือ `anthropic` · **ต้องตรงกับชื่อโฟลเดอร์** |
| `description` | 1–1024 ตัว · ห้ามมีแท็ก `< >` · **บอกทั้งว่าทำอะไร และใช้เมื่อไหร่** |
| เนื้อหา `SKILL.md` | ไม่เกิน 500 บรรทัด |
| ความลึกของการอ้างอิง | **ชั้นเดียว** — `SKILL.md` → ไฟล์อ้างอิง ได้ · แต่ไฟล์อ้างอิง → ไฟล์อ้างอิงอีกที ไม่ได้ |
| ขนาดรวม (อัปโหลดผ่าน API) | 30 MB ต่อ skill |

ตรวจทั้งหมดนี้ด้วย `node scripts/validate-marketplace.mjs`

## 2 · สี่ระดับ

ทั้งสี่ใช้โครงไฟล์ในข้อ 1 เหมือนกันหมด · ต่างกันแค่ที่วาง วิธีติดตั้ง และใครเห็น

### 2.1 ระดับบัญชี (account)

**ที่อยู่:** claude.ai → Customize → Skills → อัปโหลด `.zip`

**ใช้ได้ที่ไหน:** ทุกที่ที่ล็อกอินบัญชีนี้ — เว็บ, แอปเดสก์ท็อป, มือถือ, Cowork
**เป็นระดับเดียวที่แชตในคลาวด์แบบนี้เห็น**

#### โครงในไฟล์ zip

```
srs-writing.zip
└── srs-writing/
    ├── SKILL.md
    └── assets/
        └── srs-outline.md
```

**หนึ่ง zip หนึ่ง skill** · โฟลเดอร์ชั้นในต้องชื่อเดียวกับ `name:`

> ⚠️ เอกสาร API ระบุว่า `SKILL.md` ต้องอยู่ที่ราก แต่การอัปโหลดผ่านหน้าเว็บ
> รับแบบมีโฟลเดอร์ครอบ · **ยืนยันรูปทรงที่ถูกต้องตอนอัปโหลดไฟล์แรกจริง**
> ถ้าตัวแรกติด ให้ลองอีกแบบก่อนทำซ้ำอีก 33 ไฟล์

#### วิธีเรียกใช้

**ไม่ต้องพิมพ์อะไรเลย** — พิมพ์งานที่อยากทำตามปกติ ถ้า `description` ตรงกับงาน
Claude จะโหลด skill นั้นเอง

```
เขียน SRS สำหรับระบบจองห้องประชุมให้หน่อย
```

อยากบังคับให้ใช้ตัวไหน เรียกด้วยชื่อเป็นภาษาคนได้เลย:

```
ใช้ skill srs-writing เขียน SRS ระบบจองห้องประชุม
```

**ไม่มี slash command ที่ระดับนี้** — แชตบนเว็บกับมือถือไม่มีระบบ `/` แบบ Claude Code

**เช็กว่ามันอยู่จริงไหม:** claude.ai → Customize → Skills จะเห็นรายการที่อัปโหลดไว้ ·
หรือถามในแชตตรง ๆ ว่า "ตอนนี้มี skill อะไรใช้ได้บ้าง"

**อัปโหลดแล้วใช้ได้เลย** ไม่ต้องรีสตาร์ทอะไร — แต่แชตที่เปิดค้างไว้ก่อนอัปโหลดอาจยังไม่เห็น
เปิดแชตใหม่

#### ข้อจำกัดของระดับนี้

- `scripts/` รันไม่ได้ในบางสภาพแวดล้อม — คอนเทนเนอร์ของ API ไม่มีเน็ตและติดตั้ง package ไม่ได้
- อัปเดตคือ**อัปโหลดทับทั้งก้อน** ไม่ใช่แก้ทีละไฟล์
- แก้แล้วต้องอัปโหลดใหม่ทุกครั้ง — ไม่เหมาะกับของที่กำลังพัฒนาอยู่

### 2.2 ระดับเครื่อง (user)

**ที่อยู่:** `%USERPROFILE%\.claude\skills\<ชื่อ-skill>\SKILL.md`

**ใช้ได้ที่ไหน:** Claude Code ทุกโปรเจกต์บนเครื่องนั้น · **Cowork ไม่เห็น**

```
C:\Users\sanse\.claude\
├── settings.json
├── CLAUDE.md              ← กติกาการทำงาน โหลดทุกครั้งเสมอ (ไม่ใช่ skill)
└── skills\
    ├── srs-writing\
    │   └── SKILL.md
    └── ui-craft\
        └── SKILL.md
```

ลงด้วย `scripts\sync-global-skills.ps1` — คัดลอก core skills จากรีโปมาที่นี่ทั้งชุด

#### วิธีเรียกใช้

เหมือนระดับบัญชี — **พิมพ์งานตามปกติ** แล้ว Claude เลือกเอง

เพิ่มมาคือ Claude Code มี slash command ให้เรียกตรง ๆ:

```
/srs-writing
```

ใช้ได้กับ skill ที่ตั้ง `user-invocable` ไว้ · ถ้าตั้ง `disable-model-invocation: true`
ด้วย จะเรียกได้**เฉพาะ**วิธีนี้ ไม่ถูกเลือกอัตโนมัติอีกเลย

**ต้องรีสตาร์ท Claude Code หลังคัดลอกไฟล์เข้าไป** — ระดับนี้อ่านตอนเปิดโปรแกรม
ไม่ได้อ่านใหม่ระหว่างทาง

**เช็กว่าโหลดครบไหม:**

```
/doctor
```

**เหมาะกับ:** ของส่วนตัวที่ไม่ได้อยากแชร์ · หรือของที่กำลังลองอยู่

### 2.3 ระดับ plugin

**ที่อยู่:** `<marketplace>\plugins\<ชื่อ-plugin>\skills\<ชื่อ-skill>\SKILL.md`

**ใช้ได้ที่ไหน:** Claude Code **และ** Cowork บนเครื่องที่ติดตั้ง · แชร์ให้ทีมได้

```
SQT-Marketplace\
├── .claude-plugin\
│   └── marketplace.json          ← ประกาศว่ามี plugin อะไรบ้าง
└── plugins\
    └── software-company\
        ├── .claude-plugin\
        │   └── plugin.json       ← name · version · description
        ├── skills\               ← skill
        │   └── srs-writing\
        │       ├── SKILL.md
        │       └── assets\
        ├── agents\               ← sub agent (มีได้เฉพาะระดับนี้)
        │   └── business-analyst.md
        └── commands\             ← slash command (ของเก่า ทยอยย้ายไป skills/)
            └── feature-kickoff.md
```

#### สิ่งที่มีได้เฉพาะระดับนี้

| | |
|---|---|
| **agents/** | sub agent — ระดับอื่นไม่มี |
| **commands/** | slash command — ของเก่า เอกสารแนะนำให้ย้ายไป `skills/` ที่ตั้ง `disable-model-invocation: true` แทน |
| **เลขรุ่น** | `plugin.json` มี `version` · **ต้องเพิ่มเลขทุกครั้งที่แก้ ไม่งั้นเครื่องปลายทางไม่ดึงของใหม่** |
| **ชื่อนำหน้า** | skill ถูกเรียกเป็น `<plugin>:<skill>` จึงไม่มีทางชนกับระดับอื่น |

#### ข้อดีที่ใหญ่ที่สุดของระดับนี้

**plugin โหลดจากโฟลเดอร์รีโปโดยตรง** — แก้ `SKILL.md` แล้วสั่ง `/reload-plugins`
เห็นผลทันที ไม่ต้องคัดลอกไปไหน เหมาะที่สุดตอนกำลังพัฒนา skill

#### วิธีเรียกใช้

**ต้องติดตั้ง plugin ก่อน** — วางไฟล์ไว้เฉย ๆ ไม่ทำให้ skill เข้ามา

```powershell
.\scripts\install-marketplace.ps1
```

หรือทำเองใน Claude Code:

```
/plugin marketplace add "C:\_DATA\...\SQT-Marketplace"
/plugin install software-company@sqt-marketplace
```

ติดตั้งแล้วใช้เหมือนระดับอื่น — **พิมพ์งานตามปกติ** แล้ว Claude เลือกเอง

เรียกตรงต้องใส่ชื่อ plugin นำหน้า:

```
/software-company:srs-writing
```

เรียก agent ด้วยชื่อ agent ในคำสั่งภาษาคน:

```
ให้ business-analyst ช่วยแตก requirement ชุดนี้เป็น user story
```

**แก้ SKILL.md แล้วเห็นผลทันทีด้วย:**

```
/reload-plugins
```

**นี่คือข้อได้เปรียบใหญ่สุดของระดับนี้** — plugin อ่านจากโฟลเดอร์รีโปโดยตรง
ไม่มีสำเนาให้ลืมอัปเดต · ระดับอื่นต้องคัดลอกหรืออัปโหลดใหม่ทุกครั้ง

**เช็กว่าติดตั้งแล้วไหม:**

```
/plugin
```

#### ข้อสำคัญเรื่อง agent

`agents/*.md` ใช้คีย์ **`tools:`** ส่วน skill และ command ใช้ **`allowed-tools:`**
ใส่ผิดคีย์ loader จะเมินเงียบ ๆ ไม่มี error (validator จับให้แล้ว)

### 2.4 ระดับโปรเจกต์ (project)

**ที่อยู่:** `<โปรเจกต์>\.claude\skills\<ชื่อ-skill>\SKILL.md`

**ใช้ได้ที่ไหน:** ใครก็ตามที่เปิดรีโปนั้นด้วย Claude Code — **commit ขึ้น git ไปด้วยได้**

```
Dr-Screening\
├── .claude\
│   ├── CLAUDE.md                 ← กติกาของโปรเจกต์นี้ โหลดทุกครั้ง
│   └── skills\
│       └── fundus-figure-rules\
│           ├── SKILL.md
│           └── references\
│               └── color-palette.md
├── src\
└── README.md
```

**เหมาะกับ:** ความรู้ที่**ใช้ได้เฉพาะโปรเจกต์นี้** — ชุดสีของแผนภาพ
ตัวย่อเฉพาะทาง กติกาการตั้งชื่อไฟล์ผลลัพธ์ วิธีอ่านผลของโมเดล

#### วิธีเรียกใช้

**เปิด Claude Code ที่โฟลเดอร์โปรเจกต์นั้น** แล้วพิมพ์งานตามปกติ

```powershell
cd "C:\...\Dr-Screening"
claude
```

skill จะถูกเลือกเองเมื่องานตรงกับ `description` · เรียกตรงด้วย `/ชื่อ-skill` ได้เหมือนกัน

**เปิดจากโฟลเดอร์อื่นจะไม่เห็น** — ต้องอยู่ในรีโปนั้นจริง ๆ

**เพื่อนร่วมทีมได้ไปด้วยอัตโนมัติ** เพราะ `.claude\skills\` ถูก commit ขึ้น git —
เขา `git pull` แล้วเปิด Claude Code ก็ได้ใช้เลย ไม่ต้องติดตั้งอะไร

**นี่คือระดับที่ยังไม่ได้ทำสำหรับ Dr Screening****นี่คือระดับที่ยังไม่ได้ทำสำหรับ Dr Screening**

## 3 · เรียกใช้ skill ยังไง

### วิธีหลัก: ไม่ต้องเรียก

ทุกระดับทำงานเหมือนกัน — Claude เห็น `name` + `description` ของทุก skill อยู่แล้วตลอดเวลา
พอคุณพิมพ์งาน มันเทียบกับรายการนั้นแล้วโหลดตัวที่ตรงเอง

**คุณไม่ต้องจำว่ามี skill อะไรบ้าง** และไม่ต้องพิมพ์คำสั่งพิเศษ นี่คือวิธีที่ออกแบบมาให้ใช้

```
เขียน SRS สำหรับระบบจองห้องประชุม        → srs-writing ทำงานเอง
ทำ UI หน้าแดชบอร์ดคลังสินค้า              → web-app-design + ui-craft ทำงานเอง
วาดไดอะแกรมว่า service คุยกันยังไง         → software-diagrams ทำงานเอง
```

### วิธีที่ 2: เรียกด้วยชื่อเป็นภาษาคน

ใช้ได้ทุกระดับ ทุกแพลตฟอร์ม รวมแชตบนมือถือ

```
ใช้ skill presentation-design ทำเด็คเสนอลูกค้า
```

เหมาะตอน**รู้ว่ามีแต่มันไม่ขึ้นเอง** หรือตอนอยากบังคับตัวใดตัวหนึ่ง

### วิธีที่ 3: slash command

เฉพาะ Claude Code · เฉพาะ skill ที่ตั้ง `user-invocable`

```
/srs-writing                      ← ระดับเครื่อง และระดับโปรเจกต์
/software-company:srs-writing     ← ระดับ plugin ต้องมีชื่อ plugin นำหน้า
```

### เกิดอะไรขึ้นหลังมันถูกเรียก

เนื้อหาของ skill เข้ามาอยู่ใน context **แล้วอยู่ต่อจนจบ session**
ไม่ได้หายไปหลังตอบคำถามเดียว — เรียกครั้งเดียวก็มีผลกับทุกคำตอบหลังจากนั้น

ผลข้างเคียงที่ควรรู้: เรียก skill หนัก ๆ หลายตัวใน session เดียวจะกิน context ไปเรื่อย ๆ
ถ้าเริ่มงานคนละเรื่องกันจริง ๆ เปิด session ใหม่ถูกกว่า

### มันไม่ขึ้นเลย ทำยังไง

ไล่ตามลำดับนี้ หยุดเมื่อเจอ

| # | เช็คอะไร | แก้ยังไง |
|---|---|---|
| 1 | ติดตั้งหรือยัง | ระดับ plugin ต้อง `/plugin install` ก่อน · วางไฟล์เฉย ๆ ไม่พอ |
| 2 | รีสตาร์ทหรือยัง | ระดับเครื่องและโปรเจกต์อ่านตอนเปิดโปรแกรม · ระดับ plugin ใช้ `/reload-plugins` |
| 3 | อยู่ในรายการไหม | `/doctor` หรือ `/plugin` |
| 4 | `frontmatter` พังไหม | `node scripts\validate-marketplace.mjs` — `": "` ในค่าที่ไม่ได้ครอบเครื่องหมายคำพูดทำให้ skill หายทั้งตัวโดยไม่มี error |
| 5 | งานง่ายเกินไปไหม | คำสั่งขั้นตอนเดียวจะไม่เรียก skill เลยไม่ว่า `description` ดีแค่ไหน — เป็นพฤติกรรมปกติ |
| 6 | `description` ไม่ตรงงาน | **นี่คือสาเหตุที่พบบ่อยที่สุด** ดูข้างล่าง |

### `description` คือตัวตัดสิน ไม่ใช่เนื้อหา

เนื้อหาใน `SKILL.md` ไม่มีผลกับการตัดสินใจว่าจะเรียกหรือไม่เรียกเลย —
Claude เห็นแค่ `description` ตอนเลือก

เขียนให้ตรงสามข้อ:

1. **บอกทั้งว่าทำอะไร และใช้เมื่อไหร่** — "Use when …" แล้วตามด้วยสถานการณ์จริง
2. **ใส่คำที่ผู้ใช้จะพิมพ์จริง** — ถ้าคนพิมพ์ว่า "แดชบอร์ด" ก็ต้องมีคำว่าแดชบอร์ดอยู่ในนั้น
3. **บอกด้วยว่าเมื่อไหร่ไม่ใช้** — "ไม่ใช้กับ …" ช่วยตัดการชนกันระหว่าง skill ที่ใกล้เคียงกัน

> ⚠️ **อย่าเขียน `description` เป็นบทสรุปของขั้นตอน** — มันจะกลายเป็นทางลัดที่ Claude
> ใช้**แทนการอ่านเนื้อหา** มีเคสที่ `description` เขียนว่า "รีวิวโค้ดระหว่างงาน"
> แล้ว agent รีวิวรอบเดียวทั้งที่เนื้อหาบังคับสองรอบ
> `description` ควรมีแต่**เงื่อนไขว่าเมื่อไหร่ควรเรียก** ไม่ใช่สรุปว่าต้องทำอะไรบ้าง

## 6 · ชื่อชนกันและการวางซ้ำ

**ทุกระดับโหลดรวมกัน ไม่ทับกัน** — มี 4 ระดับก็เห็นครบ 4 ระดับ

**ลำดับเมื่อชื่อชนกัน:** องค์กร → เครื่อง → โปรเจกต์
**plugin ไม่เคยชน** เพราะถูกเรียกเป็น `<plugin>:<skill>`

### กฎข้อเดียวที่ต้องจำ

> **skill ตัวเดียวห้ามอยู่หลายระดับพร้อมกัน**

เพราะจะเกิดเหตุการณ์นี้: แก้ที่รีโป → `/reload-plugins` → ไม่เปลี่ยน →
เพราะตัวที่ทำงานจริงคือสำเนาใน `~\.claude\skills\` ที่คัดลอกไปตอนก่อน

**เลือกระดับเดียวต่อ skill หนึ่งตัว** ถ้าเคยคัดลอกไปหลายที่แล้ว ให้ลบตัวที่ไม่ใช้

`sync-global-skills.ps1` เก็บ `.sqt-synced.json` ไว้บอกว่ามันคัดลอกอะไรไปบ้าง —
ใช้ตามรอยตอนสงสัยว่าตัวไหนมาจากไหน

## 7 · เลือกระดับยังไง

| คำถาม | ระดับ |
|---|---|
| อยากใช้บนมือถือหรือในแชตบนเว็บด้วยไหม | **บัญชี** (ระดับเดียวที่ทำได้) |
| ทีมต้องใช้ด้วยไหม | **plugin** |
| ใช้ได้เฉพาะกับโปรเจกต์นี้ไหม | **โปรเจกต์** |
| กำลังพัฒนา แก้บ่อย | **plugin** (แก้แล้วเห็นผลทันที) |
| ส่วนตัวล้วน ไม่แชร์ | **เครื่อง** |

### สิ่งที่ไม่ควรเป็น skill เลย

**กติกาการทำงานที่ต้องใช้ทุกครั้ง** — ตอบสั้น · กางตัวย่อ · เขียนของชั่วคราวลง `_to_delete\`

ของพวกนี้ควรอยู่ใน **`CLAUDE.md`** ไม่ใช่ skill

| | CLAUDE.md | skill |
|---|---|---|
| โหลดเมื่อไหร่ | **ทุกครั้งเสมอ** | เฉพาะตอน `description` ตรงกับงาน |
| เหมาะกับ | กติกาที่ใช้กับทุกงาน | ความรู้เฉพาะงานประเภทหนึ่ง |
| ที่อยู่ | `~\.claude\CLAUDE.md` (ทุกโปรเจกต์) หรือ `<repo>\CLAUDE.md` (เฉพาะโปรเจกต์) | ดูข้อ 2.1–2.4 |

เอากติกาไปใส่เป็น skill แล้วมันจะไม่ถูกเรียกในงานที่ไม่ตรงคำอธิบาย
ซึ่งก็คือตอนที่อยากให้มันทำงานพอดี
