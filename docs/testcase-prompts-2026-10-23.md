# Test case prompts — สิ่งที่แก้ใน SQT-Marketplace (2026-10-23)

วิธีใช้: **1 เคส = 1 session ใหม่** ของ agent ที่โหลด marketplace แล้ว · วาง prompt ตามเคส · ตัดสินผ่าน/ไม่ผ่านจากคอลัมน์ "ผ่านเมื่อ" · เคสพวกนี้เป็น behavioral eval — โมเดลไม่ deterministic รันอย่างน้อย 2 รอบก่อนสรุป · ผ่านแล้วบันทึกวันที่ไว้ท้ายเคส (แบบเดียวกับตาราง eval ของ mcp-server)

สิ่งที่แก้รอบนี้: `presentation-design` (ขั้น 0 research + ลำดับเลือกสไตล์) · `html-slide-deck` (ธีมตามทิศทาง ค่าประจำบ้านเป็นตัวสำรอง) · `brief-to-image` (ขั้น 0 หา reference งานสวย) · `set-data-mcp` (server ใหม่) · `inventory-mcp` (eval เดิม ต้องรันซ้ำบน Claude Code)

---

## ชุด 1 · presentation-design (TC-PD)

### TC-PD-001: เด็คที่ต้องอ้างตัวเลข โดยไม่ให้ข้อมูลมา

**Type:** Functional · **Priority:** P1

**Prompt:**
> ทำ slide deck เรื่อง "ตลาด e-commerce ไทยปีนี้" 10 หน้า นำเสนอผู้บริหาร

**ผ่านเมื่อ:**
- มีขั้น research เนื้อหาก่อนเขียนหัวสไลด์ (ค้นเว็บ/แหล่งจริง ไม่ใช่ความจำโมเดล)
- หัวสไลด์ที่เป็นตัวเลขมีที่มาระบุ (แถบข้างหรือท้ายกระดาษ)
- เห็นร่องรอย research ในงาน (ลิงก์/ชื่อแหล่ง)

**ไม่ผ่านเมื่อ:** เขียนหัวสไลด์จากความจำโดยไม่มีแหล่ง หรือข้าม research ไปเปิดทำเด็คเลย

---

### TC-PD-002: ไม่มีดีไซน์โปรเจกต์ ไม่แนบต้นแบบ

**Type:** Functional · **Priority:** P1

**Prompt:**
> ทำเด็คขออนุมัติงบโปรเจกต์แอปจองคิวคลินิก 8 หน้า (โฟลเดอร์นี้ไม่มีดีไซน์อะไรเลย)

**ผ่านเมื่อ:**
- research เด็ค/งานนำเสนอประเภทเดียวกัน 2–3 ชุดก่อน
- เลือกทิศทางภาพ 1 อย่าง (พื้นสว่าง/เข้ม · ฟอนต์ · ความหนาแน่น) **พร้อมเหตุผล 1 บรรทัดและแหล่งที่ดู**
- หน้าตาสุดท้ายสอดคล้องกับทิศทางที่เลือก

**ไม่ผ่านเมื่อ:** ไหลไปใช้ Stage/พื้นเข้มประจำบ้านโดยไม่เคยดูงานอ้างอิง หรือเลือกทิศทางโดยไม่มีเหตุผล/แหล่ง

---

### TC-PD-003: โปรเจกต์มีดีไซน์อยู่แล้ว

**Type:** Functional · **Priority:** P2

**Preconditions:** โปรเจกต์มี `doc-theme` หรือสีแบรนด์ในโค้ด/โลโก้

**Prompt:**
> ทำเด็คสรุปความคืบหน้าให้ทีม 6 หน้า

**ผ่านเมื่อ:**
- ใช้สี/ดีไซน์ของโปรเจกต์ทันที (ลำดับเลือกสไตล์ขั้นแรกสุด)
- **ไม่** research ทิศทางภาพซ้ำ (ขั้น 0 ทำเฉพาะที่ขาด)

**ไม่ผ่านเมื่อ:** research ทิศทางใหม่ทั้งที่โปรเจกต์มีอยู่ หรือใช้สีประจำบ้านแทนสีโปรเจกต์

---

### TC-PD-004: ผู้ใช้แนบต้นแบบมา

**Type:** Functional · **Priority:** P2

**Preconditions:** แนบไฟล์เด็ค/ภาพต้นแบบไปกับ prompt

**Prompt:**
> ทำเด็คอบรมพนักงานใหม่เรื่อง PDPA 12 หน้า เอาหน้าตาแบบไฟล์ที่แนบ

**ผ่านเมื่อ:** ใช้ต้นแบบที่แนบเป็นลำดับสูงสุด ไม่ research ทิศทางใหม่

**ไม่ผ่านเมื่อ:** เพิกเฉยต้นแบบแล้วไป research หรือใช้ค่าประจำบ้าน

---

### TC-PD-005: เด็ค 2 ใบต่างเรื่องติดกัน ห้ามหน้าเหมือนกัน

**Type:** Integration · **Priority:** P1 — เคสที่ตอบปัญหา "ผลงานเหมือนกันหมด" โดยตรง

**Prompt (2 รอบ คนละ session):**
> รอบ 1: ทำเด็ค pitch สตาร์ทอปส่งอาหารเส้นทางชนบท
> รอบ 2: ทำเด็ครายงานผลประจำปีของมูลนิธิเด็ก

**ผ่านเมื่อ:** ทิศทางภาพของ 2 เด็คต่างกันโดยมีเหตุผล (งานต่างประเภท) และเด็คที่ 2 ไม่สืบทิศทางจากเด็คแรกโดยไม่ได้ดูว่างานต่างกัน

**ไม่ผ่านเมื่อ:** ออกมาพื้น/ฟอนต์/โครงหน้าเหมือนกันทั้ง 2 ใบ หรือเด็คที่ 2 อ้าง "ใช้ชุดเดิมจากเด็คก่อน"

## ชุด 2 · html-slide-deck (TC-HTML)

### TC-HTML-001: ทิศทางเป็นพื้นสว่าง

**Type:** Functional · **Priority:** P1

**Preconditions:** ทำ TC-PD-002 มาก่อนและทิศทางที่เลือกเป็นพื้นสว่าง (หรือสั่งตรง ๆ)

**Prompt:**
> ทำเด็ค html เรื่องผลการตรวจสุขภาพประจำปีของบริษัท ทิศทาง: พื้นสว่าง สะอาด ฟอนต์อ่านง่ายสำหรับผู้สูงอายุ

**ผ่านเมื่อ:**
- override `--bg` `--panel` `--line` `--text` `--soft` `--muted` `--dim` ใน `--css`
- เปิด `sheet-*.png` ตรวจคอนทราสต์ทุกแผ่น (มีขั้นนี้จริง ไม่ใช่บอกเฉย ๆ)
- `check_deck.py` ปัญหา 0 จุด

**ไม่ผ่านเมื่อ:** ออกมาพื้นเข้มตาม shell เดิม หรือ override แล้วไม่ตรวจคอนทราสต์

---

### TC-HTML-002: ทิศทางกำหนดฟอนต์อื่น

**Type:** Functional · **Priority:** P2

**Prompt:**
> ทำเด็ค html แนะนำร้านกาแฟ specialty ทิศทาง: พื้นครีม ฟอนต์หัวแบบ serif ไทย

**ผ่านเมื่อ:** ฟอนต์เปลี่ยนตามทิศทาง (ไม่ใช่ Chakra Petch/IBM Plex Sans Thai) และฟอนต์ที่เลือกมีทั้งไทย+อังกฤษในตระกูลเดียว มีตัวหนาจริง

**ไม่ผ่านเมื่อ:** ฟอนต์ประจำบ้านโผล่ หรือเลือกฟอนต์ที่ไม่มีภาษาไทยจนสระเบลอ

---

### TC-HTML-003: ไม่มีข้อมูลอะไรเลย → fallback ประจำบ้านยังทำงาน

**Type:** Boundary · **Priority:** P3

**Prompt:**
> ทำเด็ค html สรุปสถานะเซิร์ฟเวอร์ให้ทีม dev 5 หน้า (โปรเจกต์นี้ไม่มีดีไซน์ ไม่ต้อง research ทิศทาง เอาแบบบ้านเรา)

**ผ่านเมื่อ:** ใช้พื้นเข้ม + ฟอนต์ประจำบ้านได้ปกติ ไม่พัง — ยืนยันว่าตัวสำรองยังอยู่

**ไม่ผ่านเมื่อ:** สับสนว่าต้อง research (ผู้ใช้สั่งข้ามชัดเจน) หรือ build ไม่ผ่าน

## ชุด 3 · brief-to-image (TC-IMG)

### TC-IMG-001: หมวดใหม่ ไม่มี style lock — ต้องหา reference ก่อน

**Type:** Functional · **Priority:** P1 — เคสหลักของการเปลี่ยนนี้

**Prompt:**
> ขอภาพโปสเตอร์โปรโมตแอปของร้านดอกไม้ สำหรับลง IG

**ผ่านเมื่อ:**
- มีขั้นหางานจริงระดับดี 3–5 ชิ้นในหมวดเดียวกัน**ก่อน**เขียน brief
- แต่ละชิ้นมี 1 บรรทัดว่าทำไมถึงสวย (composition · light · palette · type)
- ลิงก์ reference ถูกเก็บใน `briefs/<ชื่อ>.md` หัวข้อ References
- บรรทัด style/palette/light ใน brief อ้างถึง benchmark เหล่านั้น

**ไม่ผ่านเมื่อ:** เขียน brief โดยเลือกสไตล์จากลิสต์เดิม (`photo` · `flat` · `3d` …) โดยไม่เคยดูงานจริง

---

### TC-IMG-002: มี style lock / brand kit อยู่แล้ว — ต้องข้ามขั้น 0

**Type:** Functional · **Priority:** P2

**Preconditions:** โปรเจกต์มี brand kit หรือ style lock sheet

**Prompt:**
> ทำภาพโพสต์ขึ้นชุดที่สองของแคมเปญเดิม ตาม style lock ที่มี

**ผ่านเมื่อ:** ข้ามการหา reference ใหม่ ใช้ style lock เดิมทันที

**ไม่ผ่านเมื่อ:** ไป research ใหม่แล้วทิศทางเพี้ยนจากชุดเดิม

---

### TC-IMG-003: เครื่องมือ gen รับ reference image

**Type:** Integration · **Priority:** P2

**Preconditions:** ใช้เครื่องมือที่รับ reference image ได้ (เช่น image_generation ที่รับ reference)

**Prompt:**
> (ต่อจาก TC-IMG-001) สร้างภาพจริงเลย

**ผ่านเมื่อ:** ป้อน reference 1–2 ชิ้นจากขั้น 0 ให้เครื่องมือ และบันทึก prompt + model + seed ข้าง brief

**ไม่ผ่านเมื่อ:** gen โดยไม่ใช้ reference ทั้งที่เครื่องมือรับได้

---

### TC-IMG-004: reference คือแถบวัด ไม่ใช่ของให้ลอก

**Type:** Negative · **Priority:** P2

**Prompt:**
> (ต่อจาก TC-IMG-001) เอาแบบ reference ชิ้นแรกเป๊ะ ๆ เลย

**ผ่านเมื่อ:** agent ปฏิเสธการลอกตรง ๆ และเสนอ concept ที่ยืนระดับเดียวกันแต่เป็นของตัวเอง (องค์ประกอบ/มุม/แสงต่างออกไป)

**ไม่ผ่านเมื่อ:** เขียน prompt เพื่อทำสำเนางานคนอื่นตรง ๆ

## ชุด 4 · MCP servers — regression (TC-MCP)

eval 3 ข้อของทั้ง 2 server อยู่ใน README ของตัวเองแล้ว · ที่ต้องทำเพิ่ม:

### TC-MCP-001: รัน eval ซ้ำบน Claude Code เมื่อมี claude CLI

**Type:** Integration · **Priority:** P1 · **สถานะ:** ยังรันไม่ได้ (เครื่องนี้ไม่มี claude CLI)

- `inventory-mcp`: 3 ข้อตามตารางใน `plugins/software-company/skills/mcp-server/assets/inventory-mcp/README.md`
- `set-data-mcp`: 3 ข้อตามตารางใน `tools/set-data-mcp/README.md`
- ผ่านเมื่อครบทั้ง 2 ตาราง แล้วลงวันที่แถว "Claude Code" เพิ่ม

### TC-MCP-002: Codex CLI เห็น tool ทุกครั้งหลัง startup_timeout_sec

**Type:** Regression · **Priority:** P1 — กันอาการ "ไม่พบ tool ทั้งที่ mcp list ขึ้น enabled" กลับมา

**Prompt (Codex CLI, รัน 3 ครั้งติด):**
> ใช้ tool setdata_get_quote ดูราคาหุ้น PTT

**ผ่านเมื่อ:** ทั้ง 3 ครั้งเรียก tool ได้จริง (เห็น `mcp: setdata/setdata_get_quote`) โดยไม่มีครั้งไหนบอก "ไม่พบ tool"

**ไม่ผ่านเมื่อ:** มีแม้แต่ครั้งเดียวที่โมเดลมองไม่เห็น tool → ตรวจ `startup_timeout_sec` ใน config ของ host นั้น

### TC-MCP-003: set-data-mcp ต่อ Settrade จริงแล้วต้องรัน eval ใหม่

**Type:** Integration · **Priority:** P2 · **สถานะ:** รอสมัคร Settrade Open API

- หลังเปลี่ยน `query()` ไปยิง API จริง: `source` ต้องเป็น `"settrade"` พร้อม `as_of` จริง ทุกแถว
- รัน eval 3 ข้อใหม่ทั้งระดับ server และระดับโมเดล แล้วบันทึกวันที่ทับ
