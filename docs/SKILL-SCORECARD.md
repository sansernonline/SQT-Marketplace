# วัดผล skill เป็นตัวเลข — แบบประเมินต่อ skill และต่อชุด

_ร่าง 2026-11-01 · ตัวเลขฐานรันจริง `node scripts/evals/scorecard.mjs` วันที่ 2026-11-01 ที่ main `5cc3076`_

**ข้อสรุป:** วัด skill ด้วย 5 ชั้นที่แพงขึ้นตามลำดับ แล้วให้แต่ละ skill ได้ **ระดับหลักฐาน** A ถึง D แทนคะแนนรวมตัวเดียว เพราะคะแนนถ่วงน้ำหนักซ่อนจุดอ่อน เช่น skill ที่เปิดถูกทุกครั้งแต่ทำงานผิดจะยังได้คะแนนกลาง ๆ · ตอนนี้ repo มีเครื่องมือวัดครบเกือบทุกชั้นแล้ว (`scripts/evals/`) แต่ 269 จาก 336 skill (80%) ยังไม่มีเคสเลย และเคสที่มีส่วนใหญ่ยังไม่เคยรัน · งานแรกจึงไม่ใช่สร้างเครื่องมือใหม่ แต่เป็นเติมเคสให้ skill ที่ผิดแล้วผู้ใช้เสียของจริง แล้วรันเป็นรอบ

คู่กับ [`SKILL-BENCHMARK-MAP.md`](SKILL-BENCHMARK-MAP.md) ซึ่งไล่ดูข้างในทุก skill ว่าตัดสินอะไรบ้าง (จัดขนาด · เลือก model · คิดเงิน · ตรวจผ่านไม่ผ่าน) และแต่ละเรื่องวัดเป็นตัวเลขได้อย่างไร

## 1 · คำถามที่ตัวเลขต้องตอบ

| คำถาม | ตัววัด | ชั้น |
|---|---|---|
| skill พร้อมให้วัดไหม | เคสครบ 3 แบบ · ข้อเท็จจริงมีวันที่ · สคริปต์มี self-test | 0 |
| Claude เปิด skill ถูกจังหวะไหม | อัตราเปิดเมื่อควรเปิด (recall) · อัตราเปิดผิด (false trigger) · เปิดตัวข้างเคียงแทน | 1 |
| เปิดแล้วงานดีขึ้นจริงไหม | อัตราผ่านเกณฑ์ ตอนมี skill เทียบตอนไม่มี (ส่วนต่าง = uplift) · ผ่านครบทุกรอบ (pass^k) | 2 |
| คุ้มไหม | token · เวลา · ค่าใช้จ่ายต่องานที่ผ่าน · ขนาด SKILL.md ที่กิน context | 3 |
| ใช้จริงแล้วเป็นอย่างไร | ถูกเปิดกี่ครั้งใน 30 วัน · ผู้ใช้แก้งานหลัง skill ทำ · ผู้ตรวจเจอข้อสูงต่องาน | 4 |

## 2 · 5 ชั้นของการวัด

### ชั้น 0 · ไฟล์อย่างเดียว ฟรี รันทุก commit

`node scripts/evals/scorecard.mjs` นับต่อ skill: เคสเปิด (`-trigger`) · เคสไม่ควรเปิด (`-negative`) · เคสพฤติกรรม (`-behaviour` `-guard` `-regression`) · จำนวนสคริปต์ · อยู่ใน router ไหม · แถวใน `expiry.json` · ขนาด SKILL.md · ใส่ `--md <ไฟล์>` ได้ตารางทุก skill

ตัวเลขฐาน 2026-11-01 (ตรวจจริง):

| plugin | skill | มีเคสเปิด | มีเคสไม่ควรเปิด | มีเคสพฤติกรรม | ระดับ C | ระดับ D |
|---|---|---|---|---|---|---|
| e-commerce | 48 | 15% | 15% | 15% | 7 | 41 |
| graphic-design | 27 | 63% | 19% | 56% | 5 | 10 |
| personal-life | 59 | 7% | 5% | 15% | 1 | 50 |
| software-company | 132 | 8% | 3% | 8% | 4 | 121 |
| superuser | 39 | 13% | 13% | 31% | 5 | 27 |
| trading-finance | 31 | 29% | 6% | 35% | 2 | 20 |

ตัวนับนับเคสชื่อ `-negative` และ `-no-trigger` เป็นฝั่งไม่ควรเปิด · เคสเปิด skill กลางในชุด `scripts/evals/triggers/` ยังไม่ได้นับรวม

### ชั้น 1 · เปิดถูกไหม ราคาถูก

ใช้ `scripts/evals/triggers/` (คำขอจริงที่ควรเปิด skill กลาง) กับเคส `-trigger` `-negative` ใน `plugins/<plugin>/evals/` ผ่าน `plugin-eval.mjs`

| ตัววัด | สูตร | เกณฑ์ผ่าน |
|---|---|---|
| recall | รอบที่เปิด ÷ รอบที่ควรเปิด | ≥ 0.90 |
| false trigger | รอบที่เปิดทั้งที่ไม่ควร ÷ รอบเคสไม่ควรเปิด | ≤ 0.10 |
| เปิดผิดตัว | รอบที่เปิด skill ข้างเคียงแทน ÷ รอบที่ควรเปิด | ≤ 0.10 |

ชุดเดียวกันใช้วัดทั้งชุดด้วย เพราะรายการ skill ยาวเกินงบ context แล้วคำอธิบายถูกตัด (`triggers/RESULTS.md` 2026-10-21 รอบก่อนแก้ผ่าน 2/20 · หลังแก้ 20/20) · ทุกครั้งที่เพิ่ม skill ต้องรันชุดนี้ซ้ำ เพราะ skill ใหม่ทำให้ตัวเก่าเปิดน้อยลงได้

### ชั้น 2 · งานดีขึ้นจริงไหม ราคากลาง

เคส `-behaviour` ใน `claude plugin eval` รัน 2 แขน (มี skill · ไม่มี skill) ผู้ให้คะแนนใช้ regex · เรียกเครื่องมือ · ไฟล์ที่ได้ ก่อนใช้โมเดลตัดสิน (เคส `doc-quotation-behaviour` เทียบยอด VAT กับผลสคริปต์ตรง ๆ เป็นแบบที่ควรลอก)

| ตัววัด | ความหมาย | ใช้ตัดสินอะไร |
|---|---|---|
| อัตราผ่าน (แขนมี skill) | ทำถูกตามเกณฑ์กี่ส่วน | skill ใช้ได้ไหม |
| uplift | อัตราผ่านมี skill ลบไม่มี skill | skill มีค่าไหม หรือ Claude ทำได้เองอยู่แล้ว |
| pass^k | ผ่านครบทั้ง k รอบ | ทำซ้ำได้นิ่งไหม (งานเงินและกฎหมายดูตัวนี้) |
| ช่วง 95% | ช่วงของอัตราผ่าน (Wilson) · ช่วงของ uplift (Newcombe วิธี 10 ประกอบจากขอบ Wilson) | ส่วนต่างเชื่อได้ไหม |

ตัวเลขชั้น 1–2 ทั้งตารางนี้คำนวณด้วย `node scripts/evals/skill-grades.mjs` จากไฟล์ผลของ `plugin-eval.mjs` และ `triggers/` (สูตรใน `scripts/evals/speed/stats.mjs` มี self-test) ไม่ต้องคิดมือ · เพิ่ม 2026-11-07

**กติกาตัดสิน:** รัน 3 รอบใช้ดูแนวโน้มเท่านั้น · จะบอกว่า skill ช่วยได้ต้องรันอย่างน้อย 10 รอบต่อแขน และขอบล่างของ uplift ต้องมากกว่า 0 · ผล 2026-10-26 ของ graphic-design (`plugins/graphic-design/evals/RESULTS.md`) ต่าง +0.11 ถึง +0.17 แต่ช่วงทับกันหมด จึงยังสรุปไม่ได้

### ชั้น 3 · คุ้มไหม

เก็บจากรอบชั้น 1–2 และ `scripts/evals/models/` · ตัวที่ใช้ตัดสิน:

- **ค่าใช้จ่ายต่องานที่ผ่าน** = ค่าใช้จ่ายรวม ÷ จำนวนรอบที่ผ่าน (ถูกกว่าดูค่าใช้จ่ายต่อรอบ เพราะ skill ที่ทำให้ผ่านมากขึ้นอาจแพงขึ้นต่อรอบแต่ถูกลงต่องาน)
- **token ส่วนเพิ่ม** = token แขนมี skill ลบแขนไม่มี
- **ขนาด SKILL.md** · เกิน 20 KB ตัวตรวจเตือนอยู่แล้ว (52 ไฟล์ ณ 2026-11-01) เพราะหลังบีบ context กฎท้ายไฟล์อาจหาย

### ชั้น 4 · ใช้จริง ฟรีแต่ต้องรอ

| ตัววัด | ที่มา |
|---|---|
| ถูกเปิดกี่ครั้งใน 30 วัน | `/skill-doctor` ของ Claude Code · log token ของ superuser |
| ผู้ใช้แก้งานหลัง skill ทำ | `learn/` และรอบ "รวมบทเรียน" (นับครั้งที่ผู้ใช้แก้เรื่องเดิม) |
| ข้อสูงจากผู้ตรวจต่องาน | รายงาน `reviewer` ในงานจริง |

ชั้นนี้บอกสิ่งที่ eval บอกไม่ได้ คือ skill ไหนไม่มีใครใช้เลย และ skill ไหนผ่าน eval แต่ผู้ใช้ยังต้องแก้

## 4 · ระดับหลักฐานต่อ skill

| ระดับ | เงื่อนไข | หมายความว่า |
|---|---|---|
| **D** | ไม่มีเคสเปิดและไม่มีเคสพฤติกรรม | ยังไม่รู้อะไรเลย |
| **C-** | มีเคสอย่างใดอย่างหนึ่ง | วัดได้บางส่วน |
| **C** | มีเคสเปิด · ไม่ควรเปิด · พฤติกรรม ครบ | พร้อมวัด |
| **B** | รันแล้ว · recall ≥ 0.90 · false trigger ≤ 0.10 · อัตราผ่านแขนมี skill ≥ 0.80 ที่ 3 รอบ | น่าจะใช้ได้ |
| **A** | B และ uplift ขอบล่าง > 0 ที่ 10 รอบต่อแขน และใช้จริงใน 30 วันโดยไม่มีผู้ใช้แก้เรื่องเดิมซ้ำ | พิสูจน์แล้วว่าช่วย |

ตัวนับชั้น 0 (`scorecard.mjs`) ให้ได้ถึง C · B และ A* (ส่วนที่วัดด้วย eval ได้) ให้โดย `skill-grades.mjs` จากผลรันจริง · A เต็มต้องเติมชั้น 4 (ใช้จริง 30 วัน) ด้วยมือลง `RESULTS.md` ของ plugin

**ใช้ระดับตัดสินอะไร**
- skill ที่ผิดแล้วผู้ใช้เสียเงิน ภาษี หรือสิทธิ์ ต้องถึง B ก่อนขึ้น 1.0.0
- รันถึง 10 รอบแล้ว uplift ไม่ต่างจาก 0 และไม่มีใครเปิดใน 30 วัน ให้เสนอรวมกับตัวข้างเคียงหรือถอด
- recall ต่ำแต่อัตราผ่านสูง แปลว่าเนื้อดีแต่คำอธิบายเรียกไม่ขึ้น ให้แก้ description ไม่ต้องแก้เนื้อ

## 6 · ข้อจำกัดที่รู้แล้ว

- `claude plugin eval` โหลด plugin ที่มี `dependencies` ไม่ขึ้น `plugin-eval.mjs` จึงทำสำเนาที่ลบ dependencies ก่อน รอบนั้นจึงไม่มี skill กลางของ superuser (เคยเสีย 35.39 ดอลลาร์ก่อนรู้ 2026-10-26)
- ผลแกว่งตามรุ่น Claude Code และโมเดล ให้จดรุ่นทุกครั้งที่รัน
- งานภาษา รสนิยม และหน้าตา ตัวเลขบอกได้แค่ว่าผ่านเกณฑ์ที่ตรวจได้ คำตัดสินสุดท้ายยังเป็นของผู้ใช้
