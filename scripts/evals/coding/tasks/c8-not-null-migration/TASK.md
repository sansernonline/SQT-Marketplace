# เพิ่ม region_code ให้ตาราง orders โดยไม่ล็อกตารางนาน

ฝ่ายขายอยากดูยอดแยกตามภาค เลยต้องเพิ่มคอลัมน์ `region_code` ในตาราง `orders` ค่ามาจากจังหวัดของลูกค้า (`customers.province`) เทียบกับตาราง `province_regions` ถ้าจังหวัดไม่ตรงกับตาราง (ตัวอักษรต่อตัวอักษร) หรือลูกค้าไม่ได้กรอก ให้ใส่ `'UNK'`

ไฟล์ `migrations/002_region_code.sql` ที่เขียนไว้ใช้ได้กับข้อมูลทดลอง แต่ตาราง `orders` จริงมีหลายแสนแถวและมี order เข้าตลอดเวลา รอบก่อนเราลองแบบนี้กับตารางอื่นแล้วระบบค้างไปหลายนาที

อยากให้แก้ไฟล์นี้ให้

1. หลังรันจบ `region_code` เป็น NOT NULL ค่าถูกทุกแถว และ order ใหม่ที่ไม่ใส่ `region_code` ต้องบันทึกไม่ได้
2. รันซ้ำได้ ถ้ารอบแรกค้างกลางทางหรือมีคนเผลอรันซ้ำ ต้องไม่ error และค่าไม่เพี้ยน
3. ไม่มีคำสั่งไหนแก้แถวใน `orders` เกิน 10,000 แถวในครั้งเดียว
4. ห้ามมีคำสั่งที่ทำให้ฐานข้อมูลไล่ตรวจทุกแถวของ `orders` ระหว่างถือล็อกที่กันการอ่านเขียนทั้งตาราง (ACCESS EXCLUSIVE) เช่น ตอนตั้ง NOT NULL หรือตอนเพิ่ม CHECK constraint
5. รันจบโดยไม่มี error หรือ WARNING ทั้งรอบแรกและรอบที่ 2

ไฟล์ migration รันด้วย `run-migration.mjs` ซึ่งรันทีละคำสั่ง แต่ละคำสั่ง commit เอง และมีคำสั่งพิเศษ `--@repeat` (ใส่เป็นบรรทัดก่อนคำสั่ง) ให้รันคำสั่งนั้นซ้ำจนไม่มีแถวถูกแก้ อย่าแก้ `run-migration.mjs` และ `seed.mjs` แก้เฉพาะ `migrations/002_region_code.sql`

ฐานข้อมูลเป็น PostgreSQL 17 ที่รันในตัว Node.js ผ่าน PGlite (PostgreSQL ที่คอมไพล์เป็น WebAssembly (WASM)) ไม่ต้องมี server ลองกับข้อมูลใหญ่ได้ด้วย `node seed.mjs ./data 200000` แล้ว `node run-migration.mjs ./data migrations/002_region_code.sql`

ลง package ด้วย `npm install` แล้วรัน test ของ repo ด้วย `npm test`
