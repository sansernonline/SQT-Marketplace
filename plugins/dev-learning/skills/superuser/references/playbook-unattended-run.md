# playbook · unattended-run — งานยาวที่ผู้ใช้ไม่อยู่ดู

ใช้เมื่อ: "ทำให้เสร็จ เดี๋ยวกลับมาดู" · "ไม่ต้องถาม" · งานหลายขั้นที่ผู้ใช้จะมาตรวจทีเดียว — เช่น เตรียมแผนสอบใบรับรองทั้งเล่ม · ทำเรดาร์ย้อนหลัง 1 เดือน
เป็นตัวห่องาน ไม่ได้แทน playbook ของงาน — คุมการทำต่อจนจบ ส่วนแต่ละชิ้นข้างในยังเลือก playbook ตามงานตามปกติ
skill หลัก: ตาราง "การตัดสินใจ" และ "รับงานต่อ" ใน `CONTEXT.md` · หัวข้อ 6 และ 7 ของ `superuser`

## ขั้นตอน (คัดลง todo ตรงตัว)

1. เขียนเงื่อนไขจบที่ตรวจได้ — ไฟล์ไหนต้องมี · ตารางไหนต้องครบ · ร่างไหนต้องพร้อมส่ง · รันด้วย `claude -p` → ใส่ `--max-budget-usd <งบ>` เสมอ (ไม่รู้งบ → ถามรวมในคำถามครั้งเดียวตอนเริ่ม) ชนเพดาน = `ติด` แล้วรายงานว่าทำถึงไหน · ใคร: หัวหน้าทีม
2. แตกงานเป็นชิ้นที่แต่ละชิ้นจบด้วยการตรวจ แล้วเลือก playbook ย่อยให้แต่ละชิ้น หัวหน้าทีมประสานงานและตรวจ แล้วแจกชิ้นให้ subagent ตัวใหม่ทีละชิ้น · ใคร: หัวหน้าทีม
3. ทำทีละชิ้น — ผ่านเกณฑ์หัวข้อ 4 แล้วค่อยไปชิ้นถัดไป ถ้าชิ้นไหนพัง 2 รอบ → แตกเป็นขั้นย่อย ไม่ลองแบบเดิมซ้ำ · ครบ 3 รอบ → หยุดชิ้นนั้น ลงเป็น `ติด` แล้วไปชิ้นอื่น · ใคร: `tech-mentor` ตัวใหม่ต่อชิ้น · ตรวจ: `reviewer` ตัวใหม่
4. ทุกครั้งที่เลือกทางเอง ให้ลงตาราง "การตัดสินใจ" ทันที ไม่รวบไปเขียนตอนจบ · ใคร: หัวหน้าทีม
5. ถ้าเจอรายการ "รออนุมัติ" (สมัครสอบ · ซื้อคอร์ส · push repo สาธารณะ) ให้เตรียมให้พร้อมกด แล้วลงใน "รออนุมัติ" ห้ามทำเอง ส่วนคำถามที่ต้องให้ผู้ใช้ตอบให้ลงใน "ค้างอยู่" · ใคร: หัวหน้าทีม (อนุมัติ: ผู้ใช้)
6. จบแต่ละชิ้นแล้วให้เขียน "รับงานต่อ" ใน `CONTEXT.md` ใหม่ และดู `.claude/superuser/inbox/` ถ้ามี ผู้ใช้ที่กลับมากลางทางจะได้เห็นสถานะล่าสุด · เริ่ม session ใหม่กลางงาน → รันตัวตรวจ "เสร็จเมื่อ" ของชิ้นล่าสุดที่ `เสร็จ` 1 ครั้งก่อนทำชิ้นถัดไป ไม่ผ่าน → แก้ชิ้นนั้นก่อน · ใคร: หัวหน้าทีม
7. เมื่อจบงาน ให้ตรวจเงื่อนไขข้อ 1 ทั้งหมดอีกรอบ แล้วรายงานครั้งเดียว: เสร็จอะไร · ติดอะไร · ตัดสินใจเองกี่ข้อ · รออนุมัติอะไร · ค้างอะไรให้ผู้ใช้ตัดสิน · ใคร: หัวหน้าทีม (ตรวจเงื่อนไขซ้ำ: `reviewer` ตัวใหม่)

## จบเมื่อ

เงื่อนไขข้อ 1 ผ่านทั้งหมด หรือชิ้นที่เหลือทุกชิ้นมีเหตุผลว่าทำไมติด
