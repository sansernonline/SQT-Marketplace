# ทะเบียนกฎธุรกิจ (Business Rule Register)

คัดลอกไฟล์นี้เป็น `docs/as-is/04-business-rules.md` · กฎหนึ่งข้อต่อหนึ่งแถว · ID ไม่นำกลับมาใช้ซ้ำแม้กฎถูกยกเลิก

ป้ายความมั่นใจ: โค้ด = อ่านเจอในโค้ด (`จากแหล่ง` · สูง) · คู่มือ = ตามคู่มือ ยังไม่ได้เทียบโค้ด (`จากแหล่ง` · กลาง) · อนุมาน (`อนุมาน`) · ต้องถาม (`ยังไม่ได้ตรวจ`) · กฎที่ change request จะใช้ ใส่ commit hash ของโค้ดที่อ่าน และสิ่งที่ยังมองไม่เห็น

| ID | Module | กฎ (ภาษาคน) | บังคับที่ไหน | ป้าย | ที่มา | ตารางที่เกี่ยว | หมายเหตุ |
|---|---|---|---|---|---|---|---|
| BR-[MOD]-001 | [module] | [ประโยคเดียว เช่น จองท่าล่วงหน้าได้ไม่เกิน 30 วัน] | server / client only / DB / report | โค้ด | `path/File.cs:123` | `TABLE_NAME` | [client only = ข้าม UI แล้วผ่านได้] |

## การ์ดกฎ — สำหรับกฎที่ change request จะแตะ หรือป้ายไม่ใช่ "โค้ด"

แถวในตารางพอสำหรับกฎทั่วไป · กฎที่จะถูกแก้หรือยังไม่แน่ใจ ทำการ์ดเพิ่ม 1 ใบต่อกฎ ให้คนที่ไม่ได้อ่านโค้ดตรวจได้

```markdown
### BR-[MOD]-001 · [ประโยคเดียวเหมือนในตาราง]
- ที่มา: `path/File.cs:123` (commit `abc1234`)
- ตัวอย่างค่าจริง: Given [สถานะเริ่มพร้อมค่าจริง เช่น วันนี้ 2026-11-10 ท่า A ว่าง] · When [การกระทำ เช่น จองวันที่ 2026-12-15] · Then [ผล เช่น ระบบปฏิเสธ "เกิน 30 วัน"]
- ค่าที่ฝังในโค้ด: [30 วัน · สถานะ "N" · รหัส 99 — บอกว่าควรย้ายไป config ไหม]
- ความมั่นใจ: สูง / กลาง / ต่ำ · เหตุผล 1 บรรทัด
- ถามผู้รู้ (ถ้าไม่ใช่ "สูง"): [คำถามเดียวที่ตอบได้ด้วยใช่/ไม่ใช่ หรือตัวเลข → ลง `05-open-questions.md`]
```

ข้อมูลส่วนตัวหรือรหัสผ่านที่เจอในโค้ดหรือข้อมูลตัวอย่าง ปิดค่าก่อนใส่การ์ด · ที่มาของรูปแบบการ์ด: code-modernization (Apache-2.0) · `agents/business-rules-extractor.md` · ดู 2026-11-10

## กฎที่ขัดกัน

กฎเดียวกันแต่โค้ดสองที่ทำไม่เหมือนกัน หรือโค้ดไม่ตรงกับคู่มือ — ทุกแถวต้องมีคำถามคู่กันใน `05-open-questions.md`

| กฎ | ที่ 1 | ที่ 2 | ต่างกันตรงไหน | คำถาม |
|---|---|---|---|---|
| | `A.cs:10` | `B.cs:88` | | Q-0xx |
