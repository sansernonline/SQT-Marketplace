# parallel-split-and-merge — แบ่งงาน ทำพร้อมกัน รวมเป็นรายงานเดียว
> ใช้คู่กัน: `principle-build-a-tool-not-handwork` (เขียนสคริปต์ทำงานซ้ำ) · `principle-small-verifiable-steps` (ตัดเป็นชิ้นเล็กที่ตรวจได้)

> ต่างจาก `parallel-attempts-pick-best` ตรงที่แต่ละตัวทำ**คนละชิ้น** ไม่ใช่แข่งทำชิ้นเดียวกัน

มาจาก `swarm` ของ pstack

## ขั้นตอน

0. **วางของกลางก่อนแบ่ง** — รูปข้อมูล · interface · ไฟล์กลาง ตัวหลักทำคนเดียว · ชิ้นเล็ก (โค้ดไม่ถึงราว 40 บรรทัด) ไม่ต้องแยกออกไป ตัวหลักทำเองเร็วกว่า · ใบสั่งงานทุกตัวใช้แบบ 5 ส่วนเดียวกันตาม `superuser` หัวข้อ 5 "แบ่งงาน"
1. **แบ่งให้ไม่ทับกัน** — เขียนตารางแบ่งงาน `| ชิ้น | ขอบเขต (ไฟล์ · หน้าจอ · กรณี) | worker |` ทุกส่วนของงานอยู่ในชิ้นเดียวพอดี ไม่ซ้ำ ไม่ตก
2. **รูปแบบรายงานเดียวกันทุกตัว** — กำหนดหัวข้อที่ต้องส่งกลับ เช่น `| สิ่งที่พบ | ไฟล์:บรรทัด | ความรุนแรง | หลักฐาน |` เพื่อรวมได้โดยไม่ต้องตีความ
3. **ห้ามเขียนที่เดียวกัน** — งานอ่านอย่างเดียวปล่อยได้เลย งานที่แก้ไฟล์ให้แยก git worktree ต่อตัวตามหัวข้อ "worktree ต่อตัว" ข้างล่าง (เบาและเร็วกว่าห้อง Docker บน Windows) ส่วนไฟล์สรุปรวมให้ตัวหลักเขียนคนเดียว
4. **ขนาดชิ้น** — ชิ้นละไม่เกินสิ่งที่ subagent ทำจบในรอบเดียว (ราว 5 โมดูล หรือ 10 หน้าจอ) และปล่อยพร้อมกันไม่เกิน 8 ตัว
5. **ปล่อยทุกตัวในข้อความเดียว** รันเบื้องหลัง โดยส่งตำแหน่งไฟล์แทนเนื้อหา และเลือก agent ตามงาน (`qa-tester` ตรวจ · `developer` แก้ · `system-analyst` อ่าน)
6. **รอให้ครบ** — ห้ามสรุปจากตัวที่เสร็จก่อน ถ้าตัวไหนล้มให้ปล่อยตัวใหม่ทำซ้ำ 1 ครั้ง ถ้ายังล้มอีกให้บันทึกว่าชิ้นนั้นไม่ได้ตรวจ
7. **รวม** — ตัดข้อซ้ำ แล้วจัดกลุ่มสิ่งที่เป็นเรื่องเดียวกัน (หลายรายงานที่ต่างกันเล็กน้อย มักชี้ไปที่ต้นเหตุเดียวที่อยู่สูงกว่า) และยืนยันข้อที่ร้ายแรงด้วยตัวเองก่อนรายงาน
8. **รายงานเดียว** — สรุป 1 ย่อหน้า · ตารางรวม · ชิ้นที่ไม่ได้ตรวจ (ถ้ามี) · `status-report`

## worktree ต่อตัว

- **`git status` สะอาด** → subagent ใส่ `isolation: worktree` และตั้ง `"worktree": { "baseRef": "head" }` ใน `.claude/settings.json` · ถ้าไม่ตั้ง worktree จะแตกจาก branch หลักบน remote = ได้โค้ดเก่า
- **มีงานที่ยังไม่ commit** (ปกติ เพราะ commit ต้องรออนุมัติ) → worktree ในตัวมองไม่เห็นงานนั้น · หัวหน้าทีมสร้างเองแบบไม่ commit และไม่แตะ branch:
  ```bash
  base=$(git stash create); base=${base:-HEAD}       # ถ่ายภาพไฟล์ที่ track ไว้ โฟลเดอร์งานไม่เปลี่ยน
  git worktree add --detach .claude/worktrees/<ชิ้น> "$base"
  ```
  ไฟล์ใหม่ที่ยังไม่ track (`git status --porcelain` ขึ้นต้น `??`) คัดลอกตามไปเอง · ไฟล์ที่ gitignore แต่ต้องใช้ (เช่น `.env`) ใส่ใน `.worktreeinclude`
- **รวมกลับ** → `git -C .claude/worktrees/<ชิ้น> add -A && git -C .claude/worktrees/<ชิ้น> diff --cached "$base" > _to_delete/patches/<ชิ้น>.patch` แล้วหัวหน้าทีม `git apply` ทีละชิ้นในโฟลเดอร์งาน รัน test หลังแต่ละชิ้น · ชนกัน → หยุดชิ้นนั้น ลง `ติด` · เสร็จแล้ว `git worktree remove` · ไม่ commit เอง
- worktree คือ checkout ใหม่ → ต้องติดตั้ง dependency ใหม่ (ใช้ cache ของ package manager ช่วย) · ห้อง Docker (`docker-sandbox -Isolated`) เก็บไว้ใช้กับงานที่ต้องแยกเครื่องจริง: ติดตั้งของทั้งระบบ · รันโค้ดที่ไม่ไว้ใจ · งานทั้งคืน

## สิ่งที่ห้ามทำ

| อย่าทำ | เพราะ |
|---|---|
| ปล่อย worker โดยไม่มีตารางแบ่งงาน | ทำซ้ำกันบางส่วน ตกหล่นบางส่วน ไม่มีใครรู้ |
| ส่งต่อรายงานของ worker ตรง ๆ | ตัวหลักต้องรับผิดชอบผลรวม ต้องอ่านและยืนยันเอง |
| ให้ worker หลายตัวแก้ไฟล์เดียวกัน | ผลชนกันและหายเงียบ |
