# หลักฐานเบื้องหลังกฎทดสอบ skill

ตัวเลขทุกตัวในไฟล์นี้เป็น **ตัวอย่างจากงานนั้น** ไม่ใช่เกณฑ์ · ส่วน A อ่านจากบันทึกและผลรันของคอร์ส CWN2026 (เปิดอ่านเอง 2026-11-04) · ส่วน B ได้จาก agent ค้นเว็บ 2026-11-04 ผ่านเครื่องมือที่ส่งหน้าเว็บให้โมเดลสรุปก่อน ตัวเลขจึงมาจากบทสรุป ยังไม่ได้เทียบหน้าเต็ม และตัวเลขต่างกันตามรุ่นของ paper

## A · จากงานจริงในคอร์ส

| เรื่อง | สิ่งที่เห็น (ตัวอย่างจากงานนั้น) | กฎที่ได้ | ข้อจำกัด |
|---|---|---|---|
| ชุดคำค้น trigger ต้องมาจากคนที่ไม่เคยเห็น description | จำลองการหา skill ด้วย BM25 (ค้นด้วยคำ ไม่ใช่ Claude เลือก skill) คลัง 23 ตัว · คำค้นชุด "เคยเห็น" 60 ข้อ hit@1 98.3% · ชุด "ใหม่" ที่ Claude อีกตัวเขียนโดยไม่เคยเห็น skill hit@1 80% hit@5 95% · ชุดแรก 58 จาก 60 ข้อมีคำใน description คำต่อคำ · ข้อที่หาไม่เจอใน 5 อันดับเป็นคำสั่งไทยปนอังกฤษ (อ่านจากบันทึกคอร์ส 2026-11-04) | คนหรือ agent ที่เขียนชุดทดสอบ trigger ต้องไม่เคยเห็น description · ใส่คำไทยและอังกฤษที่ผู้ใช้พิมพ์จริงทั้งสองภาษา | วัดรอบเดียว n=60 ด้วย BM25 ไม่ใช่การเลือก skill ของ Claude |
| รอบแดงต้องให้คะแนนกระบวนการและการตีความเงียบ ๆ ด้วย | รอบไม่มี skill ผ่าน 39 จาก 40 test แต่ agent สั่ง `ls petshop` (ผิดกติกา black-box) และตีความ "อาหารแมว" ว่านับขนมโดยไม่บอก · ตีความอีกแบบ คำตัดสินพลิกจาก "ปล่อยได้" เป็น "ยังไม่ปล่อย" (บันทึกคอร์ส 2026-11-04) | ผลลัพธ์ผ่านไม่พอให้สรุปว่า skill ไม่ใช่สาเหตุ · ให้คะแนนด้วยว่าทำผิดขั้นตอนไหม และมีจุดที่ตัดสินใจเองโดยไม่บอกไหม | รันครั้งเดียว n=1 |
| ร่าง skill ที่ AI เขียนต้องมีคนอ่านก่อนรวม | v1 ที่ AI เขียน เลือกตีความ "อาหารแมว" แบบที่ทำให้ test ผ่านแล้วเงียบ คนอ่านเจอใน LAB 3 จึงเพิ่มกติกาให้ลองอีกแบบและรายงานว่าคำตัดสินพลิกไหม (บันทึกคอร์ส 2026-11-04) | อ่านร่างโดยหาจุดที่ AI ตัดสินใจเองเพื่อให้ test ผ่าน | 1 skill |
| ลองทำงานจริง 1 รอบก่อนเขียน skill | คอร์สสอนให้ให้ AI ทำงานจริงก่อน แล้วค่อยเก็บเป็น skill เพราะ skill ควรมาจากวิธีที่ทำแล้วได้ผล (ที่มา: คลิปในบันทึกคอร์ส) | ทำงานจริง 1 ครั้งก่อนร่าง | เหตุผลอ้างจากคลิป ไม่ได้วัดเทียบ |
| รอบทดสอบรั่ว | agent เดินไปเปิดชุดกติกาบริษัท โฟลเดอร์ดีล และ skill ของแผนกอื่นใน plugin cache เอง (เกิด 2 ครั้ง) · ผลที่ใช้ได้มาจากรอบที่รันในโฟลเดอร์ว่างโดยซ่อน plugin อื่น (บันทึกคอร์ส 2026-11-04) | รันแดง/เขียวในโฟลเดอร์ว่าง ซ่อน plugin อื่น และอย่าให้โฟลเดอร์งานจริงอยู่ข้างเคียง | เจอในแล็บที่ 21 คนใช้เครื่องเดียวกัน |
| ผู้ตัดสินต้องปิดตา | ให้ผู้ตัดสินให้คะแนนแผน 2 ฉบับโดยไม่บอกว่าฉบับไหนมี skill (ติดป้าย A/B ไว้ในไฟล์เฉลยแยก) เกณฑ์ 12 ข้อเขียนก่อน ผล 1/12 (ไม่มี skill) กับ 12/12 (มี skill) (ผลรันคอร์ส 2026-11-04) | ผู้ตัดสินไม่รู้ว่าฉบับไหนมี skill · สลับป้าย A/B · เขียนเกณฑ์ไว้ก่อน | คู่เดียว ผู้ตัดสินเป็น Claude อีกตัว |
| เขียนใน settings ไม่เท่ากับติดตั้งแล้ว | แม่แบบเขียนชื่อ `core` ไว้ใน settings แต่ไม่ได้ติดตั้ง · เปิด Claude ใหม่แล้วนับ skill ที่เห็นจริง 13 จาก 21 โต๊ะไม่มี `core` (บันทึกคอร์ส 2026-11-04) | หลังติดตั้ง เปิดแชตใหม่แล้วนับ skill ที่ agent เห็นจริง | แล็บเดียว |
| กฎห้ามเด็ดขาดอย่าอยู่แค่ใน skill | กติกา black-box อยู่ใน skill · ถามเรื่องแผนโดยไม่เรียก skill agent เปิดแผนทั้งไฟล์รวมหัวข้อเฉลย (บันทึกคอร์ส 2026-11-04) | กฎ "ห้าม" ที่พลาดไม่ได้ ใส่ใน hook หรือ CLAUDE.md ด้วย (ข้อสรุปของเราเอง บันทึกคอร์สแนะให้บอกกติกาเองหรือเรียกผ่าน slash command) | 1 กรณี |
| บทเรียนที่จดไว้ต้องมีขอบเขตและวันหมดอายุ | คำตอบเดิมของเจ้าของแผนใช้ได้เมื่อชื่อแผน URL จำนวน test และถ้อยคำในแผนตรง · ถ้อยคำเปลี่ยน คำตอบหมดอายุ · การทดสอบ "หมดอายุ" รายงานโดย Claude เอง ผู้ตรวจไม่ได้รันซ้ำ (บันทึกคอร์ส 2026-11-04) | ผูกบทเรียนกับถ้อยคำต้นทาง | ยังไม่ได้ยืนยันซ้ำ |
| แก้เนื้อ plugin ต้องเพิ่มเลขเวอร์ชัน | `claude plugin update` ตอบว่าล่าสุดแล้ว เพราะ `plugin.json` ยังเป็น 1.0.0 ทั้งที่เนื้อใน `SKILL.md` เปลี่ยน ต้องถอนแล้วติดตั้งใหม่ (บันทึกคอร์ส 2026-11-04) | เพิ่ม `version` ใน `plugin.json` ทุกครั้งที่แก้เนื้อ | validator ของเรายังไม่ตรวจข้อนี้ (ค้น `scripts/check` 2026-11-04) ต้องทำมือ |
