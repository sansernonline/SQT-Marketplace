# prompt-thesis — วิทยานิพนธ์ · การค้นคว้าอิสระ (IS) · บทความวิจัย: โครงร่าง ทบทวนวรรณกรรม เขียนทีละบท ตรวจอ้างอิง สอบป้องกัน

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `personal-life` (หมวดเรียนรู้) · ไฟล์นี้รวม prompt 5 ฉบับ · 1 ฉบับ = 1 งาน · งานวิจัยและข้อค้นพบเป็นของผู้ใช้ agent ช่วยจัดโครง เกลาภาษา และตรวจอ้างอิง

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์วิทยานิพนธ์** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. วางคู่มือการทำวิทยานิพนธ์ของคณะ หรือคำแนะนำผู้เขียนของวารสาร ไว้ใน `inbox/` · กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `personal-life` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต (ห้ามข้าม):** ทำตาม skill `thesis-writing` ตาราง "What Claude does and does not do" · **ไม่เขียนผลการวิจัย ข้อค้นพบ หรือข้อสรุปที่ผู้ใช้ยังไม่ได้ทำ** · ไม่แต่งหรือปรับข้อมูล ขนาดตัวอย่าง หรือค่าสถิติ · อ้างอิงที่หาตัวจริงไม่เจอ (Digital Object Identifier (DOI) · ThaiJO · ThaiLIS · หน้าสำนักพิมพ์) ไม่ใส่ · ใช้ AI ตามนโยบายของมหาวิทยาลัยหรือวารสาร · ส่งงานให้อาจารย์ ส่งวารสาร หรือยื่นสอบ อยู่ใน "รออนุมัติ"

**ภาษาและไฟล์:** ตัวเล่มเขียนตามภาษาวิชาการใน `thesis-writing` (ไฟล์ `references/thai-academic-language.md`) · ข้อความที่ไม่ใช่ตัวเล่ม (รายงาน · คำอธิบาย) เขียนตาม `human-writing` · ร่างเป็น `.md` ใน `thesis/` · ส่งเป็น `.docx` → จัดหน้าตาม `references/thai-typesetting.md` ของ `thesis-writing`

## 1. โครงร่าง: คำถามวิจัย · วัตถุประสงค์ · โครงทุกบท

skill `thesis-writing` (ขั้น 1–2 และ 4 · `references/thesis-structure.md`) · agent `tech-mentor`
**ผลลัพธ์:** `thesis/proposal.md` · `thesis/outline.md`

### ข้อมูล (ผู้ใช้กรอก)

- ระดับ (ปริญญาโท วิทยานิพนธ์ · การค้นคว้าอิสระ (IS) · บทความวารสาร) / มหาวิทยาลัย คณะ หรือวารสาร:
- คู่มือของคณะ หรือคำแนะนำผู้เขียน (path ใน `inbox/`):
- หัวข้อที่สนใจ / ปัญหาที่เจอจริง:
- ข้อมูลหรือระบบที่เข้าถึงได้ (เช่น ระบบที่ทำงานอยู่ · ข้อมูลลูกค้าที่ได้รับอนุญาต):
- วันส่งโครงร่าง / วันสอบ:
- อาจารย์ที่ปรึกษาให้ความเห็นอะไรมาแล้ว:

### ต้องมีในผลงาน

1. คำถามวิจัย 1 ประโยค · วัตถุประสงค์ 2–4 ข้อ ขึ้นต้นด้วยคำที่วัดได้ (ศึกษา · เปรียบเทียบ · พัฒนา · ประเมิน) · สมมติฐานถ้ามี
2. ขอบเขต · นิยามศัพท์ · ประโยชน์ที่คาดว่าจะได้รับ
3. วิธีวิจัยฉบับย่อ: ประชากรและตัวอย่าง · เครื่องมือ · การเก็บข้อมูล · สถิติที่ใช้ และเหตุผลว่าตรงกับคำถาม
4. `outline.md`: หัวข้อทุกบทพร้อมข้ออ้าง 1 บรรทัดต่อหัวข้อ · ทุกหัวข้อโยงกลับไปวัตถุประสงค์ข้อไหน
5. ชื่อบท รูปแบบอ้างอิง และความยาว ตามคู่มือที่ให้มา · ไม่มีคู่มือ → ค่าตั้งต้นของ skill พร้อม `(รอยืนยัน)`

### กฎเฉพาะฉบับนี้

- คำถามวิจัยพูดไม่จบใน 1 ประโยค → ขอบเขตกว้างเกิน เสนอทางแคบลง 2–3 ทางให้ผู้ใช้เลือก
- งานที่เก็บข้อมูลจากคน → บอกว่าต้องขออนุมัติจริยธรรมการวิจัยในมนุษย์ไหม ตามกฎของมหาวิทยาลัย `(รอยืนยัน)`

## 2. ทบทวนวรรณกรรม

skill `thesis-writing` (ขั้น 3 และ 7 · `references/literature-matrix.md` · `references/citation-and-integrity.md`) · `english-tech-reading` · agent `tech-mentor`
**ต้องมีก่อน:** `thesis/proposal.md`
**ผลลัพธ์:** `thesis/lit-matrix.md` · `thesis/ch2-literature.md`

### ข้อมูล (ผู้ใช้กรอก)

- paper ที่มีอยู่แล้ว (path ใน `inbox/papers/`):
- ฐานข้อมูลที่เข้าได้ (ThaiJO · ThaiLIS · IEEE · ACM · Scopus · Google Scholar):
- ช่วงปีที่ต้องการ:

### ต้องมีในผลงาน

1. ตารางวรรณกรรม: ผู้แต่ง · ปี · วิธี · กลุ่มตัวอย่าง · ข้อค้นพบ · ช่องว่าง · DOI หรือลิงก์ · สถานะ `อ่านแล้ว` / `ยังไม่ได้ตรวจ`
2. บท 2 จัดตามประเด็น ไม่ใช่ 1 ย่อหน้าต่อ 1 paper · ทุกย่อหน้า: ข้อความหลัก → หลักฐานพร้อมอ้างอิง → ความหมายต่องานนี้
3. ช่องว่างงานวิจัยที่งานนี้เติม เขียนให้ชัดตอนท้ายบท
4. แหล่งที่ agent หาเพิ่ม มีลิงก์ทุกตัว และติด `(ยังไม่ได้ตรวจ)` จนผู้ใช้อ่านเอง

## 3. เขียนทีละบท

**ผลลัพธ์:** `thesis/ch<เลขบท>-<ชื่อ>.md` · `thesis/glossary.md`

### ข้อมูล (ผู้ใช้กรอก)

- บทที่จะทำ:
- ร่างหรือโน้ตของผู้ใช้ (path) · บท 3: ขั้นตอนที่ทำจริง · บท 4: ผลวิเคราะห์จริง (ไฟล์ output ของโปรแกรมสถิติ):
- ความเห็นอาจารย์รอบล่าสุด (ถ้ามี):

### ต้องมีในผลงาน

3. บท 5 อภิปรายทุกข้อค้นพบเทียบงานก่อนหน้าอย่างน้อย 1 งาน · ข้อจำกัด · ข้อเสนอแนะ

5. แก้ตามความเห็นอาจารย์ → ตาราง `| ความเห็น | แก้ที่ไหน | แก้อย่างไร |`

## 4. ตรวจอ้างอิงและตัวเลขก่อนส่งอาจารย์

playbook `review` · skill `thesis-writing` (ขั้น 7 และ 9 · `references/citation-and-integrity.md`) · agent `reviewer` ตัวใหม่
**ผลลัพธ์:** `thesis/check-<ปี-เดือน-วัน>.md` · **ไม่แก้ตัวเล่มเอง** · **รออนุมัติ:** ส่งให้อาจารย์

### ต้องมีในผลงาน

1. อ้างอิงทุกรายการ: หาตัวจริงเจอไหม (DOI หรือลิงก์) · ข้อความในเล่มตรงกับที่แหล่งพูดไหม · ในเนื้อหามีครบในรายการอ้างอิงและกลับกัน · รูปแบบตามคู่มือ
2. ตัวเลขในบท 4 · บท 5 · บทคัดย่อ ตรงกับตารางผลวิเคราะห์
3. ศัพท์ไม่ตรงกับ `glossary.md`
4. ส่วนที่ควรตรวจความคล้ายด้วยเครื่องมือของมหาวิทยาลัย (Turnitin · อักขราวิสุทธิ์) ก่อนส่ง · เกณฑ์ของมหาวิทยาลัย `(รอยืนยัน)`
5. ตารางปัญหา: ตำแหน่ง · ปัญหา · ระดับ (สูง / กลาง / ต่ำ) · วิธีแก้ (เดิม → ใหม่)

## 5. เตรียมสอบป้องกัน หรือตอบผู้ทบทวนบทความ

skill `thesis-writing` (ขั้น 10 · `references/defense-and-review.md`) · agent `tech-mentor`
**ต้องมีก่อน:** ตัวเล่มที่ผ่านฉบับ 4
**ผลลัพธ์:** `thesis/defense/slides-plan.md` · `thesis/defense/questions.md` (สอบ) · `thesis/response-to-reviewers.md` (วารสาร) · **รออนุมัติ:** ส่งคำตอบให้วารสาร

### ข้อมูล (ผู้ใช้กรอก)

- สอบ หรือ ตอบผู้ทบทวน / วันที่:
- เวลานำเสนอ (นาที) · กรรมการ (สาขา):
- ความเห็นผู้ทบทวน (path ใน `inbox/`):

### ต้องมีในผลงาน

1. แผนสไลด์: เรื่องละ 1 สไลด์ ตามลำดับ คำถาม → วิธี → ผล → ข้อสรุป · เวลาต่อสไลด์
2. คำถามที่กรรมการน่าจะถาม 15–20 ข้อ พร้อมแนวตอบจากตัวเล่ม (อ้างหน้า) · จุดอ่อนของงานที่ควรยอมรับตรง ๆ
3. ตอบผู้ทบทวน: ตาราง `| ความเห็น | ตอบ | แก้ที่ไหนในบทความ |` ทุกข้อ · ไม่เห็นด้วยข้อไหน ให้เหตุผลพร้อมหลักฐาน
