# prompt-certification — สอบใบรับรอง: เตรียมสอบ สอบใหม่หลังไม่ผ่าน

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `personal-life` (หมวดเรียนรู้) · ไฟล์นี้รวม prompt 2 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์เรียนรู้** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · ไม่รู้ปล่อยว่างได้
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `personal-life` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ข้อมูลเวอร์ชัน การเปลี่ยนแปลง และหลักสูตรสอบ อ่านจากแหล่งทางการ (release notes · changelog · exam guide) รอบนี้ ติดวันที่ตรวจ · โค้ดตัวอย่างต้องรันผ่านจริงก่อนส่ง · การสมัครสอบ ซื้อคอร์ส หรือจ่ายเงิน อยู่ใน "รออนุมัติ"

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `radar/reports/YYYY-Www.md` · `cert/<exam-code>-plan.md` · `notes/<short-title>.md`) ไม่กำหนด → ใช้ชื่อในตาราง

## 1. เตรียมสอบใบรับรอง

playbook `cert-prep` · agent `tech-mentor` · skill `cert-prep`
**ผลลัพธ์:** `cert/<exam-code>-plan.md` · **รออนุมัติ:** สมัครสอบ · ซื้อข้อสอบจำลอง

### ข้อมูล (ผู้ใช้กรอก)

- ใบรับรอง (เช่น AWS SAA-C03 · AZ-104 · CKA · PSM I):
- วันสอบ (หรือเดือนที่อยากสอบ):
- ประสบการณ์จริงกับเรื่องนี้:
- เวลาต่อสัปดาห์:
- คะแนนข้อสอบจำลองล่าสุด (ถ้ามี):

### ต้องมีในผลงาน

1. หัวข้อสอบและน้ำหนักจาก exam guide ฉบับปัจจุบัน (ลิงก์ + วันที่ตรวจ)
2. แผนที่ช่องว่าง: หัวข้อ · น้ำหนัก · ระดับที่ผู้ใช้รู้ · ลำดับเรียน
3. แผนรายสัปดาห์ถึงวันสอบ ใส่ lab ที่ลงมือจริงทุกสัปดาห์
4. เกณฑ์พร้อมสอบ (เช่น ข้อสอบจำลอง ≥ 80% ติดกัน 2 ชุด) และแผนถ้ายังไม่ถึง

## 2. สอบไม่ผ่าน เตรียมสอบใหม่

playbook `cert-prep` · agent `tech-mentor` · skill `cert-prep`
**ผลลัพธ์:** `cert/<exam-code>-retake-plan.md` · **รออนุมัติ:** จองรอบสอบใหม่ · จ่ายค่าสอบ · ซื้อข้อสอบจำลอง

### ข้อมูล (ผู้ใช้กรอก)

- ใบรับรอง:
- วันที่สอบครั้งก่อน:
- คะแนนและผลรายหมวดจากรายงานผลสอบ (score report · แปะหรือระบุไฟล์):
- หมวดที่รู้สึกว่าพลาด:
- แผนเดิม (path `cert/<exam-code>-plan.md` ถ้ามี):
- เวลาต่อสัปดาห์ / วันที่อยากสอบใหม่:

### ต้องมีในผลงาน

1. กฎการสอบซ้ำ (ต้องรอกี่วัน · ค่าสอบ · ส่วนลดสอบซ้ำถ้ามี) จากหน้าทางการของผู้จัดสอบรอบนี้ ติดวันที่ตรวจ · ไม่เจอ → `(รอยืนยัน)`
2. ตรวจว่า exam guide เปลี่ยนรุ่นหลังสอบครั้งก่อนไหม · เปลี่ยน → บอกหัวข้อที่เพิ่มหรือตัด
3. แผนที่ช่องว่างจาก score report: หมวด · ผลที่ได้ · น้ำหนักในข้อสอบ · ลำดับแก้ (หมวดที่อ่อนและน้ำหนักมากก่อน)
4. แผนรายสัปดาห์ถึงวันสอบใหม่ ให้เวลาส่วนใหญ่กับหมวดที่อ่อน และมี lab ที่ลงมือจริงทุกสัปดาห์ในหมวดนั้น
5. เกณฑ์พร้อมสอบใหม่ วัดด้วยข้อสอบจำลองชุดที่ยังไม่เคยทำ (ชุดเดิมจำคำตอบได้แล้ว ใช้วัดไม่ได้)

### กฎเฉพาะฉบับนี้

- ไม่มี score report → บอกตรง ๆ ว่าแผนอิงความรู้สึกของผู้ใช้ และให้ทำข้อสอบจำลอง 1 ชุดก่อนเพื่อหาช่องว่างจริง
