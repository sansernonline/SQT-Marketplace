# prompt-vehicle — รถยนต์และมอเตอร์ไซค์: ภาษี ประกัน อุบัติเหตุ ซื้อรถมือสอง

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `personal-life` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์บ้าน** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปบิล ใบเสนอราคา เอกสารรถ ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1 และ 4`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `personal-life` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** อัตราค่าไฟ ค่า Ft ภาษีรถ เบี้ย พ.ร.บ. (พระราชบัญญัติคุ้มครองผู้ประสบภัยจากรถ) และสิทธิผู้สูงอายุ ตรวจกับแหล่งทางการรอบนี้ ติดวันที่ · ไม่วินิจฉัยโรคของคนหรือสัตว์ · การจ่ายเงิน จ้างช่าง ต่อภาษี ตั้งหักบัญชีอัตโนมัติ อยู่ใน "รออนุมัติ"

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

|---|---|---|---|
| 1 | รถ: ภาษี พ.ร.บ. ตรวจสภาพ ประกัน เข้าศูนย์ | `vehicle` | `vehicles/<ทะเบียน>.md` |
| 2 | รถเกิดอุบัติเหตุ: เคลมและเอกสาร | `vehicle` (ขั้น 1) + ประกอบเพิ่ม | `vehicles/<ทะเบียน>-claim-<ปี-เดือน-วัน>.md` |

## 1. รถ: ภาษี พ.ร.บ. ตรวจสภาพ ประกัน เข้าศูนย์

playbook `vehicle` · agent `home-manager` · skill `vehicle-care`
**ผลลัพธ์:** `vehicles/<ทะเบียน>.md` (วันครบกำหนดทุกเรื่อง + ประวัติเข้าศูนย์) · **รออนุมัติ:** ต่อภาษี ซื้อประกัน จองศูนย์

### ข้อมูล (ผู้ใช้กรอก)

- รถ (รถยนต์ / มอเตอร์ไซค์) · ยี่ห้อ รุ่น ปี · ทะเบียน:
- วันหมดภาษี / พ.ร.บ. / ประกันภาคสมัครใจ / ใบขับขี่:
- เลขไมล์ปัจจุบัน / เข้าศูนย์ครั้งล่าสุด:
- ประกันที่เสนอมา (path) ถ้าจะเทียบ:

### ต้องมีในผลงาน

1. ตารางวันครบกำหนด เรียงจากใกล้สุด และวันที่ควรเริ่มทำ
2. ต้องตรวจสภาพก่อนต่อภาษีไหม (ตามอายุรถ) · ต่อออนไลน์ได้ไหม (ตรวจกับกรมการขนส่งทางบก)
3. ถ้าเทียบประกัน: ชั้น · ทุน · ค่าเสียหายส่วนแรก · ซ่อมห้าง/อู่ ในตารางเดียว
4. รายการเข้าศูนย์ครั้งถัดไปตามไมล์

## 2. รถเกิดอุบัติเหตุ: เคลมและเอกสาร

playbook `vehicle` (ขั้น 1 อ่านกรมธรรม์และเอกสารรถ + ขั้นสุดท้าย reviewer ตัวใหม่ตรวจ) ส่วนขั้นตอนเคลมประกอบเพิ่มตาม `playbook-template` (skill `superuser` หัวข้อ 2) · agent `home-manager` · skill `vehicle-care`
**ผลลัพธ์:** `vehicles/<ทะเบียน>-claim-<ปี-เดือน-วัน>.md` (สิ่งที่ต้องทำ · เอกสาร · ไทม์ไลน์เคลม) · **รออนุมัติ:** เซ็นเอกสารยอมความหรือตกลงค่าเสียหาย · ยื่นเคลม · รับเงินชดเชย · ส่งรถเข้าอู่

### ข้อมูล (ผู้ใช้กรอก)

- เกิดเมื่อไร ที่ไหน มีคนเจ็บไหม:
- รถเรา (ทะเบียน) / คู่กรณี (ทะเบียน · บริษัทประกัน ถ้ารู้):
- กรมธรรม์ พ.ร.บ. และประกันภาคสมัครใจ (path):
- รูปที่เกิดเหตุ ใบเคลม ใบแจ้งความ (path ถ้ามี):
- ตอนนี้อยู่ขั้นไหน (เพิ่งเกิด / รอเคลม / รถอยู่อู่ / มีปัญหากับบริษัทประกัน):

### ต้องมีในผลงาน

1. ถ้ามีคนเจ็บ → บอกให้โทร 1669 ก่อนทำอย่างอื่น
2. เช็กลิสต์ที่เกิดเหตุ: รูปรอบคัน มุมกว้างและมุมใกล้ · ทะเบียนคู่กรณี · เบอร์เคลมจากกรมธรรม์ · อย่าย้ายรถก่อนถ่ายรูป (ถ้าปลอดภัย)
3. พ.ร.บ. และประกันชั้นที่มีคุ้มครองอะไรในเหตุนี้ — คัดจากกรมธรรม์ตรงตัว · ค่าเสียหายส่วนแรก · ข้อเท็จจริงที่ไม่อยู่ในกรมธรรม์ตรวจกับแหล่งทางการรอบนี้ ติดวันที่
4. เอกสารที่ต้องใช้ และเมื่อไรต้องมีใบแจ้งความ (ตรวจรอบนี้ · ตรวจไม่ได้ → `ยังไม่ได้ตรวจ`)
5. ไทม์ไลน์เคลม: วันเกิดเหตุ · วันแจ้งเคลม · วันเข้าอู่ · วันรับรถ · ใครติดต่อ เบอร์อะไร

### กฎเฉพาะฉบับนี้

- เหตุฉุกเฉิน (เพิ่งเกิด · มีคนเจ็บ) → ตอบขั้นตอนเร่งด่วนทันทีก่อน แล้วค่อยถามช่องที่ขาด
- **ไม่ตัดสินว่าใครผิด** · ไม่ร่างข้อความยอมรับผิด
- ปัญหากับบริษัทประกัน (ไม่จ่าย จ่ายช้า) → จดไทม์ไลน์และหลักฐานให้ครบ แล้วบอกช่องทางร้องเรียนจากแหล่งทางการที่ตรวจรอบนี้

## 3. ซื้อรถมือสอง หรือโอนรถ

playbook `vehicle` (ขั้น 1 อ่านเล่มทะเบียน · ขั้น 2 ตรวจเงื่อนไขกับกรมการขนส่งทางบก · ขั้น 3 ลำดับขั้น พ.ร.บ. → ตรวจสภาพ → ภาษี + ขั้นสุดท้าย reviewer ตัวใหม่ตรวจ) · agent `home-manager` · skill `vehicle-care`
**ผลลัพธ์:** `vehicles/buy-<รุ่น>.md` (ตรวจเอกสาร · เช็กลิสต์ดูรถ · ขั้นตอนโอน · ค่าใช้จ่ายรวมปีแรก) · **รออนุมัติ:** จ่ายมัดจำ โอนเงิน เซ็นเอกสารโอน

### ข้อมูล (ผู้ใช้กรอก)

- ซื้อ / ขาย / โอนในครอบครัว:
- รถ (ยี่ห้อ รุ่น ปี เลขไมล์) · ราคาที่ตกลงหรือที่ประกาศ:
- รูปเล่มทะเบียนหน้าที่มีชื่อผู้ครอบครองและรายการจดทะเบียน (path):
- ผู้ขายเป็นเจ้าของเอง / เต็นท์รถ / ยังติดไฟแนนซ์:
- ประกาศขายหรือราคาตลาดที่เทียบไว้ (ลิงก์):

### ต้องมีในผลงาน

1. ตรวจเอกสาร: ชื่อผู้ครอบครองตรงกับผู้ขาย · ยังติดไฟแนนซ์ไหม · ภาษีค้าง · เลขตัวถังและเลขเครื่องในเล่มต้องตรงกับตัวรถ
2. เช็กลิสต์ดูรถและลองขับ · แนะนำให้ช่างหรือศูนย์ตรวจก่อนจ่ายมัดจำ
3. ขั้นตอนโอนที่กรมการขนส่งทางบก: เอกสารทั้ง 2 ฝ่าย · ค่าธรรมเนียม · ทำแทนได้ไหม — ตรวจรอบนี้ ติดวันที่
4. ค่าใช้จ่ายรวมปีแรก: ราคารถ · ค่าโอน · พ.ร.บ. · ภาษี · ประกัน · เข้าศูนย์ (ตัวเลขที่ไม่มีแหล่ง → `(รอยืนยัน)`)
5. ลำดับการจ่ายเงินที่ปลอดภัย: จ่ายเมื่อไร เท่าไร แลกกับเอกสารอะไร
6. ถ้าเป็นฝ่ายขาย: โอนทะเบียน · แจ้งย้ายหรือโอนกับกรมการขนส่งทางบก · ยกเลิกหรือโอน พ.ร.บ. และประกัน · เก็บหลักฐานรับเงิน — ขั้นตอนตรวจกับแหล่งทางการรอบนี้ ติดวันที่ตรวจ

### กฎเฉพาะฉบับนี้

- ราคาตลาดใช้เฉพาะแหล่งที่ผู้ใช้ให้หรือที่ค้นเจอพร้อมลิงก์และวันที่ · ห้ามประเมินราคาจากความจำ
- เอกสารไม่ตรงกัน (ชื่อ เลขตัวถัง) → เขียนชัดว่า "หยุดก่อนจ่ายเงิน" ไว้บรรทัดแรก
