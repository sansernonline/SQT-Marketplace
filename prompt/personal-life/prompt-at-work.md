# prompt-at-work — ระหว่างทำงาน: ประเมินตัวเอง ทดลองงาน คุยกับหัวหน้า

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `personal-life` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานอาชีพ** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · ไม่รู้ปล่อยว่างได้
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1` หรือ `ทำข้อ 1 และ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `personal-life` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ไม่แต่งประสบการณ์ ตำแหน่ง ตัวเลข หรือวุฒิ · ตัวเลขเงินเดือนตลาดต้องมีแหล่งและปี · การกดส่งใบสมัคร ส่งอีเมล หรือตอบรับข้อเสนอ อยู่ใน "รออนุมัติ" เสมอ · ข้อพิพาทแรงงาน → จัดข้อเท็จจริงให้ แล้วแนะนำศาลแรงงานหรือทนาย

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. ประเมินตัวเองและขอเลื่อนตำแหน่ง

playbook `promotion-case` · agent `career-coach` · skill `performance-self-review`
**ผลลัพธ์:** `review/<ปี>-<H1/H2>-self-review.md` · `brag.md` (จดผลงานต่อเนื่อง) · **รออนุมัติ:** ส่ง self-review เข้าระบบ · ส่งคำขอเลื่อนตำแหน่งหรือขึ้นเงินเดือนถึงหัวหน้า

### ข้อมูล (ผู้ใช้กรอก)

- รอบประเมิน และวันส่ง:
- แบบฟอร์มหรือหัวข้อที่บริษัทใช้ (path ไฟล์):
- เป้าที่ตั้งไว้ต้นรอบ (KPI / OKR):
- งานที่ทำในรอบนี้ (เล่าแบบไหนก็ได้ · โน้ต · อีเมล · ไฟล์):
- ต้องการขอ (เลื่อนตำแหน่ง / ขึ้นเงินเดือน / แค่ประเมิน):

### ต้องมีในผลงาน

1. ผลงาน 3–5 เรื่อง เขียนเป็นผลกระทบ (ก่อน → หลัง พร้อมตัวเลข) จับคู่กับเป้าหรือ KPI
2. เรื่องที่ยังไม่ถึงเป้า เขียนตามจริง พร้อมสิ่งที่เรียนรู้และแผนรอบหน้า
3. ถ้าขอเลื่อนตำแหน่ง: ตารางเกณฑ์ตำแหน่งถัดไป → หลักฐานที่มีแล้ว · ช่องที่ยังขาด
4. บทพูดคุยกับหัวหน้า 5 นาที + คำตอบถ้าถูกบอกว่า "ยังไม่ถึง"
5. `brag.md` ตั้งให้จดต่อได้ทุกสัปดาห์

## 2. เริ่มงานใหม่ ผ่านช่วงทดลองงาน

playbook `promotion-case` (ใช้ขั้น 1–2 และ 5: รวบรวมผลงาน · เขียนเป็นผล · ตรวจหลักฐาน · ขั้น 3–4 เรื่องตำแหน่งถัดไปไม่ใช้ จดเหตุผลตามหัวข้อ 2 ของ `superuser`) · agent `career-coach` · skill `performance-self-review`
**ผลลัพธ์:** `review/<ปี>-probation.md` · `brag.md` · **รออนุมัติ:** ส่งสรุปผลงานหรือนัดคุยกับหัวหน้า

### ข้อมูล (ผู้ใช้กรอก)

- วันเริ่มงาน / วันครบทดลองงาน (ตามสัญญาจ้าง):
- ตำแหน่ง และหน้าที่ตามประกาศงานหรือสัญญา:
- เป้าที่หัวหน้าบอกไว้ (ถ้ายังไม่มี เขียนว่ายังไม่มี):
- งานที่ทำไปแล้ว และเรื่องที่ยังไม่แน่ใจ:
- เกณฑ์ประเมินทดลองงานของบริษัท (path ไฟล์ ถ้ามี):

### ต้องมีในผลงาน

1. แผน 30 · 60 · 90 วัน: แต่ละช่วงมีงาน 2–3 ชิ้นที่วัดผลได้ และคนที่ต้องรู้จัก
2. คำถามที่ควรถามหัวหน้าในสัปดาห์แรก เพื่อให้รู้ว่า "ผ่านทดลองงาน" วัดจากอะไร
3. `brag.md` ตั้งให้จดทุกสัปดาห์ · หัวข้อ: วันที่ · ทำอะไร · ผล · หลักฐานอยู่ที่ไหน
4. ร่างสรุปผลงานก่อนวันครบทดลองงาน จับคู่กับเป้าหรือเกณฑ์ข้อ 2 · ตัวเลขที่ไม่มี → `[ใส่ตัวเลข]`
5. สัญญาณเตือนที่ควรคุยกับหัวหน้าก่อนถึงวันประเมิน (เป้าไม่ชัด · งานไม่ตรงตำแหน่ง · ยังไม่ได้รับคำติชมเลย)

### กฎเฉพาะฉบับนี้

- ระยะทดลองงานและสิทธิ์เมื่อไม่ผ่านทดลองงาน ไม่เขียนจากความจำ → อ่านจากสัญญาจ้างของผู้ใช้ และตรวจกับแหล่งทางการรอบนี้ ติดวันที่ตรวจ · ถูกแจ้งว่าไม่ผ่าน → `prompt-leaving-job.md` ฉบับ 2

## 3. คุยกับหัวหน้าเรื่องยาก

playbook `promotion-case` (ใช้ขั้น 1 รวบรวมหลักฐาน และขั้น 4 ร่างบทพูดกับหัวหน้า · ไม่มี playbook ที่ตรงทั้งตัว จึงปรับตามหัวข้อ 2 ของ `superuser`) · agent `career-coach` · skill `performance-self-review` · `human-writing`
**ผลลัพธ์:** `talks/<ปี-เดือน>-<เรื่อง>.md` · **รออนุมัติ:** ส่งข้อความหรืออีเมลถึงหัวหน้า · ส่งเรื่องถึงฝ่ายบุคคล (Human Resources: HR)

### ข้อมูล (ผู้ใช้กรอก)

- เรื่องที่จะคุย (งานล้นมือ · ถูกตำหนิ · ขอทำงานจากบ้าน · ขอย้ายทีม · ไม่ได้รับเครดิตผลงาน · ขัดแย้งกับเพื่อนร่วมงาน · อื่น ๆ):
- เกิดอะไรขึ้นบ้าง เรียงตามวันที่:
- หลักฐานที่มี (อีเมล · แชต · งานที่ได้รับมอบหมาย):
- อยากให้จบแบบไหน:
- คุยต่อหน้า / ออนไลน์ / เขียนเป็นข้อความ:

### ต้องมีในผลงาน

1. สรุปเรื่อง 3 บรรทัด: เกิดอะไร · กระทบงานอย่างไร · ขออะไร · แยก "มีหลักฐาน" ออกจาก "ความรู้สึก"
2. บทพูด 5 นาที: เปิดเรื่อง · ข้อเท็จจริง · สิ่งที่ขอ · ทางเลือกที่ยอมได้ 1–2 ทาง
3. คำตอบเมื่อหัวหน้าปฏิเสธ หรือโยนกลับ
4. ร่างอีเมลสรุปหลังคุย (ตกลงอะไร · ใครทำอะไร · ภายในวันไหน) เพื่อเก็บเป็นหลักฐาน
5. ถ้าคุยแล้วไม่ดีขึ้น: ขั้นต่อไปที่ทำได้ (ฝ่ายบุคคล · หัวหน้าลำดับถัดไป · ช่องทางร้องเรียนภายในบริษัท) ตามระเบียบบริษัทที่ผู้ใช้ให้มา

### กฎเฉพาะฉบับนี้

- ไม่เขียนถ้อยคำกล่าวหาหรือตีตราบุคคล · ทุกข้อชี้ไปที่เหตุการณ์และวันที่
- เรื่องที่เข้าข่ายล่วงละเมิด เลือกปฏิบัติ หรือข้อพิพาทแรงงาน → จัดไทม์ไลน์และหลักฐานให้ แล้วแนะนำศาลแรงงานหรือทนาย ไม่ตัดสินเอง
