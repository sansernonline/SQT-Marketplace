# prompt-weekly-routine — งานประจำสัปดาห์ อีเมล ประชุม

ใช้คู่กับ plugin `personal-life` · ไฟล์นี้รวม prompt 4 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ส่วนตัว** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วาง statement สแกนเอกสาร โน้ตประชุม ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `personal-life` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · อีเมลและปฏิทินอ่านผ่าน plugin หรือ connector ที่ติดตั้ง ไม่มี → ให้ผู้ใช้ export มาวางใน `inbox/` · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ไม่เก็บรหัสผ่าน เลขบัตร หรือเลขบัญชีเต็มลงไฟล์ (เก็บแค่ 4 ตัวท้าย) · การส่งอีเมล ยกเลิกสมาชิก จองตั๋ว เปลี่ยนรหัสผ่าน หรือตั้งค่าบัญชี อยู่ใน "รออนุมัติ" — ผู้ใช้กดเอง · กฎวีซ่าและพาสปอร์ตตรวจกับแหล่งทางการรอบนี้ ติดวันที่

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `weekly-reviews.md` · `subscriptions.md` · `important-docs.csv` · `decision-journal.md` · `goals/YYYY-Qn.md` · `gift-tracker.md` · `kb/index.md`) ไม่กำหนด → ใช้ชื่อในตาราง

| # | งาน | playbook | ได้ไฟล์ |
|---|---|---|---|
| 1 | รีเซ็ตปลายสัปดาห์ (ทบทวน + อินบ็อกซ์ + ปฏิทิน) | `weekly-reset` | `weekly-reviews.md` |
| 2 | ก่อน / หลังประชุม | `meeting` | `meetings/YYYY-MM-DD_<เรื่อง>_prep.md` · `_summary.md` |
| 3 | กลับจากลาพักร้อน อีเมลค้างเป็นร้อย | `weekly-reset` (ขั้น 1–3 และ 5) | `weekly-reviews.md` (หัวข้อ "กลับจากลา") |
| 4 | ตรวจงานก่อนส่งหรือก่อนใช้ | `review` | คำตัดสินในคำตอบ · ไม่สร้างไฟล์ |

ทำประจำ: ฉบับ 1 ทุกสัปดาห์ · ใช้ต่อกัน: กลับจากลา → 3 → 1 · หลังประชุมสำคัญ → 2 → 4 ก่อนส่งสรุป · ข้อความที่ต้องส่งจากไฟล์อื่น ตรวจด้วยฉบับ 4 ได้เหมือนกัน

## 1. รีเซ็ตปลายสัปดาห์

playbook `weekly-reset` · agent `life-admin` · skill `weekly-review` · `inbox-triage` · `calendar-audit`
**ผลลัพธ์:** ต่อท้าย `weekly-reviews.md` · ร่างอีเมลที่ต้องตอบวันนี้ · **รออนุมัติ:** ส่งอีเมล · ยกเลิกประชุมประจำ

### ข้อมูล (ผู้ใช้กรอก)

- อีเมลที่ใช้ (ส่วนตัว / งาน) และอ่านได้ทางไหน:
- ปฏิทินที่ใช้:
- งานที่ค้างใครอยู่ / ใครค้างเราอยู่:
- รอบนี้ทำ calendar audit 4 สัปดาห์ด้วยไหม (ใช่ / ไม่):

### ต้องมีในผลงาน

1. อีเมลคัด 5 กอง: ตอบวันนี้ · สัปดาห์นี้ · ส่งต่อ · ต้องตรวจก่อน · เก็บ
2. ทบทวน: เสร็จอะไร · หลุดอะไร · ค้างใคร · ครบกำหนดอะไรสัปดาห์หน้า
3. 3 เรื่องสำคัญของสัปดาห์หน้า (ไม่เกิน 3)
4. ร่างคำตอบอีเมลกอง "ตอบวันนี้"
5. ถ้าทำ calendar audit: ประชุมประจำที่ไม่ได้อะไร · ช่วงเวลาทำงานลึกที่เสนอ

## 2. ก่อน / หลังประชุม

playbook `meeting` · agent `meeting-prep` · skill `meeting-prep-card` · `meeting-summary`
**ผลลัพธ์:** `meetings/YYYY-MM-DD_<เรื่อง>_prep.md` (ก่อน) · `meetings/YYYY-MM-DD_<เรื่อง>_summary.md` (หลัง) · **รออนุมัติ:** ส่งสรุปให้ผู้เข้าประชุม

### ข้อมูล (ผู้ใช้กรอก)

- ก่อน หรือ หลังประชุม:
- ประชุมเรื่องอะไร / กับใคร / เวลา:
- (ก่อน) อยากได้อะไรจากประชุมนี้:
- (หลัง) โน้ต / transcript / ไฟล์เสียงที่ถอดแล้ว (path):
- ต้องการรายงานการประชุมแบบทางการไทยไหม:

### ต้องมีในผลงาน

1. ก่อน: การ์ด 1 หน้า — เป้า · 3 คำถาม · บริบท · สิ่งที่จะขอ · จุดที่ยอมถอย
2. หลัง: ข้อตัดสินใจ · งานที่ต้องทำ (ใคร · อะไร · ภายในวันไหน) · คำถามค้าง
3. ข้อความส่งสรุปพร้อมส่ง (หรือรายงานการประชุมแบบทางการ ถ้าขอ)
4. งานที่ไม่มีเจ้าของหรือไม่มีวันที่ → ทำเครื่องหมายให้เห็น ไม่เดาเอง

## 3. กลับจากลาพักร้อน อีเมลค้างเป็นร้อย

playbook `weekly-reset` (ขั้น 1–3 และ 5: อ่าน · คัด 5 กอง · ทบทวน · 3 เรื่องสำคัญ) · agent `life-admin` · skill `inbox-triage` · `weekly-review` · `polite-message-th-en`
**ผลลัพธ์:** หัวข้อ "กลับจากลา YYYY-MM-DD" ต่อท้าย `weekly-reviews.md` · ร่างอีเมลที่ต้องตอบวันนี้ · **รออนุมัติ:** ส่งอีเมล · เก็บถาวรหรือลบอีเมลทีละมาก

### ข้อมูล (ผู้ใช้กรอก)

- ลาตั้งแต่วันไหนถึงวันไหน:
- อีเมลที่ต้องเคลียร์ (ส่วนตัว / งาน) และอ่านได้ทางไหน:
- ใครดูงานแทนระหว่างลา / เขาสรุปอะไรไว้ให้ไหม:
- เรื่องที่รู้ว่าครบกำหนดช่วงนี้:

### ต้องมีในผลงาน

1. อีเมลคัด 5 กองเหมือนฉบับ 1 · อีเมลที่ถูกตอบหรือจบไปแล้วระหว่างลา (มีคนตอบแทน · เรื่องปิดแล้ว) แยกเป็นกอง "จบแล้ว ไม่ต้องทำ"
2. เรื่องที่เลยกำหนดไประหว่างลา เรียงตามความเสียหายถ้าช้าต่อ
3. ร่างตอบกอง "ตอบวันนี้" · เรื่องที่ตอบช้าไปแล้ว → ประโยคเปิดที่ขอโทษสั้น ๆ ไม่อธิบายยาว
4. ร่างข้อความถึงคนที่ดูงานแทน: ขอบคุณ + ถามเรื่องที่ยังค้าง
5. 3 เรื่องสำคัญของสัปดาห์แรกที่กลับมา

### กฎเฉพาะฉบับนี้

- อีเมลขอเงินหรือขอข้อมูลบัญชีลงกอง "ต้องตรวจก่อน" เสมอ ช่วงหลังลามีอีเมลหลอกมากกว่าปกติ
- ไม่เก็บถาวรหรือลบเอง เตรียมรายการไว้ใน "รออนุมัติ" · ข้อยกเว้นมีแค่เก็บถาวรที่ผู้ใช้อนุญาตไว้ล่วงหน้าใน `.claude/superuser/CONTEXT.md` · ลบอยู่ใน "รออนุมัติ" เสมอ

## 4. ตรวจงานก่อนส่งหรือก่อนใช้

playbook `review` · agent `life-admin` + agent ตัวใหม่ (มุมคนที่จะได้รับหรือใช้ชิ้นงาน)
**ผลลัพธ์:** คำตัดสิน `ส่งได้ / ส่งได้หลังแก้ / ยังไม่ควรส่ง` · **ไม่แก้ไฟล์เอง**

### ข้อมูล (ผู้ใช้กรอก)

- ไฟล์หรือข้อความที่จะให้ตรวจ (สรุปประชุม · ร่างอีเมล · ข้อความลำบากใจ · itinerary · ทะเบียนเอกสาร · ตารางรายจ่าย):
- จะส่งถึงใคร / ใช้ทำอะไร:
- ต้นทางที่ต้องเทียบ (โน้ตประชุม · อีเมลยืนยันการจอง · statement):

### ต้องมีในผลงาน

1. คำตัดสิน 1 บรรทัด
2. ตารางปัญหา: ตำแหน่ง · ปัญหา (ข้อมูลไม่ตรงต้นทาง · งานไม่มีเจ้าของหรือวันที่ · ระดับภาษาไม่เหมาะกับผู้รับ · มีเลขบัตร เลขบัญชีเต็ม หรือรหัสผ่านหลุดอยู่ · กฎวีซ่าไม่ได้ติดวันที่ตรวจ) · ระดับ (ต้องแก้ · ควรแก้ · ข้อสังเกต) · วิธีแก้
3. ข้อที่ตรวจแล้วผ่าน
