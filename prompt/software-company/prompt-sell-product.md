# prompt-sell-product — ขายซอฟต์แวร์ของเราเอง: ราคา · license · เงื่อนไขการใช้ · หน้าร้าน · เปิดขาย

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `software-company` · ไฟล์นี้มี prompt 5 ฉบับ · ใช้เมื่อจะขายผลิตภัณฑ์ของเราเอง (แอป · plugin · API · EA) ไม่ใช่งานรับจ้างทำให้ลูกค้า · Expert Advisor (EA) คือโปรแกรมเทรดอัตโนมัติบน MetaTrader · รับจ้างทำ → `prompt-proposal.md` · ตั้งชื่อและ roadmap → `prompt-product.md` · ให้คนค้นเจอและสมัคร → `prompt-growth.md`

## วิธีใช้

วางทั้งไฟล์ใน Claude Code, Codex CLI หรือ Gemini CLI ที่รากโฟลเดอร์โปรเจกต์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำทั้งหมด` หรือ `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุ (ไม่ระบุ → `project-docs`) · กฎร่วม (ถามแบบเลือกคำตอบครั้งเดียว ทุกตัวเลือกมีหลักฐาน · ทำจบรอบเดียว · ตัดสินใจเอง · รายงานสถานะ) อยู่ใน skill `superuser` และ playbook ที่เดียว · ข้อที่ต้องตัดสิน: ใช้ค่าตั้งต้นของเจ้าของใน `~/.claude/superuser-style.md` ก่อน ไม่มี → ค้นแล้วโหวต 3 agent ตาม skill `superuser` หัวข้อ 6 · ถามผู้ใช้เฉพาะข้อที่โหวตแทนไม่ได้ และตัวแนะนำบอกผลโหวต · ตัดสินใจเอง (พร้อมผลโหวต) และสถานะลง `docs/BUILD-PLAN.md` (ยังไม่มี → สร้าง) · ไฟล์ทำงานของ SuperUser (`CONTEXT.md` · `IMPROVEMENTS.md` · log) อยู่ใต้ `.claude/superuser/` ตาม `project-doc-set` ข้อ 1 ไม่วางที่รากโปรเจกต์ · ใช้ skill และ agent ของ plugin `software-company` เท่านั้น (ไม่ใช้ตัวชื่อซ้ำของ plugin อื่น) · เปิด skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ของ plugin · ไม่มี agent → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด · ไม่มี `reviewer` หรือ `brainstormer` (plugin เวอร์ชันเก่า) → `general-purpose` ตัวใหม่ทำหน้าที่เดียวกัน (ตรวจอย่างเดียว ไม่แก้ · เสนอ 2–3 ทาง) · ไม่มี `learning-reviewer` → ข้ามรอบเรียนรู้แล้วจดไว้

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

## กฎเฉพาะไฟล์นี้

- ทุกตัวเลขราคาและค่าธรรมเนียมแสดงวิธีคิด ให้คิดซ้ำได้ · ค่าธรรมเนียมของ store หรือ payment gateway หักออกก่อนคิดกำไร
- ระบบ license ต้องไม่ทำให้ลูกค้าที่จ่ายแล้วใช้ไม่ได้ (เน็ตหลุด · เซิร์ฟเวอร์ license ล่ม) · ทุกแบบมีช่วงผ่อนผัน
- agent ที่ใช้: `product-manager` · `revops-analyst` · `fintech-engineer` · `security-engineer` · `legal-compliance-officer` · `growth-specialist` · `reviewer` ตรวจทุกฉบับ

## 1. ตั้งราคาและแพ็กเกจ

playbook `project-docs` · agent `revops-analyst` + `product-manager` · skill `saas-platform` · `simplicity-first`
**ผลลัพธ์:** `docs/sell/pricing.md`

### โจทย์ (ผู้ใช้กรอก)

- ผลิตภัณฑ์คืออะไร ขายใคร (คนทั่วไป · บริษัท · นักพัฒนา):
- ลูกค้าอยู่ไทย · ต่างประเทศ · ทั้ง 2:
- คู่แข่งหรือของที่ลูกค้าใช้แทนอยู่ตอนนี้:
- ต้นทุนต่อผู้ใช้ต่อเดือน (เซิร์ฟเวอร์ · AI · ค่าส่ง SMS) ถ้ารู้:
- แบบที่อยากขาย (ซื้อขาด · รายเดือน · ตามการใช้ · ฟรีบางส่วน · ยังไม่รู้):

### หัวข้อที่ต้องมี

1. **ราคาคู่แข่ง** — ตาราง `| คู่แข่ง | แพ็กเกจ | ราคา | ได้อะไร | แหล่ง + วันที่ตรวจ |` อย่างน้อย 3 ราย
2. **แบบขาย** — เทียบ 2–3 แบบ พร้อมข้อดีข้อเสียกับผลิตภัณฑ์นี้ · แบบที่แนะนำ
3. **แพ็กเกจ** — ไม่เกิน 3 ระดับ · แต่ละระดับต่างกันที่สิ่งที่ลูกค้ารู้สึก (จำนวนผู้ใช้ · ปริมาณใช้ · ฟีเจอร์) · ราคาไทยและราคาต่างประเทศ
4. **กำไรต่อลูกค้า** — ราคา − ค่าธรรมเนียม store/gateway − ต้นทุนต่อผู้ใช้ = กำไรต่อเดือน ต่อแพ็กเกจ
5. **รุ่นทดลอง** — มีไหม · กี่วัน · จำกัดอะไร · ต้องใส่บัตรไหม พร้อมเหตุผล

## 2. ระบบ license · สมาชิก · รับเงิน

playbook `project-docs` (ติ๊กแก้โค้ด → ส่วนโค้ดใช้ `feature`) · agent `fintech-engineer` + `security-engineer` + `developer` · skill `fintech-payments` · `saas-platform` · `auth-implementation-patterns` · `principle-secure-by-default` · `config-and-secrets`
**ต้องมีก่อน:** `docs/sell/pricing.md`
**ผลลัพธ์:** `docs/sell/licensing.md` · **ไม่แก้โค้ด** เว้นแต่ข้างล่างติ๊ก `[x]` · **รออนุมัติ:** เปิดบัญชี payment gateway · ใช้ key จริง

- [ ] อนุญาตให้สร้างและแก้โค้ด (ใช้ key ทดสอบของ gateway เท่านั้น · commit บนเครื่อง · ไม่ push)

### หัวข้อที่ต้องมี

1. **ชนิดผลิตภัณฑ์ → วิธีล็อก** — แอปบนเครื่อง (license key + เปิดใช้ต่อเครื่อง) · เว็บหรือ API (บัญชีสมาชิก + สิทธิ์ตามแพ็กเกจ) · plugin หรือ EA (ตาม store หรือ `stack-mql` ข้อ 7)
2. **วงจร license** — ซื้อ → ออก key → เปิดใช้ → ต่ออายุ → หมดอายุ → ย้ายเครื่อง → คืนเงินแล้วยกเลิก · ผังสถานะ 1 รูป
3. **ช่วงผ่อนผัน** — ออฟไลน์ได้กี่วัน · เซิร์ฟเวอร์ license ล่มแล้วลูกค้ายังใช้ได้
4. **รับเงิน** — gateway ที่เลือก (Stripe · Omise · PromptPay · store) พร้อมค่าธรรมเนียม · webhook ยืนยันการจ่ายทุกครั้ง ไม่เชื่อหน้า return · จ่ายซ้ำไม่ออก license ซ้ำ · คืนเงิน
5. **ความปลอดภัย** — key ลงนามด้วย private key ที่อยู่บนเซิร์ฟเวอร์เท่านั้น · ไม่เก็บเลขบัตร · ป้องกันแชร์ key (จำกัดจำนวนเครื่อง)

## 3. เงื่อนไขการใช้ · ความเป็นส่วนตัว · คืนเงิน

playbook `project-docs` · agent `legal-compliance-officer` + `product-manager` · skill `pdpa-compliance` · `human-writing`
**ต้องมีก่อน:** `pricing.md` · `licensing.md`
**ผลลัพธ์:** `docs/sell/legal/terms.md` · `privacy.md` · `refund.md` (ภาษาไทยและอังกฤษถ้าขายต่างประเทศ) — ทุกไฟล์ติด `(ให้ผู้รู้กฎหมายตรวจ)` บนสุด

### ข้อมูล (ผู้ใช้กรอก)

- ผู้ขายคือใคร (ชื่อบริษัท · ที่อยู่ · ช่องทางติดต่อ):
- ลูกค้าอยู่ประเทศไหนบ้าง:
- เก็บข้อมูลอะไรของลูกค้า · ส่งให้ใคร (ผู้ให้บริการ AI · gateway · analytics):

### หัวข้อที่ต้องมี

1. **เงื่อนไขการใช้ (Terms / End User License Agreement — EULA)** — สิทธิ์ที่ได้ (ใช้ · ไม่ใช่เป็นเจ้าของ) · จำนวนเครื่อง · สิ่งที่ห้าม · การรับประกันและขีดจำกัดความรับผิด · ยกเลิก · กฎหมายที่ใช้บังคับ
2. **ความเป็นส่วนตัว** — ตาม `pdpa-compliance`: เก็บอะไร · ทำไม · เก็บนานเท่าไร · ส่งให้ใคร · สิทธิ์ของเจ้าของข้อมูล · ช่องทางติดต่อ
3. **คืนเงิน** — กี่วัน · เงื่อนไข · ขั้นตอน · ต้องตรงกับที่ store บังคับ (store บังคับมากกว่า → ใช้ของ store)
4. **ตารางตรวจความตรงกัน** — สิ่งที่เอกสารสัญญา เทียบกับสิ่งที่ระบบทำจริง (`licensing.md` · โค้ด) ทุกข้อ

### กฎเฉพาะฉบับนี้

- ผลิตภัณฑ์การเงิน (EA · สัญญาณเทรด) → เพิ่มคำเตือนความเสี่ยง และห้ามสัญญาผลตอบแทน · ข้อมูลสุขภาพ → เพิ่ม "ไม่ใช่การวินิจฉัย"
