# prompt-dynamic-website — เว็บเล่าเรื่องทีละบท: ทิศทางภาพ · บทเต็มจอ · หน้าเลื่อนและลงทะเบียน · ตรวจคุณภาพ · ขึ้นจริง

ใช้คู่กับ plugin `software-company` · ไฟล์นี้มี prompt 5 ฉบับ · ใช้เมื่อเว็บการตลาด หน้างานสัมมนา หน้าเปิดตัวสินค้า หรือหน้า "เกี่ยวกับเรา" ต้องเล่าเรื่องทีละบทด้วยการเคลื่อนไหว (GSAP · เลื่อน · พื้นหลัง 3D) · แดชบอร์ดหรือหน้าแอดมินที่คนเข้ามาทำงาน → `prompt-mockup.md` · สไลด์ที่คนพูดกดเปลี่ยนหน้าเอง → `prompt-product.md` ฉบับ 4 หรือ skill `html-slide-deck` · ยังไม่รู้ว่าแต่ละบทจะพูดอะไร → ฉบับ 1 ร่างโครงเรื่องให้ก่อน

## วิธีใช้

วางทั้งไฟล์ใน Claude Code, Codex CLI หรือ Gemini CLI ที่รากโฟลเดอร์โปรเจกต์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำทั้งหมด` หรือ `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุ (ไม่ระบุ → `project-docs`) · กฎร่วม (ถามแบบเลือกคำตอบครั้งเดียว ทุกตัวเลือกมีหลักฐาน · ทำจบรอบเดียว · ตัดสินใจเอง · รายงานสถานะ) อยู่ใน skill `superuser` และ playbook ที่เดียว · ข้อที่ต้องตัดสิน: ใช้ค่าตั้งต้นของเจ้าของใน `~/.claude/superuser-style.md` ก่อน ไม่มี → ค้นแล้วโหวต 3 agent ตาม skill `superuser` หัวข้อ 6 · ถามผู้ใช้เฉพาะข้อที่โหวตแทนไม่ได้ และตัวแนะนำบอกผลโหวต · ตัดสินใจเอง (พร้อมผลโหวต) และสถานะลง `docs/BUILD-PLAN.md` (ยังไม่มี → สร้าง) · ไฟล์ทำงานของ SuperUser (`CONTEXT.md` · `IMPROVEMENTS.md` · log) อยู่ใต้ `.claude/superuser/` ตาม `project-doc-set` ข้อ 1 ไม่วางที่รากโปรเจกต์ · ใช้ skill และ agent ของ plugin `software-company` เท่านั้น (ไม่ใช้ตัวชื่อซ้ำของ plugin อื่น) · เปิด skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ของ plugin · ไม่มี agent → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด · ไม่มี `reviewer` หรือ `brainstormer` (plugin เวอร์ชันเก่า) → `general-purpose` ตัวใหม่ทำหน้าที่เดียวกัน (ตรวจอย่างเดียว ไม่แก้ · เสนอ 2–3 ทาง) · ไม่มี `learning-reviewer` → ข้ามรอบเรียนรู้แล้วจดไว้

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ภาษาและรูป:** ทุกเอกสารเขียนตาม skill `human-writing` · รูปในเอกสารส่งมอบใช้ `diagram-figures` · Mermaid (`software-diagrams`) ใช้ได้เฉพาะเอกสารภายในทีม

**เว็บแบบบท (ใช้ทุกฉบับ):** ทำตาม skill `dynamic-website` · การเคลื่อนไหวทุกชิ้นผ่านประตูเดียว (`T()` ใน JS + kill-switch ใน CSS) · แต่ละบทมีทางเข้าของตัวเอง ห้ามใช้ fade-up ซ้ำทุกจุด · รุ่นของ GSAP และเครื่องมืออ่านจากหน้าทางการรอบนี้ แล้วติดวันที่ตรวจ · ข้อความบนเว็บตาม `human-writing` · หน้าตาต้องไม่ดูเหมือน AI ทำ ตาม `no-ai-look` (plugin `superuser`) · โค้ดเว็บอยู่ในโฟลเดอร์โค้ด (`<repo>/`) · ภาพทดลองและผลวัดลง `_to_delete/`

## กฎเฉพาะไฟล์นี้

- เว็บเดียวมีได้ทั้ง 2 โหมด: บทเล่าเรื่องใช้ deck-mode ส่วนลงทะเบียน ชำระเงิน และแอดมินใช้ page-mode · token สีและตัวอักษรชุดเดียวกันทั้ง 2 โหมด
- **ผู้ใช้เลือกแนวภาพเอง** เป็นค่าเริ่ม · สั่งหลายฉบับรวดเดียว → ทำฉบับ 1 จนได้หน้าเทียบ แล้วรอคำตอบเรื่องแนว เป็นจุดหยุดเดียวของไฟล์นี้ · ฉบับ 2–5 ทำต่อหลังผู้ใช้เลือก
- เนื้อหาและรูปต้องเหมือนของจริง ห้าม Lorem ห้ามกล่องเทาว่าง ห้ามรูปทรงพื้นฐานวางแทนรูป
- agent ที่ใช้: `ux-designer` (ฉบับ 1) · `graphic-designer` (โลโก้ สีแบรนด์ และ `no-ai-look`) · `developer` (ฉบับ 2–3) · `qa-tester` (ฉบับ 4) · `devops-engineer` + `seo-specialist` (ฉบับ 5) · `reviewer` ตรวจทุกฉบับ

## 1. ทิศทางภาพ 3 แนว ให้ผู้ใช้เลือก

playbook `project-docs` · agent `ux-designer` (นำ) + `graphic-designer` · skill `ui-craft` ข้อ 0.1 · `parallel-attempts-pick-best` · `dynamic-website` (ข้อ 4 token · ข้อ 6 ฟอนต์ไทยหัวใหญ่) · `presentation-design` (โครงเรื่อง)
**ผลลัพธ์:** `docs/design/<รหัส>-story.md` (บท · หัวบทเป็นข้อสรุป · ทางเข้าที่ตั้งใจ) · `docs/design/<รหัส>-design-directions.html` (3 แนวเคียงกัน) · **ผู้ใช้เลือกแนว** ก่อนเริ่มฉบับ 2

6. แนวที่เลือก: สีแบรนด์และฟอนต์เขียนกลับลง `docs/README.md` · โลโก้ลง `assets/logo/`

## 2. สร้างบทเล่าเรื่องแบบเต็มจอ (deck-mode)

playbook `feature` (ยังไม่มีโค้ด → `new-project`) · agent `developer` (นำ) + `ux-designer` · skill `dynamic-website` (ข้อ 1–5 · `references/recipes.md` · ตัวอย่าง `assets/example-deck.html`) · `web-app-design` (ชื่อ token) · `lazy-coding` · `readable-code`
**ต้องมีก่อน:** แนวที่ผู้ใช้เลือกจากฉบับ 1 · `docs/design/<รหัส>-story.md`
**ผลลัพธ์:** หน้าเว็บใน `<repo>/` · GSAP self-host ใน `vendor/` · ฟอนต์ woff2 self-host · ภาพทุกบทที่กว้าง 1440 · 900 · 420 ใน `_to_delete/shots/` · **ไม่เขียนโค้ด** เว้นแต่ข้างล่างติ๊ก `[x]`

- [ ] อนุญาตให้สร้างและแก้โค้ด (commit บนเครื่องเท่านั้น บน branch `site/<เว็บ>` · ไม่ push · ไม่ merge เข้า branch หลัก)

### สิ่งที่ต้องได้

1. โครงตาม `dynamic-website` ข้อ 1: `route()` ตัวเดียวบน `hashchange` · ทุก view ดันฟังก์ชันถอดลง `cleanups[]` และล้างก่อนเปลี่ยน view · เปลี่ยนบทด้วย `replaceState` · เนื้อหาอยู่ใน HTML ไม่อยู่ใน JS
2. ประตูเดียวของการเคลื่อนไหว · ทางเข้า 4 แบบต่อเว็บ บทติดกันไม่ใช้แบบซ้ำ (`data-enter`) · ออกสั้นกว่าเข้าและเร่งออก · ล้าง filter หลังเข้าเสร็จให้ตัวหนังสือคม
3. คีย์บอร์ดครบ (↓ PgDn Space · ↑ PgUp · Home End) · ย้ายโฟกัสไปบทใหม่ทุกครั้ง · rail มี `aria-current="step"` · รายการในบทเลื่อนจนสุดก่อนแล้วค่อยเปลี่ยนบท
4. พื้นหลังหนักโหลดทีหลังและรอไม่เกิน 4 วินาที · เปิด WebGL ไม่ได้ → fallback 2D ที่สื่อความหมายเดียวกัน · `devicePixelRatio` ไม่เกิน 2 · loop วิ่งเฉพาะตอนที่จอต้องใช้
5. `wheel` และ `touch` แบบ `passive:false` มีเฉพาะ deck-mode และถอดเมื่อเปลี่ยน route · ฟอนต์ไทยกับละตินแยกด้วย `unicode-range` · preload แค่ 2 น้ำหนัก
6. สีทุกตัวมาจาก token ชื่อตาม `web-app-design` · รัน `check-design-tokens.mjs` ของ `web-app-design` แล้วไม่เจอสี hardcode

### กฎเฉพาะฉบับนี้

- GSAP โหลดจาก cdnjs ได้เฉพาะตอนลอง · ไฟล์ส่งมอบต้องเปิดได้โดยไม่พึ่ง CDN · ต้องใช้ API ของ GSAP ลึกกว่าที่ `dynamic-website` บอก → อ่าน skill ทางการของผู้ผลิตเฉพาะไฟล์ของ plugin ที่ใช้ ตาม `dynamic-website` ข้อ 5
- `decodeWords` ใช้กับหัวเรื่องละตินเท่านั้น ไม่ใช้กับไทย · หัวใหญ่ไทยที่ตั้ง `letter-spacing` ติดลบต้องเปิดดูจริงทุกน้ำหนัก

3. ข้อมูลลงทะเบียนตรวจฝั่งเซิร์ฟเวอร์ทุกช่อง · ขอเฉพาะข้อมูลที่ใช้จริง · ข้อความขอความยินยอมและลิงก์นโยบายความเป็นส่วนตัวตาม `pdpa-compliance` · log ไม่มีข้อมูลส่วนบุคคล
4. กดส่ง 2 ครั้งหรือเน็ตหลุดกลางทางแล้วไม่ได้ผู้ลงทะเบียนซ้ำ
5. ปุ่ม Back ทำงานตามที่คนคาด: เปลี่ยนหน้าใช้ hash ปกติ ส่วนเปลี่ยนบทใช้ `replaceState`

## 4. ตรวจคุณภาพก่อนเปิด

playbook `review` · agent `qa-tester` ตัวใหม่ (การเข้าถึง · ความเร็ว · คีย์บอร์ด) + `graphic-designer` ตัวใหม่ (`no-ai-look`) · ผู้ตรวจต้องไม่ใช่ตัวที่สร้างหรือแก้เว็บ · skill `web-quality-audit` · `no-ai-look` (plugin `superuser`) · `dynamic-website` ข้อ 7 · `seo-audit-checklist` (ใช้ผล Lighthouse รอบเดียวกัน)

**ผลลัพธ์:** `docs/web-quality-<ปี-เดือน-วัน>.md` · ผลดิบใน `_to_delete/audit/<วันที่>/` · **ผู้ตรวจไม่แก้ไฟล์**

### สิ่งที่ตรวจ

1. **การเข้าถึงและความเร็ว:** ทำตาม `prompt-quality.md` ฉบับ 4 ที่เดียว · หาไฟล์ไม่เจอ → ทำตาม `web-quality-audit` ขั้นตอน 1–4 (WCAG 2.2 AA · Lighthouse mobile บน production build · ค่ากลาง 3 รอบ)
2. **ไม่ให้ดูเหมือน AI ทำ:** รัน `slop_scan.py` ของ `no-ai-look` กับไฟล์ HTML · ไล่ `data-enter` ทุกบทว่าไม่มี fade-up ซ้ำและบทติดกันไม่ซ้ำแบบ · ไม่มีอนุภาคลอยไร้ความหมาย glow ที่วนไม่หยุด หรือ gradient บนปุ่ม
3. **คีย์บอร์ด:** เปลี่ยนบทได้ครบทุกปุ่มในแผนที่ · Tab ไล่ rail แล้วเห็นวงโฟกัส · โฟกัสย้ายตามบท · ฟอร์มลงทะเบียนกรอกจนส่งได้ด้วยคีย์บอร์ดอย่างเดียว · Esc ปิด modal
4. **reduced motion:** เปิด `prefers-reduced-motion` แล้วเห็นเนื้อหาครบทุกบท ตัวเลขเป็นค่าสุดท้าย ไม่มีคำจาง · ของที่เล่นเองเกิน 5 วินาทีมีปุ่มหยุด
5. **ตัดของหนัก:** ปิด WebGL แล้ว fallback 2D ขึ้นและอ่านได้ · ถอดเน็ตแล้วฟอนต์ยังเป็นตัวที่ตั้งใจ · trackpad ปัดแรง 1 ครั้งเปลี่ยน 1 บท · Lighthouse ไม่ฟ้องเรื่อง passive listener
6. ภาพทุกบทที่กว้าง 1440 · 900 · 420 (`screenshot.py` ของ `web-app-design`) เปิดดูจริง · จอแคบกว่า 900 rail เป็นแถบล่างและไม่ทับเนื้อหา
