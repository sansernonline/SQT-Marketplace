# prompt-campaign — ออกแคมเปญ: หลายแพลตฟอร์ม โปรเทศกาล แตกขนาด ตรวจก่อนปล่อย

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `graphic-design` · ไฟล์นี้รวม prompt 5 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานออกแบบของแบรนด์นั้น** (1 แบรนด์ 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปอ้างอิงไว้ใน `03-source-media/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1 และ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `graphic-design` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ในแกนของ plugin `superuser` ที่ skill นั้นใช้ร่วม ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ไม่ลอกโลโก้ ตัวการ์ตูน หรืองานที่มีเจ้าของ · ขนาดและ safe zone ของแต่ละแพลตฟอร์มตรวจกับหน้า help ของแพลตฟอร์มรอบนี้ ติดวันที่ · การสร้างภาพหรือวิดีโอด้วยเครื่องมือที่เสียเงิน การโพสต์ และการลบไฟล์ต้นฉบับ อยู่ใน "รออนุมัติ" · ไม่มี plugin สร้างภาพหรือวิดีโอติดตั้ง → ส่ง brief และ prompt พร้อมวาง แทนการสร้างเอง

**ภาษาและไฟล์:** เขียนตาม `human-writing` · โครงโฟลเดอร์ตาม `asset-organize` (`00-brand-kit/` · `01-masters/` · `02-exports/` · `03-source-media/` · `04-archive/`) · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `briefs/<asset-name>.md` · `02-exports/<campaign>/asset-matrix.md`)

| # | งาน | playbook | ได้ไฟล์ |
|---|---|---|---|
| 1 | แคมเปญหลายแพลตฟอร์ม | `campaign` | `02-exports/<campaign>/` · `asset-matrix.md` |
| 2 | โปรเทศกาลด่วน มีเวลา 1–2 วัน | `campaign` | `02-exports/<campaign>/` · `asset-matrix.md` (ชุดเล็ก) |
| 3 | มีภาพหลักแล้ว ต้องแตกเป็นทุกขนาด | `campaign` (ขั้น 2 และ 4–5) | `02-exports/<campaign>/` ครบทุกขนาด · `asset-matrix.md` |
| 4 | ตรวจงานก่อนปล่อย | `review` | `review-<asset-id>-vNN.md` |
| 5 | ลูกค้าสั่งแก้แบบคลุมเครือ หรือแก้หลายรอบไม่จบ | `review` | `review-<asset-id>-vNN.md` + ร่างข้อความตอบลูกค้า |

ใช้ต่อกัน: แคมเปญใหม่ → 1 → 4 · โปรด่วน → 2 → 4 · ส่งงานแล้วลูกค้าตอบกลับมาว่า "ยังไม่ใช่" → 5 แล้วแก้ตามแผน → 4 · ฉบับ 4 ใช้ตรวจงานจากไฟล์อื่นในโฟลเดอร์นี้ได้ทุกไฟล์

## 1. แคมเปญหลายแพลตฟอร์ม

playbook `campaign` · agent `social-creator` + `art-director` · skill `campaign-set` · `social-formats`
**ผลลัพธ์:** `02-exports/<campaign>/asset-matrix.md` + ไฟล์ทุกชิ้น · **รออนุมัติ:** โพสต์ · ยิงโฆษณา

### ข้อมูล (ผู้ใช้กรอก)

- แคมเปญ 1 ประโยค (เปิดตัว · ลดราคา · อีเวนต์ · เทศกาล):
- ช่วงเวลา / วันเริ่ม:
- แพลตฟอร์มและตำแหน่ง (Facebook feed · IG story · TikTok · LINE OA · ป้ายหน้าร้าน):
- ข้อความหลัก / โปร / ราคา:
- รูปสินค้าที่มี (path):
- brand kit (path · ไม่มี → ทำ `prompt-brand.md` ฉบับ 1 ก่อนหรือใช้ค่าชั่วคราว):

### ต้องมีในผลงาน

1. master concept 1 ชิ้น (ภาพหลัก + ข้อความหลัก) ทำให้ผ่านก่อน
2. asset matrix: ชิ้น · แพลตฟอร์ม · ขนาด · safe zone · ข้อความ · ลำดับแตกจาก master
3. ทุกชิ้นตั้งชื่อตามกฎ `asset-organize`
4. ผลตรวจรายชิ้นก่อนส่ง (ตาม `design-review`) — ชิ้นไหนไม่ผ่านบอกตรง ๆ

## 2. โปรเทศกาลด่วน มีเวลา 1–2 วัน

playbook `campaign` · agent `social-creator` · skill `campaign-set` · `social-formats`
**ผลลัพธ์:** `02-exports/<campaign>/asset-matrix.md` (ชุดเล็กเฉพาะชิ้นที่จำเป็น) + ไฟล์ทุกชิ้น · **รออนุมัติ:** โพสต์ · ยิงโฆษณา

### ข้อมูล (ผู้ใช้กรอก)

- เทศกาลหรือวันขาย (สงกรานต์ · ลอยกระทง · ปีใหม่ · วันเลขเบิ้ลอย่าง 11.11):
- วันเริ่มและวันจบโปร:
- โปร ราคา และเงื่อนไข:
- ช่องทางที่ต้องมีจริง ๆ (เรียงจากช่องทางที่ขายได้มากสุด):
- brand kit และแม่แบบเดิมที่ใช้ได้ (path):

### ต้องมีในผลงาน

1. ตัดเหลือชิ้นที่จำเป็นที่สุดตามช่องทางที่ขายได้จริง · ชิ้นที่ตัดออกเขียนไว้ใน `asset-matrix.md` เผื่อมีเวลาทำเพิ่ม
2. ใช้แม่แบบและ brand kit เดิม ไม่สร้างสไตล์ใหม่ · เติมเฉพาะองค์ประกอบเทศกาลที่ออกแบบเอง ไม่ลอกงานคนอื่น
3. ทำ master ก่อน แล้วแตกขนาดตามลำดับใน matrix
4. ราคา วันที่ และเงื่อนไขโปรตรงกันทุกชิ้น — ตรวจทีละชิ้นแล้วบอกผล
5. ผลตรวจ `design-review` รายชิ้น

### กฎเฉพาะฉบับนี้

- วันที่ของเทศกาลและวันหยุดปีนี้ตรวจกับแหล่งทางการ ติดวันที่ตรวจ
- ไม่ใช้คำว่า "ถูกที่สุด" "ดีที่สุด" หรือคำอวดเกินจริงที่ไม่มีหลักฐาน

## 5. ลูกค้าสั่งแก้แบบคลุมเครือ หรือแก้หลายรอบไม่จบ

playbook `review` (ขั้น 1–5 ตรวจตามเดิม · ขั้น 6 รายงานเพิ่มตารางแปลฟีดแบ็ก) · agent `design-critic` · skill `design-review` · `brand-kit`
**ผลลัพธ์:** `review-<asset-id>-vNN.md` (แปลฟีดแบ็ก + แผนแก้รอบถัดไป) · ร่างข้อความตอบลูกค้าในคำตอบ · **ไม่แก้ไฟล์งานเอง** · **รออนุมัติ:** ส่งข้อความถึงลูกค้า

### ข้อมูล (ผู้ใช้กรอก)

- ชิ้นงานรุ่นล่าสุดและรุ่นก่อน ๆ (path):
- ฟีดแบ็กลูกค้าทุกรอบ (คัดลอกตามที่ลูกค้าพิมพ์ เช่น "ขอให้ดูแพงขึ้น" "ยังไม่ปัง"):
- brief ตั้งต้นที่ตกลงกัน (path หรือเล่าสั้น ๆ):
- จำนวนรอบแก้ตามที่ตกลง และใช้ไปแล้วกี่รอบ (ถ้ามีข้อตกลง):

### ต้องมีในผลงาน

1. ตารางแปลฟีดแบ็ก: คำของลูกค้า · น่าจะหมายถึงอะไร (ผูกกับ 8 ข้อของ `design-review` เช่น ลำดับความสำคัญ สี ระยะ) · แก้อะไรได้ · ต้องถามกลับไหม
2. ฟีดแบ็กที่ขัดกันเอง หรือขัดกับ brief หรือ brand kit — ชี้ตำแหน่งที่ขัด ไม่เลือกข้างเอง
3. คำถามกลับลูกค้าไม่เกิน 3 ข้อ แบบให้เลือก (ก หรือ ข) พร้อมภาพเทียบถ้าทำได้
4. แผนแก้รอบถัดไป 2–3 จุด เรียงตามผลกระทบ
5. ร่างข้อความตอบลูกค้า สุภาพ สั้น บอกสิ่งที่จะแก้ คำถามกลับ และรอบแก้ที่เหลือ (ถ้ามีข้อตกลง)

### กฎเฉพาะฉบับนี้

- ฟีดแบ็กเกินขอบเขต brief เดิม → เขียนแยกว่าเป็นงานเพิ่ม ให้ผู้ใช้ตัดสินเองเรื่องคิดเงินเพิ่ม ไม่เขียนเรื่องราคาลงในร่างข้อความเอง
