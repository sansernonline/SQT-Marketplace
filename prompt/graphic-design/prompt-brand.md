# prompt-brand — ตั้งแบรนด์: brand kit ของพิมพ์ชุดแรก จัดไฟล์

ใช้คู่กับ plugin `graphic-design` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานออกแบบของแบรนด์นั้น** (1 แบรนด์ 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปอ้างอิงไว้ใน `03-source-media/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1 และ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `graphic-design` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ไม่ลอกโลโก้ ตัวการ์ตูน หรืองานที่มีเจ้าของ · ขนาดและ safe zone ของแต่ละแพลตฟอร์มตรวจกับหน้า help ของแพลตฟอร์มรอบนี้ ติดวันที่ · การสร้างภาพหรือวิดีโอด้วยเครื่องมือที่เสียเงิน การโพสต์ และการลบไฟล์ต้นฉบับ อยู่ใน "รออนุมัติ" · ไม่มี plugin สร้างภาพหรือวิดีโอติดตั้ง → ส่ง brief และ prompt พร้อมวาง แทนการสร้างเอง

**ภาษาและไฟล์:** เขียนตาม `human-writing` · โครงโฟลเดอร์ตาม `asset-organize` (`00-brand-kit/` · `01-masters/` · `02-exports/` · `03-source-media/` · `04-archive/`) · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `briefs/<asset-name>.md` · `02-exports/<campaign>/asset-matrix.md`)

| # | งาน | playbook | ได้ไฟล์ |
|---|---|---|---|
| 1 | ตั้งหรือรื้อ brand kit | `brand-setup` | `00-brand-kit/` |
| 2 | ของพิมพ์ชุดแรกของร้าน: ป้าย เมนู นามบัตร สติกเกอร์ | `brand-setup` (ขั้น 4–5) | `01-masters/print/` · `02-exports/print/` · `02-exports/print/print-spec.md` |

ใช้ต่อกัน: แบรนด์ใหม่ → 1 → 2 แล้วแคมเปญแรก → `prompt-campaign.md` ฉบับ 1 · ไฟล์รกจนหาโลโก้ไม่เจอ → 3 ก่อน แล้วค่อย 1 · ตรวจก่อนปล่อย → `prompt-campaign.md` ฉบับ 4

## 1. ตั้งหรือรื้อ brand kit

playbook `brand-setup` · agent `brand-keeper` · skill `brand-kit`
**ผลลัพธ์:** `00-brand-kit/` อ่านจบใน 5 นาที (README · โลโก้และกฎ · สี · ตัวอักษร · สไตล์ภาพ · น้ำเสียง · template 5 ชิ้น)

### ข้อมูล (ผู้ใช้กรอก)

- ชื่อแบรนด์ / ธุรกิจทำอะไร / ลูกค้าคือใคร:
- โลโก้เดิม (path) หรือ "ยังไม่มี":
- สีหรือฟอนต์ที่ใช้อยู่ / ที่ชอบ / ที่ไม่เอา:
- แบรนด์ที่ชอบหน้าตา 2–3 แบรนด์ (เพื่อดูทิศทาง ไม่ลอก):
- ใช้ที่ไหนบ้าง (โพสต์ · LINE OA · ฉลาก · ป้าย · เว็บ):
- ภาษา (ไทย / อังกฤษ / ทั้งสอง):

### ต้องมีในผลงาน

1. ทิศทาง 2–3 แบบ (คำ 3 คำ + mood) แล้วเลือก 1 พร้อมเหตุผล
2. กฎโลโก้: ระยะเว้น · ขนาดเล็กสุด · พื้นที่ใช้ได้ / ห้ามใช้
3. สีแบ่งบทบาท (หลัก · รอง · พื้น · ข้อความ · เน้น) พร้อมค่า HEX และผลตรวจ contrast
4. ตัวอักษรไทยคู่ละติน + ขนาดแต่ละระดับ (ฟอนต์ใช้เชิงพาณิชย์ได้ ระบุลิขสิทธิ์)
5. template 5 ชิ้นที่ใช้บ่อยสุดตามช่องทางที่กรอก

## 2. ของพิมพ์ชุดแรกของร้าน: ป้าย เมนู นามบัตร สติกเกอร์

playbook `brand-setup` (ขั้น 4–5: ทำแม่แบบใช้งานจริงแล้วตรวจ · ใช้ brand kit ที่มีอยู่ ไม่ทำขั้น 1–3 ซ้ำ) · agent `brand-keeper` · skill `brand-kit` · `design-review`
**ผลลัพธ์:** ไฟล์ต้นฉบับที่แก้ได้ใน `01-masters/print/` · ไฟล์ส่งพิมพ์ใน `02-exports/print/` · `02-exports/print/print-spec.md` (สเปกส่งโรงพิมพ์) · **รออนุมัติ:** ส่งไฟล์ให้โรงพิมพ์ · สั่งพิมพ์และจ่ายเงิน

### ข้อมูล (ผู้ใช้กรอก)

- ชิ้นที่ต้องทำ (ป้ายหน้าร้าน · เมนู · นามบัตร · สติกเกอร์ปิดกล่อง · ฉลาก · ถุง):
- ขนาดจริงและวัสดุของแต่ละชิ้น (ไม่รู้ปล่อยว่าง):
- ข้อความที่ต้องมี (ชื่อร้าน · ราคา · เบอร์โทร · ที่อยู่ · เวลาเปิด · ลิงก์หรือ LINE สำหรับทำ QR code):
- brand kit (path · ไม่มี → ทำฉบับ 1 ก่อนหรือใช้ค่าชั่วคราว):
- โรงพิมพ์ที่จะใช้ และสเปกที่โรงพิมพ์ขอ (ถ้ามี):

### ต้องมีในผลงาน

1. ตารางชิ้นงาน: ชิ้น · ขนาดจริง · ระยะที่คนมอง (ป้ายอ่านจากไกล · นามบัตรอ่านในมือ) · ข้อความ · ชื่อไฟล์ตาม `asset-organize`
2. ขนาดตัวอักษรเล็กสุดของแต่ละชิ้นตามระยะมอง · ข้อความสำคัญอยู่ห่างจากขอบตัด
3. `print-spec.md`: ระบบสีสำหรับงานพิมพ์ (CMYK — สี่สีที่โรงพิมพ์ใช้) · ความละเอียด · ระยะเผื่อตัด (bleed) · ฟอนต์แปลงเป็นเส้นหรือแนบไฟล์ — ตัวเลขทุกค่าตรวจกับโรงพิมพ์ที่ใช้ ไม่มีข้อมูล → `(รอยืนยัน)`
4. QR code สแกนได้จริงและพาไปถูกที่ (ทดสอบแล้วบอกผล) · เบอร์โทรและราคาตรงกับที่กรอกทุกชิ้น
5. ผลตรวจ `design-review` ทุกชิ้น

### กฎเฉพาะฉบับนี้

- สีบนจอกับสีที่พิมพ์ออกมาไม่ตรงกันเสมอ → แนะนำให้ขอปรู๊ฟ (ตัวอย่างพิมพ์) ก่อนสั่งพิมพ์จำนวนมาก
- ไม่มีเครื่องมือทำไฟล์จริง → ส่งแบบร่างพร้อมขนาดและตำแหน่งทุกองค์ประกอบ ให้ผู้ใช้หรือร้านทำต่อ

## 3. จัดไฟล์งานออกแบบที่รก

playbook `asset-cleanup` · agent `brand-keeper` · skill `asset-organize`
**ผลลัพธ์:** โครงโฟลเดอร์ใหม่ · `rename-log.csv` (ชื่อเดิม → ชื่อใหม่) · **รออนุมัติ:** ลบไฟล์ซ้ำ (ย้ายไป `_to_delete/` แทนการลบ)

### ข้อมูล (ผู้ใช้กรอก)

- โฟลเดอร์ที่จะจัด (path):
- ไฟล์ที่ห้ามแตะ:
- แคมเปญที่จบแล้ว (เก็บเข้า `04-archive/`):

### ต้องมีในผลงาน

1. แผนก่อนย้าย: จำนวนไฟล์ · จะย้ายไปไหน · ไฟล์ซ้ำที่เจอ
2. เปลี่ยนชื่อและย้ายด้วยสคริปต์ที่รันซ้ำได้ ไม่ทำมือทีละไฟล์
3. `rename-log.csv` ครบทุกไฟล์ ย้อนกลับได้
4. ผลตรวจหลังย้าย: จำนวนไฟล์ก่อน = หลัง · โลโก้ฉบับล่าสุดอยู่ที่ `00-brand-kit/`
