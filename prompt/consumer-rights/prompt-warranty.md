# prompt-warranty — หลังซื้อ: ทะเบียนรับประกัน เคลม ของเสียซ้ำ

ใช้คู่กับ plugin `consumer-rights` · ไฟล์นี้รวม prompt 2 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ผู้บริโภค** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางหลักฐาน (ใบเสร็จ แชต รูป) ไว้ใน `evidence/<เรื่อง>/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `consumer-rights` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่าง → ถามรวมครั้งเดียวก่อนเริ่ม ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → หยุดและบอกผู้ใช้

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมาย · กฎหมาย เลขสายด่วน ช่องทางร้องเรียน และระยะเวลา ต้องตรวจกับแหล่งทางการรอบนี้ (ติดวันที่ตรวจ) · ส่งข้อความถึงร้าน ยื่นเรื่อง สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) หรือขอ chargeback อยู่ใน "รออนุมัติ" เสมอ · ไม่แต่งหลักฐาน · คดีที่มูลค่าสูงหรือซับซ้อน → แนะนำทนาย

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `warranties.csv`) ไม่กำหนด → ใช้ชื่อในตาราง

## 1. ทะเบียนรับประกันและการเคลม

playbook `warranty-claim` · agent `consumer-advocate` · skill `warranty-tracker`
**ผลลัพธ์:** `warranties.csv` (ทะเบียน) · `cases/<ปี-เดือน>-<ของ>/claim.md` เมื่อเคลม · **รออนุมัติ:** ส่งเครื่องเคลม

### ข้อมูล (ผู้ใช้กรอก)

- งานนี้คือ (เพิ่มของเข้าทะเบียน / ตรวจว่ายังอยู่ในประกัน / เคลม):
- ของ · ยี่ห้อ · รุ่น · เลขเครื่อง:
- วันที่ซื้อ / ร้าน / ระยะประกัน:
- ใบเสร็จ บัตรประกัน (path หรือรูป):
- อาการเสีย (ถ้าเคลม):

### ต้องมีในผลงาน

1. แถวในทะเบียนครบช่อง พร้อมวันหมดประกันที่คำนวณแล้ว และที่เก็บใบเสร็จ
2. รายการที่จะหมดประกันใน 60 วัน
3. ถ้าเคลม: ยังอยู่ในประกันไหม · ศูนย์บริการที่ใกล้ (ตรวจจริง) · เอกสารที่ต้องพก · ข้อความแจ้งเคลม
4. สิ่งที่ประกันมักไม่ครอบคลุมสำหรับของประเภทนี้ (ตามเงื่อนไขจริงของยี่ห้อ)

## 2. ของเสียซ้ำหลังซ่อมในประกันหลายครั้ง

playbook `warranty-claim` (ใช้ขั้น 1 เปิดทะเบียน และขั้น 3 ตรวจประกันกับเงื่อนไขยกเว้น · ส่วนขอเปลี่ยนเครื่องหรือคืนเงินเกินขอบเขต playbook นี้ จึงต่อด้วยฉบับ 1 ของ `prompt-complaint.md` ตามหัวข้อ 2 ของ `superuser`) · agent `consumer-advocate` · skill `warranty-tracker` · `complaint-letter-th`
**ผลลัพธ์:** `cases/<ปี-เดือน>-<ของ>/repeat-defect.md` · **รออนุมัติ:** ส่งเครื่องซ่อมรอบใหม่ · ส่งหนังสือขอเปลี่ยนเครื่องหรือคืนเงิน

### ข้อมูล (ผู้ใช้กรอก)

- ของ · ยี่ห้อ · รุ่น · เลขเครื่อง · วันที่ซื้อ · ราคา:
- ส่งซ่อมไปกี่ครั้ง แต่ละครั้งวันไหน อาการอะไร:
- ใบรับซ่อม ใบส่งคืน รายงานการซ่อม (path):
- ช่วงที่ใช้ไม่ได้รวมกี่วัน:
- อยากได้อะไร (เปลี่ยนเครื่องใหม่ · คืนเงิน · ขยายประกัน):

### ต้องมีในผลงาน

1. ตารางประวัติซ่อม: ครั้งที่ · วันที่ส่ง · วันที่ได้คืน · อาการ · ศูนย์แจ้งว่าแก้อะไร · เลขใบรับซ่อม
2. ยังอยู่ในประกันไหม และประกันนับต่อหรือเริ่มใหม่หลังซ่อม ตามเงื่อนไขจริงของยี่ห้อ (ตรวจรอบนี้ ติดวันที่ตรวจ)
3. นโยบายเปลี่ยนเครื่องของยี่ห้อหรือร้าน (ถ้ามี) ยกมาจากเอกสารจริง · ไม่มีเอกสาร → `(รอยืนยัน)`
4. หนังสือขอเปลี่ยนเครื่องหรือคืนเงิน แนบตารางประวัติซ่อม และขอคำตอบภายในวันที่กำหนด
5. ไม่ได้ผล → `prompt-complaint.md` ฉบับ 1 พร้อมไฟล์นี้เป็นหลักฐาน

### กฎเฉพาะฉบับนี้

- ตัวเลขทุกช่องในตารางประวัติซ่อมมาจากใบรับซ่อมจริง · ครั้งที่ไม่มีใบ → ระบุว่า "ผู้ใช้เล่า"
- รถยนต์หรือของมูลค่าสูง → แนะนำปรึกษา สคบ. หรือทนายก่อนรับข้อเสนอชดเชยใด ๆ
