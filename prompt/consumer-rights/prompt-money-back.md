# prompt-money-back — ขอเงินคืน: ของมีปัญหา โอนแล้วไม่ได้ของ บิลผิด

ใช้คู่กับ plugin `consumer-rights` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ผู้บริโภค** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางหลักฐาน (ใบเสร็จ แชต รูป) ไว้ใน `evidence/<เรื่อง>/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `consumer-rights` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบ 5 รอบยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมาย · กฎหมาย เลขสายด่วน ช่องทางร้องเรียน และระยะเวลา ต้องตรวจกับแหล่งทางการรอบนี้ (ติดวันที่ตรวจ) · ส่งข้อความถึงร้าน ยื่นเรื่อง สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) หรือขอ chargeback อยู่ใน "รออนุมัติ" เสมอ · ไม่แต่งหลักฐาน · คดีที่มูลค่าสูงหรือซับซ้อน → แนะนำทนาย

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `warranties.csv`) ไม่กำหนด → ใช้ชื่อในตาราง

## 1. ขอเงินคืน

playbook `refund` · agent `consumer-advocate` · skill `refund-request`
**ผลลัพธ์:** `cases/<ปี-เดือน>-<ร้าน>/refund.md` · **รออนุมัติ:** ส่งคำขอ · ยื่นข้อพิพาทบัตร

### ข้อมูล (ผู้ใช้กรอก)

- เกิดอะไรขึ้น (ของเสีย · ปลอม · ไม่ส่ง · เปลี่ยนใจหลังซื้อขายตรง · รายการบัตรที่ไม่รู้จัก):
- ซื้อจากใคร / ช่องทางไหน (หน้าร้าน · แพลตฟอร์ม · ขายตรง · โทรศัพท์):
- วันที่ซื้อ / วันที่รับของ / ยอดเงิน:
- จ่ายด้วยอะไร (บัตรเครดิต · โอน · ปลายทาง · e-wallet):
- หลักฐานที่มี (path):
- ติดต่อร้านไปแล้วหรือยัง ได้คำตอบว่าอะไร:

### ต้องมีในผลงาน

0. รายการบัตรที่ไม่รู้จัก → บรรทัดแรกของผลงานบอกให้โทรอายัดหรือระงับบัตรกับธนาคารทันที · เบอร์และช่องทางตรวจกับเว็บธนาคารรอบนี้ ติดวันที่ · ห้ามเขียนเบอร์จากความจำ
1. เส้นทางที่ใช้ได้ (ร้าน → แพลตฟอร์ม → ธนาคาร → สคบ.) พร้อม**กำหนดเวลาที่เหลือ**ของแต่ละทาง
2. รายการหลักฐานที่มี / ที่ยังขาด
3. ข้อความขอเงินคืนพร้อมส่ง (สุภาพแต่ชัด ระบุยอด วันที่ และวันที่ขอคำตอบ)
4. ถ้าจ่ายบัตร: ขั้นตอนขอ chargeback กับธนาคาร และกำหนดเวลา
5. แผนถัดไปถ้าร้านไม่ตอบภายในวันที่กำหนด → ชี้ไป `prompt-complaint.md` ฉบับ 1

## 2. โอนเงินแล้วไม่ได้ของ / ถูกหลอกขาย

playbook `refund` · agent `consumer-advocate` · skill `refund-request` · `complaint-letter-th`
**ผลลัพธ์:** `cases/<ปี-เดือน>-<ร้าน>/not-delivered.md` · **รออนุมัติ:** แจ้งธนาคาร · แจ้งความ · ยื่นข้อพิพาทกับแพลตฟอร์ม · ส่งข้อความถึงผู้ขาย

### ข้อมูล (ผู้ใช้กรอก)

- ซื้ออะไร / ยอดเงิน / วันเวลาที่โอน:
- โอนเข้าบัญชีอะไร (ธนาคาร · ชื่อบัญชี · เลขบัญชี) หรือจ่ายผ่านช่องทางไหน:
- ผู้ขาย (ชื่อเพจ · ลิงก์ · เบอร์โทร · ไอดี LINE):
- ผู้ขายยังตอบอยู่ไหม / บล็อกแล้วหรือยัง:
- หลักฐาน (สลิป · แชต · ประกาศขาย — path):

### ต้องมีในผลงาน

1. **สิ่งที่ต้องทำก่อนภายในวันนี้** เรียงตามความเร่ง: แจ้งธนาคารต้นทาง · ช่องทางแจ้งความออนไลน์หรือสายด่วนของตำรวจ · ขออายัดบัญชีปลายทาง — ช่องทางและเลขสายด่วนทุกข้อตรวจกับเว็บทางการรอบนี้ ติดวันที่ตรวจ
2. รายการหลักฐานที่ต้องเก็บก่อนผู้ขายลบ (ภาพหน้าจอประกาศ · หน้าโปรไฟล์ · แชตทั้งหมด · สลิป) พร้อมวิธีบันทึกให้เห็นวันเวลา
3. ไทม์ไลน์ข้อเท็จจริงสำหรับยื่นธนาคารและตำรวจ แยก "มีหลักฐาน" ออกจาก "ผู้ใช้เล่า"
4. จ่ายผ่านแพลตฟอร์มหรือบัตร: ขั้นตอนเปิดข้อพิพาทหรือ chargeback และกำหนดเวลาที่เหลือ ตาม `refund-request`
5. ข้อความถึงผู้ขาย 1 ครั้ง (ขอส่งของหรือคืนเงิน มีวันที่ขอคำตอบ) · ไม่ข่มขู่
6. ตารางติดตาม: หน่วยงาน · เลขรับเรื่อง · วันที่ยื่น · สถานะ

### กฎเฉพาะฉบับนี้

- ผู้ใช้กำลังจะโอนเพิ่มเพราะถูกขอ "ค่าส่ง ค่าภาษี ค่าปลดล็อก" → เตือนในบรรทัดแรกให้หยุดโอน
- ไม่รับปากว่าจะได้เงินคืน · บอกตามจริงว่าแต่ละทางขึ้นกับอะไร

## 3. บิลผิด หรือถูกเก็บเงินบริการที่ไม่ได้สมัคร

playbook `refund` · agent `consumer-advocate` · skill `refund-request` · `complaint-letter-th`
**ผลลัพธ์:** `cases/<ปี-เดือน>-<ผู้ให้บริการ>/billing.md` · **รออนุมัติ:** ส่งคำขอคืนเงินหรือยกเลิกบริการ · ยื่นข้อพิพาทบัตร · ร้องเรียนหน่วยงานกำกับ

### ข้อมูล (ผู้ใช้กรอก)

- ผู้ให้บริการ (มือถือ · อินเทอร์เน็ต · ทีวี · แอปสมาชิก · บัตรเครดิต · อื่น ๆ):
- รายการที่ผิดหรือไม่ได้สมัคร · ยอดต่อเดือน · เริ่มเก็บตั้งแต่เดือนไหน:
- บิลหรือ statement (path):
- เคยกดสมัคร กดลิงก์ หรือได้ข้อความแจ้งสมัครไหม:
- โทรแจ้งผู้ให้บริการแล้วหรือยัง ได้เลขอ้างอิงไหม:

### ต้องมีในผลงาน

1. ตารางรายการที่เก็บผิดทุกเดือน: เดือน · รายการ · ยอด · หลักฐานอยู่ไหน · รวมยอดขอคืน คำนวณซ้ำได้
2. วิธียกเลิกบริการเสริมทันที (ตามช่องทางของผู้ให้บริการ ตรวจรอบนี้ ติดวันที่ตรวจ) เพื่อไม่ให้ถูกเก็บเดือนถัดไป
3. ข้อความขอคืนเงินพร้อมส่ง ระบุเดือน ยอด และวันที่ขอคำตอบ
4. ถ้าเก็บผ่านบัตร: ขั้นตอนปฏิเสธรายการกับธนาคาร และกำหนดเวลา ตาม `refund-request`
5. ผู้ให้บริการไม่แก้: หน่วยงานกำกับของบริการนั้น (เช่น บริการโทรคมนาคม → สำนักงานคณะกรรมการกิจการกระจายเสียง กิจการโทรทัศน์ และกิจการโทรคมนาคมแห่งชาติ (กสทช.)) ช่องทางและกรอบเวลาตรวจกับเว็บทางการรอบนี้ ติดวันที่ตรวจ → `prompt-complaint.md` ฉบับ 1

### กฎเฉพาะฉบับนี้

- ยอดทุกบรรทัดมาจากบิลจริง · เดือนที่ไม่มีบิล → `(รอยืนยัน)` ไม่ประมาณเอง
