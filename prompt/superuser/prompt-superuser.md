# prompt-superuser — งานทั่วไป + ฉบับกลางที่ใช้ได้กับทุก plugin

ใช้คู่กับ plugin `superuser` (ฉบับ 1–3 · 6–9 · 11) · plugin ใดก็ได้ในชุด (ฉบับ 4–5) · plugin `software-company` (ฉบับ 10 ใช้ playbook ของที่นั่น แต่แก้ skill ได้ทุก plugin) · ไฟล์นี้รวม prompt 11 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งาน**
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · ฉบับ 4–5 ใส่ชื่อ plugin ในช่อง "plugin"
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** ฉบับ 1–3 · 6 · 8 · 9 · 11 เปิด skill `superuser` ของ plugin `superuser` · ฉบับ 4–5 เปิด skill `superuser` ของ plugin ที่ผู้ใช้กรอก · ฉบับ 10 เปิด skill `superuser` ของ plugin `software-company` · แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · หาไม่เจอ → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ภาษาและไฟล์:** เขียนตาม `human-writing` · โครงคำตอบตาม `answer-shape`

## 6. ทำ superuser ให้ plugin สาขาใหม่

ทำตาม `ADAPT.md` ของ plugin `superuser` · เปิดที่**ราก repo SQT-Marketplace**
**ผลลัพธ์:** `plugins/<ชื่อ plugin>/` ที่ผ่าน `validate-marketplace.mjs` · ไฟล์ prompt แยกตามสถานการณ์ + `README.md` ใน `prompt/<ชื่อ plugin>/` · แถวใหม่ใน `prompt/README.md`

### ข้อมูล (ผู้ใช้กรอก)

- ชื่อ plugin (ตัวพิมพ์เล็ก ขีดกลาง):
- สาขางาน / ผู้ใช้คือใคร:
- งานที่ทำบ่อย 4–8 อย่าง (จะกลายเป็น playbook):
- บทบาท agent 2–5 บทบาท:
- เรื่องที่ต้อง "รออนุมัติ" เสมอในสาขานี้:
- ขอบเขตที่ห้ามข้าม (เช่น ไม่วินิจฉัย · ไม่ใช่คำแนะนำการลงทุน):

### ต้องมีในผลงาน

1. โครง plugin ตามข้อ 2 ของ `ADAPT.md` · ของกลางมาจาก `sync-superuser.mjs` ไม่คัดลอกมือ
2. playbook ของสาขาตาม `playbook-template` · `review` และ `unattended-run` ปรับตัวอย่างให้เข้าสาขา
3. skill ของสาขา: description บอกว่า "ใช้เมื่อ" ชัด · ไม่ซ้ำกับ skill ที่มีอยู่แล้วใน plugin อื่น
4. ผล `validate-marketplace.mjs` ผ่าน · รัน `sync-docs.mjs` แล้ว · build ได้ด้วย `scripts/build-dist.cmd`
5. `prompt/<ชื่อ plugin>/` แบบเดียวกับสาขาอื่น: ไฟล์ `prompt-<สถานการณ์>.md` 4–5 ไฟล์ (ไฟล์ละ 2–5 ฉบับ) · `README.md` มีตาราง "รายการไฟล์" และ "เลือกจากสถานการณ์" 16–20 แถว
6. ลองงานจริง 3 งาน (เล็ก · กลาง · ใหญ่) แล้วรายงานว่าจัดขนาดและเลือก playbook ถูกไหม

## 7. สอน agent ให้ทำงานแบบผม

## 11. เปิดด่าน guard และ recompact ในโปรเจกต์

skill `superuser` → `references/modules.md` (หัวข้อ config) · ไม่ต้องเปิด playbook · ทำที่**โฟลเดอร์งาน**ของโปรเจกต์นั้น
**ผลลัพธ์:** `.claude/superuser/config.json` ที่ตั้ง `modules.guard` และ `modules.recompact` ตามที่ติ๊ก · `.claude/superuser/guard-allow.json` เมื่อผู้ใช้กรอกข้อยกเว้น · ผลทดสอบในคำตอบ

### ข้อมูล (ผู้ใช้กรอก)

- เปิดตัวไหน: ☐ `guard` ด่านกันคำสั่ง Bash ที่กฎประจำตัวห้าม (เช่น `git push` · `git commit` · `git reset --hard` · `rm -rf` นอก `_to_delete/` · รายการเต็มอยู่ใน `hooks/guard-rules.json` ของ plugin) ☐ `recompact` หลังย่อบริบท ส่งหัวข้อ "ความคืบหน้า" และ "รับงานต่อ" ของ `CONTEXT.md` กลับมาให้
- ข้อยกเว้นของโปรเจกต์นี้ (เช่น ผู้ใช้อนุญาตให้ commit ได้ → `git-commit` · push ได้เฉพาะ branch งาน → `^git push origin feature/` · เว้นว่าง = ไม่มี):

### ต้องมีในผลงาน

1. มี `.claude/superuser/config.json` อยู่แล้ว → แก้เฉพาะ key `guard` และ `recompact` ใต้ `modules` ค่าอื่นคงเดิม · ยังไม่มี → สร้างจาก `templates/config.json` ของ skill `superuser` แล้วตั้ง 2 key ตามที่ติ๊ก (ไม่มีไฟล์ = เปิดทุกโมดูล ยกเว้น `guard` และ `recompact`)
2. ข้อยกเว้นเขียนลง `.claude/superuser/guard-allow.json` รูปแบบ `{"allow": [...]}` · ค่าที่เป็น id ของกฎ (เช่น `git-commit`) ปิดกฎข้อนั้น · ค่าอื่นเป็น regex ที่ถ้าตรงคำสั่งให้ผ่าน · ใส่เฉพาะที่ผู้ใช้กรอก ไม่เพิ่มเอง
3. ทดสอบ: รัน `node <โฟลเดอร์ที่ติดตั้ง plugin superuser>/hooks/superuser-hook.mjs --self-test` ต้องผ่านทุกข้อ · `guard` ลองด้วยคำสั่งที่ไม่มีผลเสีย เช่น `git commit --dry-run` แล้วต้องโดนปฏิเสธพร้อมเหตุผลและกฎที่มา (เว้นแต่ใส่ `git-commit` เป็นข้อยกเว้นไว้)
4. บอกผู้ใช้ว่ามีผลทันทีในเหตุการณ์ถัดไป ไม่ต้องเริ่ม session ใหม่ · `guard` ตรวจเฉพาะ Bash ไม่แตะ Read · Edit · Write · `recompact` ทำงานเมื่อย่อบริบท และไม่ส่งอะไรถ้าไม่มี `CONTEXT.md` หรือไม่มีหัวข้อนั้น · ผู้ใช้ลองจริงได้ด้วยการพิมพ์ `/compact`

### กฎเฉพาะฉบับนี้

- `.claude/superuser/` ไม่ commit ยกเว้น `CONTEXT.md` และ `IMPROVEMENTS.md` · ไฟล์ตั้งค่าใน `~/.claude/` ไม่อยู่ในฉบับนี้
