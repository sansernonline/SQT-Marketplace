# prompt-start-learning — เริ่มเรียนของใหม่: เทคโนโลยีใหม่ stack ของงานใหม่ เลือกสาย

ใช้คู่กับ plugin `dev-learning` · ไฟล์นี้รวม prompt 4 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์เรียนรู้** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · ไม่รู้ปล่อยว่างได้
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `dev-learning` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**ขอบเขต:** ข้อมูลเวอร์ชัน การเปลี่ยนแปลง และหลักสูตรสอบ อ่านจากแหล่งทางการ (release notes · changelog · exam guide) รอบนี้ ติดวันที่ตรวจ · โค้ดตัวอย่างต้องรันผ่านจริงก่อนส่ง · การสมัครสอบ ซื้อคอร์ส หรือจ่ายเงิน อยู่ใน "รออนุมัติ"

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `radar/reports/YYYY-Www.md` · `cert/<exam-code>-plan.md` · `notes/<short-title>.md`) ไม่กำหนด → ใช้ชื่อในตาราง

| # | งาน | playbook | ได้ไฟล์ |
|---|---|---|---|
| 1 | เรียนเทคโนโลยีใหม่เป็นขั้น | `learning-path` | `paths/<เทคโนโลยี>/README.md` + โค้ดแต่ละขั้น |
| 2 | งานใหม่ต้องใช้ stack ที่ไม่เคยใช้ เวลาน้อย | `learning-path` | `paths/<เทคโนโลยี>/README.md` + `paths/<เทคโนโลยี>/compare.md` |
| 3 | เริ่มจากศูนย์หรือเปลี่ยนสายมาเขียนโปรแกรม ยังเลือกสายไม่ได้ | — (โจทย์ไม่ชัด: brainstorm ตาม `superuser` หัวข้อ 2) → `learning-path` | `docs/BRIEF.md` + `paths/<สาย>/README.md` |
| 4 | ตรวจงานเรียนรู้ก่อนใช้ | `review` | คำตัดสินในคำตอบ · ไม่สร้างไฟล์ |

ใช้ต่อกัน: ยังไม่รู้จะเรียนสายไหน → 3 แล้วทางที่เลือก → 1 · ได้งานใหม่ที่ใช้ภาษาที่ไม่เคยเขียน → 2 → 4 · ฉบับ 4 ใช้ตรวจงานจากไฟล์อื่นในโฟลเดอร์นี้ได้ทุกไฟล์

## 1. เรียนเทคโนโลยีใหม่เป็นขั้น

playbook `learning-path` · agent `tech-mentor` · skill `learning-path`
**ผลลัพธ์:** `paths/<เทคโนโลยี>/README.md` (แผน) + `paths/<เทคโนโลยี>/m<เลข>-<ชื่อ>/` (โค้ดแต่ละขั้น)

### ข้อมูล (ผู้ใช้กรอก)

- เรียนอะไร:
- ความลึกที่ต้องการ (รู้จักพอคุยได้ / ใช้งานได้ / เชี่ยวชาญ):
- พื้นฐานที่มี (ภาษา framework ที่ใช้อยู่):
- โปรเจกต์จริงที่จะเอาไปใช้ (path หรือชื่อ):
- เวลาต่อสัปดาห์ / อยากใช้ได้ภายในเมื่อไร:

### ต้องมีในผลงาน

1. milestone 4–8 ขั้น แต่ละขั้นจบด้วยโค้ดที่รันได้ และผูกกับโปรเจกต์จริงของผู้ใช้
2. แต่ละขั้น: เป้า · แหล่งเรียน 1–2 แหล่ง (ทางการก่อน) · งานที่ต้องทำ · ตรวจผ่านเมื่อ
3. checkpoint ตรง ๆ ว่าถึงขั้นไหนถือว่าใช้งานได้
4. ขั้นแรกทำให้เสร็จเลยในรอบนี้ (โค้ด + README ที่รันตามได้)

## 2. งานใหม่ต้องใช้ stack ที่ไม่เคยใช้ เวลาน้อย

playbook `learning-path` · agent `tech-mentor` · skill `learning-path` · `english-tech-reading`
**ผลลัพธ์:** `paths/<เทคโนโลยี>/README.md` (แผนแบบเร่ง) · `paths/<เทคโนโลยี>/compare.md` (ของที่รู้แล้ว → ของใน stack ใหม่) · โค้ดขั้นแรก

### ข้อมูล (ผู้ใช้กรอก)

- stack ที่ต้องใช้ (ภาษา framework ฐานข้อมูล เครื่องมือ build):
- stack ที่ถนัดอยู่แล้ว:
- วันเริ่มงาน หรือวันที่ต้องส่งงานชิ้นแรก:
- งานแรกที่น่าจะได้รับ (ถ้ารู้):
- repo ของทีม (path · ไม่มีสิทธิ์เข้าถึงปล่อยว่าง):
- เวลาต่อวันก่อนเริ่มงาน:

### ต้องมีในผลงาน

1. ตารางเทียบ "ของที่รู้แล้ว → ของใน stack ใหม่" เฉพาะเรื่องที่ต่างกัน: syntax ที่ใช้บ่อย · ตัวจัดการแพ็กเกจ · วิธีรัน test · วิธี build · ข้อผิดพลาดที่คนย้ายมาจาก stack เดิมมักเจอ
2. milestone 3–5 ขั้น เรียงตามงานแรกที่จะได้รับ ไม่ใช่ตามสารบัญหนังสือ
3. รายการสิ่งที่ข้ามไปก่อนได้จนกว่าจะเริ่มงาน
4. ขั้นแรกทำให้เสร็จในรอบนี้: โปรเจกต์เล็กที่ build และรัน test ผ่านด้วยเครื่องมือชุดเดียวกับทีม (ถ้ารู้จาก repo) พร้อมคำสั่งรัน
5. checkpoint "พร้อมรับงานแรก" ที่ตรวจได้ 3–5 ข้อ

### กฎเฉพาะฉบับนี้

- repo ของทีมอ่านอย่างเดียว ไม่แก้ ไม่ commit · ตัวอย่างโค้ดเขียนใน `paths/` เท่านั้น
- เวลาไม่พอสำหรับทุก milestone → บอกตรง ๆ ว่าตัดอะไร และอะไรต้องเรียนต่อหลังเริ่มงาน

## 3. เริ่มจากศูนย์หรือเปลี่ยนสายมาเขียนโปรแกรม ยังเลือกสายไม่ได้

ไม่มี playbook ที่ตรง → ทำตาม skill `superuser` หัวข้อ 2 แถว "ใหญ่ หรือโจทย์ไม่ชัด" (`brainstormer` ตัวใหม่เสนอ 2–3 ทาง → `docs/BRIEF.md`) แล้วใช้ playbook `learning-path` กับทางที่เลือก · agent `tech-mentor` · skill `learning-path` · `answer-shape`
**ผลลัพธ์:** `docs/BRIEF.md` (ทางที่เลือกและเหตุผล) · `paths/<สาย>/README.md` · **รออนุมัติ:** สมัครคอร์สหรือ bootcamp ที่เสียเงิน

### ข้อมูล (ผู้ใช้กรอก)

- ตอนนี้ทำงานหรือเรียนอะไร:
- เคยเขียนโค้ดมาก่อนไหม (ไม่เคย / เคยเล็กน้อย / เขียนเป็นงานอดิเรก):
- สนใจงานแบบไหน (หน้าเว็บ · แอปมือถือ · ข้อมูล · ระบบหลังบ้าน · ทดสอบซอฟต์แวร์ · ยังไม่รู้):
- เวลาต่อสัปดาห์:
- อยากได้งานสายนี้ภายในเมื่อไร / หรือเรียนเป็นงานเสริม:
- งบเรียน (ใช้ของฟรีอย่างเดียวได้):

### ต้องมีในผลงาน

1. ตารางเทียบสาย 2–3 ทาง: งานจริงในแต่ละวัน · ต้องเรียนอะไรบ้าง · เวลาถึงขั้นสมัครงานได้ · ความต้องการในตลาดงาน — ตลาดงานตรวจจากประกาศงานรอบนี้ ติดวันที่ตรวจ · เวลาและเงินเดือนที่ไม่มีแหล่งรองรับ → `(รอยืนยัน)`
2. ทางที่แนะนำ 1 ทาง พร้อมเหตุผลที่ผูกกับข้อมูลที่กรอก
3. งานทดลอง 1 สัปดาห์ต่อสาย (งานเล็กที่ทำเสร็จได้) สำหรับคนที่ยังตัดสินใจไม่ได้
4. learning path ของทางที่เลือกตามฉบับ 1 ขั้นแรกทำให้เสร็จในรอบนี้
5. ขั้นต่อไปหลังเรียนได้ระดับใช้งาน: ทำพอร์ต → `prompt-portfolio.md` ฉบับ 1

### กฎเฉพาะฉบับนี้

- ไม่สัญญาว่า "เรียนจบได้งานแน่" · ข้อมูลตลาดงานและเงินเดือนต้องมีแหล่งและวันที่
- เขียน CV และเตรียมสัมภาษณ์ไม่อยู่ในฉบับนี้ · บอกผู้ใช้ว่าอยู่ใน plugin `career`

## 4. ตรวจงานเรียนรู้ก่อนใช้

playbook `review` · agent `reviewer` ตัวใหม่ (ความรู้เฉพาะเรื่องจาก `tech-mentor` ตัวใหม่ ถ้าต้องใช้)
**ผลลัพธ์:** คำตัดสิน `ผ่าน / แก้ก่อนใช้` · **ไม่แก้ไฟล์เอง**

### ข้อมูล (ผู้ใช้กรอก)

- ไฟล์ที่จะให้ตรวจ (แผนเรียน · โน้ต · โค้ดตัวอย่าง · แผนสอบ):
- จะเอาไปใช้ทำอะไร:

### ต้องมีในผลงาน

1. คำตัดสิน 1 บรรทัด
2. ตารางปัญหา: ตำแหน่ง · ปัญหา (ข้อมูลเก่า · โค้ดรันไม่ผ่าน · แหล่งไม่ทางการ · ขั้นกระโดด) · ระดับ · วิธีแก้
3. ผลรันโค้ดจริง (ถ้ามีโค้ด)
