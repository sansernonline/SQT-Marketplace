# prompt-portfolio — side project และพอร์ต: เลือกและเริ่ม ปลุกโปรเจกต์ที่ค้าง

ใช้คู่กับ plugin `dev-learning` · ไฟล์นี้รวม prompt 2 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์เรียนรู้** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · ไม่รู้ปล่อยว่างได้
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `dev-learning` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ข้อมูลเวอร์ชัน การเปลี่ยนแปลง และหลักสูตรสอบ อ่านจากแหล่งทางการ (release notes · changelog · exam guide) รอบนี้ ติดวันที่ตรวจ · โค้ดตัวอย่างต้องรันผ่านจริงก่อนส่ง · การสมัครสอบ ซื้อคอร์ส หรือจ่ายเงิน อยู่ใน "รออนุมัติ"

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `radar/reports/YYYY-Www.md` · `cert/<exam-code>-plan.md` · `notes/<short-title>.md`) ไม่กำหนด → ใช้ชื่อในตาราง

ใช้ต่อกัน: ทำค้างแล้วตัดสินใจปิด → 2 แล้วเลือกใหม่ → 1 · ตรวจ README ก่อนเอาไปโชว์ → `prompt-start-learning.md` ฉบับ 4

## 1. เลือกและเริ่ม side project

playbook `side-project` · agent `tech-mentor` · skill `side-project-picker`
**ผลลัพธ์:** `side-projects/<ชื่อ>/README.md` (ขอบเขต · นิยามเสร็จ · แผน 2 สุดสัปดาห์)

### ข้อมูล (ผู้ใช้กรอก)

- ไอเดียที่มี (หรือ "ยังไม่มี"):
- อยากฝึกเทคโนโลยีอะไร / ทำพอร์ตไปสมัครงานแบบไหน:
- เวลาที่มี:

### ต้องมีในผลงาน

1. ตารางให้คะแนนไอเดีย (ได้ฝึกสิ่งที่ต้องการ · ทำเสร็จได้จริง · โชว์ในพอร์ตได้ · สนุก)
2. ไอเดียที่เลือก ตัดขอบเขตให้จบใน 2 สุดสัปดาห์
3. นิยาม "เสร็จ" ที่ตรวจได้ และสิ่งที่**ไม่ทำ**ในรอบแรก (ลง `later.md`)
4. งานชิ้นแรกที่เริ่มได้วันนี้

## 2. side project ทำค้าง ไม่จบสักที

playbook `side-project` (ขั้น 2–4 ทำกับโปรเจกต์เดิม: ตัด scope · นิยามเสร็จ · โครงที่รันได้) · agent `tech-mentor` · skill `side-project-picker`
**ผลลัพธ์:** อัปเดต `side-projects/<ชื่อ>/README.md` (ขอบเขตใหม่ · นิยามเสร็จ) · `later.md` (ส่วนที่ตัดออก) · **ไม่ลบโค้ดเดิม** · **รออนุมัติ:** ลบ repo · เปลี่ยน repo เป็นสาธารณะ · เก็บเข้าคลัง (archive) บน GitHub

### ข้อมูล (ผู้ใช้กรอก)

- โปรเจกต์ (path หรือลิงก์ repo):
- ตั้งใจทำไว้เพื่ออะไร (ฝึก · พอร์ต · ใช้เอง · ขาย):
- ค้างมานานเท่าไร / ติดตรงไหน:
- เวลาที่มีตอนนี้:

### ต้องมีในผลงาน

1. สำรวจของที่มี: รันได้ไหม (รันจริงแล้วบอกผล) · ฟีเจอร์ที่เสร็จแล้ว · ส่วนที่ค้าง · สาเหตุที่ค้างจากที่เห็นในโค้ดและที่ผู้ใช้เล่า
2. คำตัดสิน 1 ใน 3: **ตัดแล้วทำให้จบ** · **เปลี่ยนเป็นโปรเจกต์เล็กกว่า** · **ปิด** พร้อมเหตุผล
3. ไม่ปิด → ขอบเขตใหม่ที่จบใน 2 สุดสัปดาห์ และนิยาม "เสร็จ" ที่ตรวจได้ 3–5 ข้อ · ส่วนที่ตัดลง `later.md`
4. งานชิ้นแรกที่เล็กพอทำจบใน 1 ชั่วโมง เริ่มได้วันนี้
5. จะใช้เป็นพอร์ต → README ที่คนอื่นอ่านแล้วรันตามได้ (ติดตั้ง · รัน · ภาพหน้าจอ · สิ่งที่ได้เรียน)

### กฎเฉพาะฉบับนี้

- ปิดโปรเจกต์ = เขียนสรุปสิ่งที่ได้เรียนไว้ใน README · ไม่ลบไฟล์หรือ repo เอง
