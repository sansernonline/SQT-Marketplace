# prompt-pdpa-line — ข้อมูลลูกค้าและช่องทางออนไลน์: PDPA LINE OA แจ้งลูกค้าช่วงวันหยุดยาว

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `thai-workplace` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานบริษัท** (1 บริษัท 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางไฟล์ที่ได้รับ (รายชื่อพนักงาน · statement · หนังสือจากหน่วยงาน) ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `thai-workplace` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมายหรือบัญชี · อัตราภาษี เพดานประกันสังคม ค่าแรงขั้นต่ำ กำหนดยื่น และค่าปรับ ตรวจกับกรมสรรพากร สำนักงานประกันสังคม และกรมพัฒนาธุรกิจการค้า (DBD) ในรอบนี้ ติดวันที่ · ข้อสัญญาที่มีความเสี่ยงทางกฎหมาย → ติดป้าย `(ให้ทนายตรวจ)` · การยื่นแบบ จ่ายเงิน ส่งเอกสารถึงลูกค้า broadcast ถึงผู้ติดตาม LINE และกด deploy webhook อยู่ใน "รออนุมัติ" · ใช้ token และ secret ของผู้ใช้จาก environment variable เท่านั้น ไม่เขียนลงไฟล์

**ภาษาและไฟล์:** เขียนตาม `human-writing` · เอกสารถึงลูกค้าหรือหน่วยงานส่งเป็น `.docx` (+ `.pdf` ถ้าขอ) · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. ตั้งหรือทำงาน PDPA

playbook `pdpa-setup` · agent `compliance-helper` · skill `pdpa-workflow`
**ผลลัพธ์:** `pdpa/` — ROPA (บันทึกรายการกิจกรรมการประมวลผล) · แบบขอความยินยอม · ขั้นตอนรับคำขอ · แผนรับมือข้อมูลรั่ว · **รออนุมัติ:** ติดประกาศ · แจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล · ลบข้อมูล · ส่งคำตอบถึงเจ้าของข้อมูล · แจ้งผู้ได้รับผลกระทบ

### ข้อมูล (ผู้ใช้กรอก)

- งานนี้คือ (เริ่มตั้งระบบ / ทำแบบขอความยินยอม / มีคำขอจากเจ้าของข้อมูล / ข้อมูลรั่ว / ตรวจผู้รับจ้างประมวลผล):
- ธุรกิจทำอะไร / เก็บข้อมูลใครบ้าง (ลูกค้า · พนักงาน · ผู้สมัครงาน · กล้องวงจรปิด):
- เก็บที่ไหน ส่งต่อให้ใคร:
- (คำขอ) ใครขอ ขออะไร วันที่ได้รับ:
- (ข้อมูลรั่ว) รู้เมื่อไร รั่วอะไร กี่คน:

### ต้องมีในผลงาน

1. เริ่มตั้ง: ROPA ตามกิจกรรม · ฐานทางกฎหมายต่อกิจกรรม · ประกาศความเป็นส่วนตัว
2. คำขอ: ขั้นตอนตอบภายใน 30 วัน · ร่างคำตอบ · วันครบกำหนด
3. ข้อมูลรั่ว: นับ 72 ชั่วโมงจากเวลาที่รู้ · ต้องแจ้งไหม · ร่างหนังสือแจ้ง
4. ทุกเรื่องที่ตีความได้หลายทาง → `(ให้ทนายตรวจ)`

## 2. LINE Official Account

playbook `line-oa` · agent `line-admin` · skill `line-oa-setup` · `line-chatbot` · `line-richmenu` · `line-broadcast`
**ผลลัพธ์:** `line-oa/` — คู่มือตั้งค่า · โค้ด webhook (ถ้าทำ bot) · `richmenu.json` · แผน broadcast · **รออนุมัติ:** deploy webhook · ตั้ง rich menu เป็นค่าเริ่มต้น · ส่ง broadcast

### ข้อมูล (ผู้ใช้กรอก)

- งานนี้คือ (สร้าง OA + เปิด Messaging API / chatbot / rich menu / broadcast):
- ชื่อ OA / แพ็กเกจที่ใช้ (โควตาข้อความต่อเดือน):
- token อยู่ใน environment variable ชื่ออะไร (ห้ามวาง token ในแชต):
- (chatbot) ลูกค้าถามอะไรบ่อย (วางแชตจริง 20–50 ข้อความ):
- (rich menu) ปุ่มที่ต้องการ / ภาพ (path):
- (broadcast) ส่งถึงใคร · ข้อความ · วันเวลา:

### ต้องมีในผลงาน

1. ตั้งค่า: OA Manager vs LINE Developers ทำอะไรที่ไหน · webhook ตรวจ signature · ทดสอบ echo ผ่าน
2. chatbot: แผนที่คำถาม → คำตอบจากคลังความรู้ · ส่งต่อคนเมื่อไม่มั่นใจ · ข้อความแจ้ง PDPA
3. rich menu: ขนาดภาพถูกต้อง · พื้นที่กด · JSON · คำสั่ง API ครบชุด
4. broadcast: คำนวณโควตาที่จะใช้ก่อนส่ง · กลุ่มเป้าหมาย · บันทึกการส่ง

## 3. แจ้งลูกค้าช่วงวันหยุดยาว ผ่าน LINE OA

playbook `line-oa` (ขั้น 3 chatbot ตอบกลับ · ขั้น 5 broadcast · ขั้น 6 ตรวจ) · agent `line-admin` · skill `line-broadcast` · `line-chatbot` · `thai-holidays`
**ผลลัพธ์:** `line-oa/holiday-<ปี-เดือน>.md` — ข้อความประกาศ · ข้อความตอบกลับอัตโนมัติช่วงปิด · แผนส่ง · **รออนุมัติ:** ส่ง broadcast · เปลี่ยนข้อความตอบกลับอัตโนมัติ · เปลี่ยนกลับเมื่อเปิดทำการ

### ข้อมูล (ผู้ใช้กรอก)

- ช่วงหยุด (เช่น สงกรานต์ · ปีใหม่) / วันปิด วันเปิด:
- อะไรหยุด อะไรยังทำ (ส่งของ · ตอบแชต · รับชำระเงิน):
- ชื่อ OA / แพ็กเกจที่ใช้ (โควตาข้อความต่อเดือน) / ผู้ติดตามกี่คน:
- ส่งถึงทุกคน หรือเฉพาะกลุ่ม:
- token อยู่ใน environment variable ชื่ออะไร (ห้ามวาง token ในแชต):

### ต้องมีในผลงาน

1. วันหยุดราชการและวันหยุดธนาคารจริงของช่วงนั้น ติดวันที่ตรวจ · วันขนส่งหยุด (ตรวจกับผู้ให้บริการขนส่งรอบนี้)
2. ข้อความประกาศ 1 ข้อความ: วันปิด · วันเปิด · สั่งก่อนวันไหนได้ของก่อนหยุด · ช่องทางเรื่องด่วน
3. ข้อความตอบกลับอัตโนมัติช่วงปิด และวันเวลาที่ต้องเปลี่ยนกลับ
4. โควตา: ข้อความที่จะใช้ = ผู้รับ × จำนวนข้อความ เทียบโควตาที่เหลือก่อนส่ง
5. บันทึกการส่ง: วันเวลา · กลุ่ม · จำนวน
