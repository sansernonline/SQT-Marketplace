# prompt-documents — เอกสารธุรกิจและการรับเงิน: ใบเสนอราคาถึงใบเสร็จ ทวงเงิน แก้ใบกำกับภาษี

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `thai-workplace` · ไฟล์นี้รวม prompt 5 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานบริษัท** (1 บริษัท 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางไฟล์ที่ได้รับ (รายชื่อพนักงาน · statement · หนังสือจากหน่วยงาน) ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `thai-workplace` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมายหรือบัญชี · อัตราภาษี เพดานประกันสังคม ค่าแรงขั้นต่ำ กำหนดยื่น และค่าปรับ ตรวจกับกรมสรรพากร สำนักงานประกันสังคม และกรมพัฒนาธุรกิจการค้า (DBD) ในรอบนี้ ติดวันที่ · ข้อสัญญาที่มีความเสี่ยงทางกฎหมาย → ติดป้าย `(ให้ทนายตรวจ)` · การยื่นแบบ จ่ายเงิน ส่งเอกสารถึงลูกค้า broadcast ถึงผู้ติดตาม LINE และกด deploy webhook อยู่ใน "รออนุมัติ" · ใช้ token และ secret ของผู้ใช้จาก environment variable เท่านั้น ไม่เขียนลงไฟล์

**ภาษาและไฟล์:** เขียนตาม `human-writing` · เอกสารถึงลูกค้าหรือหน่วยงานส่งเป็น `.docx` (+ `.pdf` ถ้าขอ) · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. เอกสารธุรกิจ

playbook `business-doc` · agent `thai-doc-writer` · skill `doc-quotation` · `e-tax-invoice` · `doc-thai-official` · `doc-contract-th` · `doc-leave` (เลือกตามประเภท)
**ผลลัพธ์:** `docs/<ประเภท>/<เลขที่>-<คู่ค้า>.docx` · **รออนุมัติ:** ส่งถึงลูกค้าหรือหน่วยงาน · ลงนาม

### ข้อมูล (ผู้ใช้กรอก)

- ประเภทเอกสาร (ใบเสนอราคา · ใบแจ้งหนี้ · ใบวางบิล · ใบเสร็จ · ใบกำกับภาษี · หนังสือราชการ / บันทึกภายใน · สัญญา · ใบลา):
- บริษัทเรา (ชื่อ · ที่อยู่ · เลขผู้เสียภาษี · จด VAT หรือไม่ · โลโก้ path):
- คู่ค้า / ผู้รับ (ชื่อ · ที่อยู่ · เลขผู้เสียภาษี · ตำแหน่งผู้รับ):
- รายการ ราคา จำนวน / เรื่องที่จะเขียน:
- หัก ณ ที่จ่ายไหม กี่ %:
- เงื่อนไข (ชำระเงิน · ส่งมอบ · ยืนราคา):
- เลขที่เอกสารล่าสุด:

### ต้องมีในผลงาน

1. เลือกเอกสารให้ถูกขั้น (เสนอราคา → แจ้งหนี้ → เสร็จ / กำกับภาษี) · ผิดขั้น → บอกก่อนทำ
2. ช่องที่กฎหมายบังคับครบ (ใบกำกับภาษีตามมาตรา 86/4)
3. ยอดเงิน VAT หัก ณ ที่จ่าย คำนวณซ้ำได้ · จำนวนเงินตัวอักษรไทยตรงกับตัวเลข
4. หนังสือทางการ: คำขึ้นต้น-ลงท้ายตามระดับผู้รับ ตามระเบียบงานสารบรรณ
5. สัญญา: ข้อบังคับครบ · อากรแสตมป์ · ข้อที่ต้อง `(ให้ทนายตรวจ)`

playbook `business-doc` · agent `thai-doc-writer` · skill `doc-quotation` (ใบแจ้งหนี้ / ใบวางบิลซ้ำ) · `doc-thai-official` (หนังสือทวงถาม)
**ผลลัพธ์:** `docs/collection/<คู่ค้า>-<ปี-เดือน>.md` (ตารางยอดค้างและแผนทวง) · ข้อความทวงขั้น 1–2 · หนังสือทวงถาม `.docx` · **รออนุมัติ:** ส่งข้อความหรือหนังสือถึงลูกค้า · ส่งหนังสือทางไปรษณีย์ลงทะเบียน · ส่งเรื่องให้ทนาย

- ทวงไปแล้วกี่ครั้ง ทางไหน ลูกค้าตอบว่าอะไร:
- ยังอยากค้าขายกับลูกค้ารายนี้ต่อไหม:
- สัญญาหรือใบเสนอราคาเขียนเรื่องดอกเบี้ยผิดนัดไว้ไหม (path):

### ต้องมีในผลงาน

1. ตารางยอดค้าง: เลขที่เอกสาร · ยอด · เลยกำหนดกี่วัน · หัก ณ ที่จ่ายที่ลูกค้าอาจหักไว้ · ยอดที่ควรได้จริง
2. แผนทวงเป็นขั้น: ขั้น 1 เตือนสุภาพ (แนบใบแจ้งหนี้ + PromptPay QR) → ขั้น 2 ขอวันจ่ายที่แน่นอน → ขั้น 3 หนังสือทวงถามทางการ · แต่ละขั้นมีวันที่ส่งและข้อความพร้อมใช้
3. หนังสือทวงถาม: คำขึ้นต้น-ลงท้ายตามระดับผู้รับ · อ้างเลขเอกสารและยอด · กำหนดวันชำระ
4. ดอกเบี้ยผิดนัดหรือค่าปรับ: คิดเฉพาะที่สัญญาเขียนไว้ · อัตราตามกฎหมายตรวจกับแหล่งทางการรอบนี้ ติดวันที่ตรวจ · ทุกข้อที่เกี่ยวกับการฟ้องหรืออายุความ → `(ให้ทนายตรวจ)`

### กฎเฉพาะฉบับนี้

- ข้อความทวงไม่ข่มขู่ ไม่ประจาน ไม่ส่งถึงคนอื่นนอกจากผู้ติดต่อของลูกค้า

## 4. แก้ใบกำกับภาษีด้วยใบลดหนี้ / ใบเพิ่มหนี้

playbook `business-doc` · agent `thai-doc-writer` + `tax-helper` · skill `e-tax-invoice` · `doc-quotation` · `tax-vat-th`
**ผลลัพธ์:** `docs/credit-note/<เลขที่>-<คู่ค้า>.docx` (หรือ `debit-note/`) · บันทึกผลต่อแบบภาษีมูลค่าเพิ่ม (ภ.พ.30) ของเดือนที่ออก · **รออนุมัติ:** ส่งเอกสารถึงลูกค้า · ยกเลิกใบเดิมในระบบใบกำกับภาษีอิเล็กทรอนิกส์ (e-Tax Invoice)

### ข้อมูล (ผู้ใช้กรอก)

- ใบกำกับภาษีเดิม (เลขที่ · วันที่ · ยอด) (path):
- เกิดอะไรขึ้น (ออกผิดช่อง · ลูกค้าคืนของ · ลดราคาหลังขาย · คิดราคาขาด):
- ใบเดิมส่งถึงลูกค้าแล้วหรือยัง / ลูกค้าใช้เครดิตภาษีซื้อไปแล้วไหม:
- ออกใบกำกับเป็นกระดาษ หรือ e-Tax Invoice:
- เลขที่ใบลดหนี้ / ใบเพิ่มหนี้ล่าสุด:

### ต้องมีในผลงาน

1. เลือกทางที่ถูก: ยกเลิกแล้วออกใหม่ · ใบลดหนี้ · ใบเพิ่มหนี้ — พร้อมเหตุผล 1 บรรทัด · ไม่แก้ใบที่ออกไปแล้ว
2. ช่องบังคับของใบลดหนี้ / ใบเพิ่มหนี้ครบ · อ้างเลขใบกำกับเดิม · เหตุที่ออก
3. ยอดผลต่าง ภาษีผลต่าง คำนวณซ้ำได้
4. ลงในเดือนภาษีไหน และกระทบ ภ.พ.30 อย่างไร (ตรวจกับกรมสรรพากรรอบนี้ ติดวันที่ตรวจ)
5. ขั้นจัดการต้นฉบับเดิม (ประทับยกเลิก · เก็บทุกสำเนา) หรือขั้นในระบบ e-Tax
