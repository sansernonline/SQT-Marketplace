# prompt-open-shop — เปิดร้าน ลงสินค้า แก้หน้าสินค้า

ใช้คู่กับ plugin `online-seller` · ไฟล์นี้รวม prompt 5 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ร้าน** (1 ร้าน 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปสินค้า แชตลูกค้า รายงานยอดขาย ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `online-seller` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · ตารางสถานะตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่าง → ถามรวมครั้งเดียวก่อนเริ่ม ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → หยุดและบอกผู้ใช้

**ขอบเขต:** ค่าธรรมเนียมแพลตฟอร์ม ค่าส่ง และนโยบายคืนสินค้า เปลี่ยนบ่อย → ตรวจกับ Seller Centre หรือหน้าทางการรอบนี้ ติดวันที่ · คำโฆษณาต้องผ่านกฎ อย. (สำนักงานคณะกรรมการอาหารและยา) และ สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) · ไม่แต่งรีวิว · การลงขายจริง ส่งข้อความถึงลูกค้า คืนเงิน เปลี่ยนราคาบนร้าน อยู่ใน "รออนุมัติ" · เรื่องภาษีเป็นข้อมูลทั่วไป ยืนยันกับนักบัญชี

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. เทียบขนส่ง

skill `shipping-compare` · agent `shop-manager` · งานกลาง ไม่ต้องเปิด playbook
**ผลลัพธ์:** `shipping/<ปี-เดือน>-compare.md`

### ข้อมูล (ผู้ใช้กรอก)

- ขนส่งที่ใช้อยู่ / ที่กำลังดู (Flash · Kerry · J&T · ไปรษณีย์ไทย · SPX):
- พัสดุต่อเดือน แยกตามขนาดหรือน้ำหนัก (หรือไฟล์ออเดอร์ 1 เดือน):
- เก็บเงินปลายทาง (COD) กี่ %:
- ส่งผ่านระบบแพลตฟอร์ม หรือส่งเอง:

### ต้องมีในผลงาน

1. ค่าส่งรวมต่อเดือนของแต่ละเจ้า จากพัสดุจริงของร้าน (คิดน้ำหนักตามปริมาตร)
2. ค่าธรรมเนียม COD และรอบโอนเงิน
3. เรตที่ใช้ ตรวจจากหน้าทางการ ติดวันที่
4. ข้อสรุปใช้เจ้าไหนกับพัสดุแบบไหน

## 2. ลงสินค้าใหม่ครบชุด

playbook `new-product` · agent `shop-manager` · skill `product-listing` · `marketplace-fees-pricing` · `multi-shop-stock` · `shipping-compare`
**ผลลัพธ์:** `products/<SKU>/listing-<แพลตฟอร์ม>.md` · ตารางราคา · แถวใหม่ใน `stock.csv` · **รออนุมัติ:** กดลงขายจริง

### ข้อมูล (ผู้ใช้กรอก)

- สินค้า / จุดเด่น / วัสดุ / ขนาด:
- ต้นทุนต่อชิ้น / จำนวนที่มี:
- แพลตฟอร์ม (Shopee · Lazada · TikTok Shop · LINE · Facebook) และประเภทร้าน (ทั่วไป / Mall):
- หมวดสินค้า:
- น้ำหนักและขนาดกล่องพัสดุ:
- กำไรที่ต้องการ (% หรือบาท):
- ร้านจด VAT แล้วหรือยัง:
- รูปสินค้า (path):

### ต้องมีในผลงาน

1. ค่าส่งจริงรวมน้ำหนักตามปริมาตร
2. ตารางราคาต่อแพลตฟอร์ม: ต้นทุน · ค่าคอม · ค่าธุรกรรม · ค่าส่ง · VAT (ภาษีมูลค่าเพิ่ม) · กำไร คำนวณซ้ำได้
3. ชื่อสินค้า คำค้น คำบรรยาย ต่อแพลตฟอร์ม ตามสูตรของแต่ละที่
4. ผลตรวจคำโฆษณาต้องห้าม · เช็กลิสต์รูปและขนาดรูป (`social-formats` ของ graphic-design ถ้ามี)
5. SKU (Stock Keeping Unit — รหัสสินค้า) ตามกฎตั้งชื่อ และจุดสั่งซื้อซ้ำ

## 3. สินค้ามีคนเข้าดูแต่ไม่มีคนซื้อ

playbook `new-product` (ขั้น 3–5: ราคา · listing · คำต้องห้าม) · agent `shop-manager` · skill `product-listing` · `marketplace-fees-pricing`
**ผลลัพธ์:** `products/<SKU>/fix-<ปี-เดือน>.md` (สาเหตุ · listing ฉบับแก้แบบ "เดิม → ใหม่" · วันวัดผล) · **รออนุมัติ:** แก้หน้าสินค้าบนร้านจริง · เปลี่ยนราคา

### ข้อมูล (ผู้ใช้กรอก)

- สินค้า / แพลตฟอร์ม / ลิงก์หน้าสินค้า:
- listing ปัจจุบัน (วางข้อความ หรือ path):
- ยอดเข้าชมและยอดสั่งซื้อช่วงเดียวกัน (จาก Seller Centre):
- ราคาปัจจุบัน / ต้นทุน:
- ร้านคู่แข่ง 2–3 ร้านที่ขายดีกว่า (ลิงก์ หรือภาพหน้าจอใน `inbox/`):
- คำถามที่ลูกค้าถามซ้ำในแชต:

### ต้องมีในผลงาน

1. ติดตรงไหน อ้างตัวเลขจริง: คนหาไม่เจอ (เข้าชมน้อย) หรือเข้ามาแล้วไม่ซื้อ (รูปแรก · ราคา · ค่าส่ง · รีวิว · คำบรรยาย)
2. ตารางเทียบคู่แข่ง: ชื่อสินค้า · รูปแรก · ราคารวมค่าส่ง · จำนวนรีวิว · จุดที่เขาดีกว่า
3. ชื่อ คำค้น คำบรรยายใหม่ตามสูตรของ `product-listing` เขียนแบบ "เดิม → ใหม่"
4. คำถามที่ลูกค้าถามซ้ำ → ใส่คำตอบไว้ในคำบรรยาย
5. ถ้าราคาสูงกว่าคู่แข่ง: ตารางราคาต่ำสุดที่ยังได้กำไรตาม `marketplace-fees-pricing`
6. ผลตรวจคำโฆษณาต้องห้ามของ listing ใหม่
7. วันวัดผลและตัวเลขที่จะดู (เข้าชม · สั่งซื้อ · อัตราซื้อต่อคนเข้า)

### กฎเฉพาะฉบับนี้

- แก้ทีละ 1–2 อย่างต่อรอบ จะได้รู้ว่าอะไรได้ผล · บอกลำดับที่ควรแก้ก่อน
- ไม่มียอดเข้าชมจริง → บอกว่าวินิจฉัยจากหน้าสินค้าอย่างเดียว ห้ามเดาตัวเลข

## 4. สินค้าถูกระงับ / โดนเตือนเรื่องคำโฆษณา

playbook `new-product` (ขั้น 4–5: listing · คำต้องห้าม) · agent `shop-manager` · skill `product-listing`
**ผลลัพธ์:** `products/<SKU>/appeal-<ปี-เดือน-วัน>.md` (สาเหตุ · listing ฉบับแก้ · ร่างอุทธรณ์) · **รออนุมัติ:** แก้หน้าสินค้าบนร้านจริง · ส่งอุทธรณ์ · ลบสินค้า

### ข้อมูล (ผู้ใช้กรอก)

- แพลตฟอร์ม / ข้อความแจ้งเตือนจากแพลตฟอร์ม (วาง หรือภาพหน้าจอใน `inbox/`):
- สินค้าที่โดน / listing ปัจจุบัน (path):
- สินค้ามีเลขทะเบียน อย. หรือเอกสารรับรองไหม (path):
- กำหนดเวลาแก้หรืออุทธรณ์ที่แพลตฟอร์มให้:

### ต้องมีในผลงาน

1. สาเหตุตามที่แพลตฟอร์มระบุ ชี้คำ รูป หรือวิดีโอที่ผิดได้ตรงจุด
2. ตรวจทั้งหน้า (ชื่อ · คำบรรยาย · รูป · วิดีโอ) หาจุดผิดที่ยังไม่โดนเตือน
3. listing ฉบับแก้แบบ "เดิม → ใหม่"
4. ร่างข้อความอุทธรณ์พร้อมรายการหลักฐานที่แนบ (เฉพาะกรณีที่เห็นว่าโดนเตือนผิด)
5. สินค้าอื่นในร้านที่ใช้คำเดียวกัน (ค้นแล้วเจอกี่ชิ้น ชิ้นไหน)
6. กำหนดเวลาที่เหลือ เรียงงานตามวันครบกำหนด

### กฎเฉพาะฉบับนี้

- นโยบายและบทลงโทษของแพลตฟอร์มตรวจกับ Seller Centre รอบนี้ ติดวันที่
- สินค้าต้องขออนุญาต อย. หรือไม่ ตอบจากความรู้ทั่วไปไม่ได้ → ใส่ `(รอยืนยัน)` และบอกให้ตรวจกับ อย.
- ไม่แนะนำให้เลี่ยงคำต้องห้ามด้วยการสะกดแปลกหรือใส่ในรูป
