# prompt-ea-research-loop — วิจัยกลยุทธ์ Expert Advisor (EA) แบบวนลองผิดลองถูก บน MetaTrader 4/5

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `software-development` · ไฟล์นี้มี prompt 6 ฉบับ ทำเรียงกัน 1 → 6 · ใช้เมื่อ **ยังไม่มีกลยุทธ์ที่ชัด** แต่รู้ว่าอยากได้แนวไหน แล้วให้ agent ไป research · สร้าง EA หลายรุ่น · backtest · ให้คะแนน · เรียนรู้จากผล แล้วลองรอบถัดไป วนแบบ Reinforcement Learning (RL) จนได้ตัวที่ดีที่สุด · ผู้ใช้ไกด์ทิศทางได้ตลอดทาง · มีกลยุทธ์ชัดแล้ว → `prompt-trading-system.md` เลย

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่รากโฟลเดอร์โปรเจกต์ **บนเครื่อง Windows ที่ติดตั้ง MetaTrader 4 (MT4) หรือ MetaTrader 5 (MT5)** (หรือ Wine) · ไม่มี terminal → วนไม่ได้ ทำได้แค่ฉบับ 1–3
2. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำทั้งหมด` หรือ `ทำข้อ 4 ต่อ 20 รอบ`
3. ระหว่างที่ agent วน แก้ไฟล์ `docs/ea/research/GUIDE.md` ได้ทุกเมื่อ · agent อ่านไฟล์นี้ใหม่ทุกต้นรอบ ไม่ต้องหยุด agent

## กฎเฉพาะไฟล์นี้

- **ศัพท์ RL ในไฟล์นี้:** state = สิ่งที่รู้ตอนนี้ (`LEARNINGS.md` + ผลทุกรอบ) · action = สิ่งที่ลองในรอบนั้น (แนวคิดใหม่ หรือปรับกฎ / ค่า input ของตัวเดิม) · reward = คะแนนตาม `REWARD.md` · policy = วิธีเลือก action รอบถัดไป · champion = รุ่นที่คะแนนสูงสุดตอนนี้ · นี่คือการค้นหาแบบ RL ไม่ใช่การเทรน neural network
- **ช่วงข้อมูล 3 ส่วน ล็อกในฉบับ 1 ก่อนรันรอบแรก:** train (ใช้หา input) · validation (ให้คะแนนในลูป) · holdout (ห้ามรันจนถึงฉบับ 6 และเปิดได้ครั้งเดียว) · รัน holdout ก่อนฉบับ 6 = ทิ้งผลทั้งหมดของรอบนั้น และจดลง `LEARNINGS.md` ว่าข้อมูลรั่ว
- **ทุกรอบลงบันทึก แม้ล้ม:** compile ไม่ผ่าน · ไม่มีไม้ · คะแนนแย่ ก็ลง `experiments.csv` · ห้ามลบแถว · จำนวนรอบทั้งหมดใช้คิดค่าเผื่อการลองหลายครั้ง (multiple testing) ในฉบับ 6
- **ค่าของโบรกเกอร์** (spread · commission · swap · digits · stops level · contract size · เวลา server) อ่านจาก symbol จริง ติดวันที่ · ไม่รู้ → `(รอยืนยัน)` ห้ามใส่ 0
- **`GUIDE.md` ของผู้ใช้ชนะทุกอย่าง** ยกเว้นขอบเขตข้างบน · ไกด์ขัดกับ `REWARD.md` → ทำตามไกด์ แล้วบอกในจุดตรวจถัดไปว่าขัดตรงไหน
- agent ที่ใช้: `quant-analyst` (นำ · สูตร สถิติ ตัดสิน) · `developer` (โค้ด EA และเครื่องมือ) · `brainstormer` (แนวคิดใหม่ตอนติด) · `reviewer` ตัวใหม่ตรวจทุกจุดตรวจ

## 1. ตั้งโจทย์ · แนวที่อยากได้ · สูตรให้คะแนน · ล็อกข้อมูล

playbook `project-docs` · agent `quant-analyst` + `business-analyst` · skill `stack-mql` · `human-writing/spell-out-abbreviations`
**ผลลัพธ์:** `docs/ea/research/GUIDE.md` (ผู้ใช้แก้ต่อได้) · `docs/ea/research/REWARD.md`

### โจทย์ (ผู้ใช้กรอก)

- แนวที่อยากได้ (trend following · mean reversion · breakout · scalping · ตาม session · price action · อื่น ๆ · หลายแนวได้ เรียงตามที่ชอบ):
- แนวที่ไม่เอาเด็ดขาด (เช่น martingale · grid ไม่มี Stop Loss (SL) · hedge ล็อกไม้ · เทรดข่าว):
- MT4 · MT5 · ทั้ง 2:
- symbol และ timeframe (ระบุได้ หรือให้ agent เลือกจากรายการ):
- ถือไม้นานแค่ไหน (นาที · ชั่วโมง · วัน) / เทรดกี่ไม้ต่อสัปดาห์โดยประมาณ:
- ความเสี่ยงต่อไม้ / max drawdown ที่รับได้ / ขาดทุนสูงสุดต่อวัน:
- สิ่งที่สำคัญกว่ากำไร (drawdown ต่ำ · กราฟ equity เรียบ · ไม้น้อยแต่แม่น · อื่น ๆ):
- ช่วงข้อมูลที่มี และแหล่ง tick:
- งบการวน: จำนวนรอบสูงสุด (ค่าแนะนำ 50) / เวลาสูงสุด (ชั่วโมง) / ให้หยุดรายงานทุกกี่รอบ (ค่าแนะนำ 10):
- ไอเดียหรือ EA เดิมที่อยากให้ลองก่อน (path ใน `ref/`):

### หัวข้อที่ต้องมี

1. **`GUIDE.md`** — เขียนจากโจทย์ข้างบนเป็นข้อสั้น ๆ ที่ผู้ใช้แก้เองได้ แบ่ง 4 หัวข้อคงที่: `## อยากได้` · `## ห้าม` · `## ขุดต่อ` (แนวคิดที่ให้ลองเพิ่ม) · `## เลิก` (แนวคิดที่ให้ทิ้ง) · บรรทัดแรกบอกว่า "แก้ไฟล์นี้ได้ทุกเมื่อ agent อ่านใหม่ทุกต้นรอบ"
2. **ประตูผ่าน (gate)** — เงื่อนไขที่ไม่ผ่านแล้ว reward = 0 ทันที: จำนวนไม้ในช่วง validation น้อยกว่าเกณฑ์ (ค่าแนะนำ 100) · max drawdown เกินที่รับได้ · ใช้วิธีในหัวข้อ `## ห้าม` · compile ไม่ผ่าน
3. **สูตร reward** — ผ่าน gate แล้วคิดคะแนน 0–100 จากตัวชี้วัดที่ผู้ใช้ให้น้ำหนัก เช่น recovery factor (กำไรสุทธิ ÷ max drawdown) · profit factor · Sharpe ratio · ความสม่ำเสมอ (คะแนนของ walk-forward ช่วงที่แย่ที่สุด ไม่ใช่ค่าเฉลี่ย) · หักคะแนนตามจำนวน input ที่ปรับ · หักคะแนนเมื่อขยับ input หลัก ±10% แล้วผลพัง · เขียนสูตรเป็นตัวเลขที่คำนวณซ้ำได้ ตัวอย่างคำนวณ 1 ชุด
4. **ล็อกข้อมูล** — วันที่เริ่ม-จบของ train · validation (แบ่ง walk-forward อย่างน้อย 4 ช่วง) · holdout (ค่าแนะนำ 20–30% ท้ายสุดของข้อมูล) · ต้นทุนการเทรดที่ใช้ทุกรอบ (spread · commission · slippage)
5. **งบและเงื่อนไขหยุด** — ครบจำนวนรอบ · ครบเวลา · ไม่มี champion ใหม่ติดกัน N รอบ (ค่าแนะนำ 15) · ผู้ใช้เขียน `หยุด` ใน `GUIDE.md`

### กฎเฉพาะฉบับนี้

- น้ำหนักและเกณฑ์ทุกตัวผู้ใช้ยืนยัน · ไม่รู้ → ค่าแนะนำพร้อมเหตุผลและ `(รอยืนยัน)` · `REWARD.md` แก้ได้ แต่ทุกครั้งต้องลงเหตุผลและรอบที่แก้ แล้ว **คิดคะแนนใหม่ให้ทุกแถวเดิม** ด้วยสูตรใหม่ เพื่อเทียบกันได้

## 2. Research หาแนวคิดกลยุทธ์

playbook `project-docs` · agent `quant-analyst` + `brainstormer` · skill `reference-app-research` · `stack-mql`
**ต้องมีก่อน:** `GUIDE.md`
**ผลลัพธ์:** `docs/ea/research/IDEAS.md`

### หัวข้อที่ต้องมี

1. **แหล่งที่ค้น** — อย่างน้อย 4 ประเภท: บทความ MQL5 (mql5.com/articles) · งานวิจัย (SSRN · arXiv q-fin) · หนังสือหรือแหล่งที่อ้างกันมากในแนวนั้น · Code Base / forum (ใช้เป็นไอเดีย ไม่เชื่อตัวเลขผลลัพธ์) · ทุกแหล่งมีลิงก์และวันที่ค้น
2. **บัตรแนวคิด (idea card)** อย่างน้อย 10 ใบ ตรงกับ `## อยากได้` และไม่ชน `## ห้าม` · ใบละ: รหัส `I-xx` · ตระกูล (trend · reversion · breakout ฯลฯ) · เหตุผลว่าทำไมอาจได้ผล (ใครเสียเงินให้เรา) · กฎเข้า-ออกที่เขียนเป็นโค้ดได้ · input ที่ต้องปรับ (ไม่เกิน 4 ตัว) · แหล่งอ้างอิง · ความเสี่ยงที่เห็นล่วงหน้า
3. **ลำดับเริ่มต้น** — ตาราง `| I-xx | ตระกูล | ตรงไกด์ (1–5) | หลักฐานจากแหล่ง (1–5) | ทำง่าย (1–5) | คะแนนเริ่มต้น |` · ค่านี้เป็นค่าตั้งต้นของ policy ในฉบับ 4

### กฎเฉพาะฉบับนี้

- แนวคิดที่แหล่งอ้างผลกำไรโดยไม่มีวิธีทดสอบ → ใส่ได้ แต่หลักฐาน = 1
- กฎที่เขียนเป็นเงื่อนไขตรวจได้ไม่ได้ ("ดูแนวโน้มใหญ่") → แปลงเป็นเงื่อนไขก่อน ไม่ได้ → ตัดทิ้งและจดเหตุผล

3. **อ่านผล** — แปลงรายงาน tester (XML / HTML) เป็น `metrics.json` ต่อช่วง walk-forward
4. **ให้คะแนน** — `tools/lab/score` คิด gate และ reward ตาม `REWARD.md` · ต่อแถวลง `experiments.csv` อัตโนมัติ
5. **รอบทดสอบเครื่องมือ** — รันแม่แบบกับสัญญาณสุ่ม (เข้าไม้มั่ว) 1 รอบ · reward ต้องต่ำหรือ 0 · ได้คะแนนดี = เครื่องมือผิด ต้องแก้ก่อนไปฉบับ 4

### กฎเฉพาะฉบับนี้

- `experiments.csv` คอลัมน์คงที่: `round,time,idea,variant,parent,action_type,change,inputs,trades,net,max_dd,pf,sharpe,wf_worst,gate,reward,champion,note`
- 1 รอบ tester ค้างเกินเวลาที่ตั้ง → ฆ่า process · ลงแถวว่า `timeout` · ไปรอบถัดไป

## 4. วนทดลอง (agent loop แบบ RL)

playbook `feature` · agent `quant-analyst` (นำ) + `developer` · `brainstormer` เมื่อติด · skill `stack-mql` · `ground-rules/principle-small-verifiable-steps`
**ต้องมีก่อน:** ฉบับ 1–3 ครบ และรอบทดสอบเครื่องมือผ่าน
**ผลลัพธ์:** `experiments.csv` (เพิ่มแถวทุกรอบ) · `LEARNINGS.md` · `CHAMPION.md` · โค้ดแต่ละรุ่นบน branch `lab/<I-xx>-v<n>` หรือ commit แยก

### ลำดับใน 1 รอบ

1. **อ่าน state** — `GUIDE.md` (ใหม่ทุกรอบ) · `LEARNINGS.md` · 20 แถวล่าสุดของ `experiments.csv` · `CHAMPION.md` · เจอ `หยุด` ใน `GUIDE.md` → ไปฉบับ 5 แล้วจบ
2. **เลือก action (policy)** — คิดคะแนนเลือกของแต่ละตระกูลแนวคิด = reward เฉลี่ยของตระกูล + โบนัสสำรวจ (ตระกูลที่ลองน้อยได้โบนัสมาก · แบบ Upper Confidence Bound (UCB)) · แล้วเลือก 1 ใน 3 แบบ:
   - **ขุดต่อ (exploit) ~60%** — ปรับ champion หรือรุ่นท็อป 3 ทีละ 1 อย่าง: เพิ่มหรือตัดตัวกรอง 1 ตัว · เปลี่ยนวิธีออก · ขยับ input
   - **สำรวจ (explore) ~30%** — แนวคิดใหม่จาก `IDEAS.md` ที่ยังไม่ลอง หรือที่ผู้ใช้ใส่ใน `## ขุดต่อ`
   - **ผสม ~10%** — เอาส่วนที่ได้ผลจาก 2 รุ่นท็อปมารวมกัน
   - ไม่มี champion ใหม่ 5 รอบติด → เพิ่มสัดส่วนสำรวจ · 10 รอบติด → เรียก `brainstormer` หาแนวคิดใหม่ 3 ใบลง `IDEAS.md`
3. **เขียนสมมติฐาน 1 บรรทัดก่อนลงมือ** — "เปลี่ยน X เพราะ Y คาดว่า Z ดีขึ้น" ลงคอลัมน์ `change`
4. **สร้าง** — แก้ไฟล์สัญญาณ หรือ `.set` · compile
5. **ทดสอบ** — `tools/lab/run` บน train → หา input ด้วย optimizer ในกรอบที่ `REWARD.md` อนุญาต → รันค่าที่ได้บน validation ทุกช่วง walk-forward
6. **ให้คะแนน** — `tools/lab/score` · reward สูงกว่า champion อย่างมีนัย (ค่าแนะนำ +5 คะแนน และ walk-forward ช่วงแย่สุดไม่ต่ำลง) → เป็น champion ใหม่ อัปเดต `CHAMPION.md`
7. **เรียนรู้** — เขียน 1–3 บรรทัดลง `LEARNINGS.md` ว่ารอบนี้สอนอะไร (เช่น "ตัวกรอง ADX ช่วย breakout บน H1 แต่ทำ M15 แย่") · บทเรียนที่ซ้ำ 3 รอบขึ้นไป → ยกเป็น `## กฎที่ยืนยันแล้ว` ด้านบนไฟล์ · policy รอบถัดไปต้องอ่านกฎเหล่านี้
8. **ครบรอบจุดตรวจ** (ทุก N รอบตาม `GUIDE.md` หรือได้ champion ใหม่) → ฉบับ 5 · ไม่ครบ → กลับข้อ 1

### กฎเฉพาะฉบับนี้

- 1 รอบเปลี่ยน 1 อย่าง (ยกเว้นแบบผสม) เพื่อให้รู้ว่าอะไรทำให้ดีขึ้น
- ห้ามแก้ `REWARD.md` เพื่อให้รุ่นที่ชอบได้คะแนนสูงขึ้น · ห้ามขยับช่วงวันที่ · ห้ามลบรอบที่แย่
- optimizer 1 ครั้งที่ลองหลายชุด input นับจำนวนชุดทั้งหมดลง `note` (ใช้คิดค่าเผื่อในฉบับ 6)
- `CHAMPION.md` มีเสมอ: รหัสรุ่น · กฎเข้า-ออกแบบคนอ่าน · input และค่า · reward และตัวชี้วัดทุกช่วง · รอบที่ได้ · path โค้ดและ `.set`

## 5. รายงานจุดตรวจ และรับไกด์จากผู้ใช้

playbook `review` · agent `quant-analyst` + `reviewer` (ตัวใหม่) · skill `markdown-visuals` · `human-writing`
**ผลลัพธ์:** `docs/ea/research/checkpoints/<วันที่>-r<รอบ>.md`

### หัวข้อที่ต้องมี

1. **สรุป 3 บรรทัด** — champion ตอนนี้คือรุ่นไหน · คะแนนเท่าไร ดีขึ้นจากจุดตรวจก่อนเท่าไร · ใช้ไปกี่รอบจากงบ
2. **กราฟ reward ต่อรอบ** และเส้น champion · ตาราง 5 รุ่นท็อป · reward เฉลี่ยแยกตามตระกูลแนวคิด
3. **บทเรียนใหม่** จาก `LEARNINGS.md` ตั้งแต่จุดตรวจก่อน
4. **สัญญาณเตือน** — คะแนนดีขึ้นเฉพาะ train แต่ validation ไม่ขึ้น · input ดีเฉพาะช่วงแคบ · ไม้น้อยใกล้ gate · ผลขึ้นกับไม้ใหญ่ไม่กี่ไม้
5. **ข้อเสนอรอบถัดไป** — 2–3 ทิศ พร้อมเหตุผล · ถามผู้ใช้แบบเลือกคำตอบ: `วนต่อตามเดิม` · `เน้นทิศ A` · `เน้นทิศ B` · `เปลี่ยนน้ำหนัก reward` · `หยุดและไปฉบับ 6`

### กฎเฉพาะฉบับนี้

- `reviewer` ตรวจจาก `experiments.csv` และไฟล์รายงาน tester จริง ไม่ใช่จากสรุปของ agent ที่วน
- ผู้ใช้ตอบ → แปลงคำตอบเป็นบรรทัดใน `GUIDE.md` (หัวข้อที่ตรง) ให้ผู้ใช้เห็นว่าไกด์ถูกบันทึกอย่างไร แล้วกลับฉบับ 4
- ผู้ใช้ไม่อยู่ (ไม่ตอบ หรือรันแบบไม่มีคนเฝ้า) → เลือก `วนต่อตามเดิม` ลง `## ตัดสินใจเอง` แล้ววนต่อจนครบงบ · การเปลี่ยนน้ำหนัก reward ต้องรอผู้ใช้เสมอ

## 6. ตัดสินผู้ชนะ: เปิดช่วงข้อมูลที่ล็อกไว้ ครั้งเดียว

playbook `review` · agent `quant-analyst` (นำ) + `reviewer` · skill `stack-mql` · `ground-rules/principle-prove-it-works` · `markdown-visuals` · `design-gate/polished-document-style`
**ต้องมีก่อน:** วนครบงบหรือผู้ใช้สั่งหยุด · `CHAMPION.md`
**ผลลัพธ์:** `docs/ea/research/FINAL.md`

### หัวข้อที่ต้องมี

1. **ผู้เข้ารอบ** — champion + รองอีกไม่เกิน 2 รุ่น เลือกก่อนรัน holdout และห้ามเปลี่ยนหลังเห็นผล
2. **ผล holdout** — รันครั้งเดียวด้วย input ที่ล็อกไว้ · ตาราง `| ตัวชี้วัด | train | validation | holdout |` · กราฟ equity
3. **ค่าเผื่อการลองหลายครั้ง** — นับจำนวนชุดที่ลองทั้งหมดจาก `experiments.csv` · คิด Deflated Sharpe Ratio (DSR) หรือวิธีเทียบเท่า · บอกว่าผลที่ได้ "อาจเป็นโชค" มากน้อยแค่ไหน
4. **ความทนทาน** — ขยับ input ±10–20% · Monte Carlo สลับลำดับไม้และสุ่ม spread / slippage อย่างน้อย 1,000 รอบ → drawdown ที่ percentile 95 · symbol หรือ timeframe อื่นอย่างน้อย 1 ชุด
5. **คำตัดสิน** — `ผ่าน` · `ผ่านแบบมีเงื่อนไข` · `ไม่ผ่าน` · `ยังไม่พอบอก` พร้อมเหตุผลข้อละ 1 บรรทัด
6. **ส่งต่อ** — ผ่าน → สิ่งที่ต้องใส่ใน `prompt-trading-system.md` ฉบับ 1 (กฎ `R-xx` · ตาราง input · เกณฑ์) · ไม่ผ่าน → บทเรียนหลักจาก `LEARNINGS.md` และทิศที่แนะนำถ้าจะวนรอบใหม่ (ต้องใช้ holdout ช่วงใหม่ที่ยังไม่เคยเห็น)

### กฎเฉพาะฉบับนี้

- holdout แย่ → รายงานว่าแย่ · ห้ามกลับไปปรับแล้วรัน holdout ซ้ำ · ห้ามเลือกรุ่นที่ holdout ดีที่สุดมาเป็นผู้ชนะแทน champion ถ้าไม่ได้ระบุไว้ในหัวข้อ 1
