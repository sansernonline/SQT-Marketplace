# prompt-customers — ลูกค้าและหลังการขาย

ใช้คู่กับ plugin `e-commerce` · ไฟล์นี้รวม prompt 2 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ร้าน** (1 ร้าน 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปสินค้า แชตลูกค้า รายงานยอดขาย ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `e-commerce` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ค่าธรรมเนียมแพลตฟอร์ม ค่าส่ง และนโยบายคืนสินค้า เปลี่ยนบ่อย → ตรวจกับ Seller Centre หรือหน้าทางการรอบนี้ ติดวันที่ · คำโฆษณาต้องผ่านกฎ อย. (สำนักงานคณะกรรมการอาหารและยา) และ สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) · ไม่แต่งรีวิว · การลงขายจริง ส่งข้อความถึงลูกค้า คืนเงิน เปลี่ยนราคาบนร้าน อยู่ใน "รออนุมัติ" · เรื่องภาษีเป็นข้อมูลทั่วไป ยืนยันกับนักบัญชี

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

|---|---|---|---|

ใช้ต่อกัน: ลูกค้าถามเรื่องเดิมซ้ำ → 1 → `prompt-open-shop.md` ฉบับ 3 (แก้คำบรรยาย) · ของเสียหายระหว่างส่งบ่อย → 2 → `prompt-open-shop.md` ฉบับ 1 (เทียบขนส่ง) · ตรวจร่างตอบก่อนส่ง → `prompt-open-shop.md` ฉบับ 5

## 1. ลูกค้าถาม บ่น ขอคืน รีวิวแย่

playbook `customer-issue` · agent `customer-chat` · skill `chat-reply-templates` · `returns-and-bad-reviews`
**ผลลัพธ์:** ร่างข้อความตอบในแชต · เรื่องยาว → `issues/<เลขออเดอร์>.md` · **รออนุมัติ:** ส่งข้อความ · คืนเงิน · ส่งของใหม่

### ข้อมูล (ผู้ใช้กรอก)

- แพลตฟอร์ม:
- ลูกค้าเขียนว่าอะไร (วางข้อความหรือรูปแชต):
- สถานะออเดอร์ / เลขพัสดุ:
- รูปจากลูกค้า (path):
- น้ำเสียงร้าน (ทางการ / เป็นกันเอง):

### ต้องมีในผลงาน

1. ร่างตอบพร้อมส่ง 1–2 แบบ ในน้ำเสียงร้าน
2. ถ้าขอคืน: คืนเงิน / ส่งใหม่ / โต้แย้ง — เลือกทางไหนตามนโยบายแพลตฟอร์มและหลักฐาน · กำหนดเวลาที่เหลือ
3. ถ้ารีวิวแย่: คำตอบสาธารณะ (สั้น สุภาพ ไม่โต้เถียง) + ข้อความส่วนตัว
4. ถ้าปัญหาซ้ำบ่อย: เสนอแก้ที่ต้นเหตุ 1 ข้อ (คำบรรยาย · แพ็กของ · ขนส่ง)

## 2. พัสดุหาย เสียหาย ลูกค้าเปิดข้อพิพาท

playbook `customer-issue` · agent `customer-chat` (ข้อความถึงลูกค้า) + `shop-manager` (เคลมขนส่ง) · skill `returns-and-bad-reviews` · `shipping-compare` · `chat-reply-templates`
**ผลลัพธ์:** `issues/<เลขออเดอร์>.md` (ลำดับเหตุการณ์ · หลักฐาน · ทางที่เลือก · ร่างข้อความ) · **รออนุมัติ:** ส่งข้อความถึงลูกค้า · ยื่นโต้แย้งกับแพลตฟอร์ม · ยื่นเคลมกับขนส่ง · คืนเงิน · ส่งของใหม่

### ข้อมูล (ผู้ใช้กรอก)

- แพลตฟอร์ม / เลขออเดอร์ / เลขพัสดุ / ขนส่ง:
- เกิดอะไร (ไม่ได้รับของ · ของแตก · ได้ของไม่ครบ · ได้ของผิด · ลูกค้าส่งคืนของที่ไม่ใช่ของร้าน):
- สถานะพัสดุตามระบบขนส่ง (ภาพหน้าจอ):
- หลักฐานที่ร้านมี (วิดีโอแพ็กของ · รูปก่อนส่ง · หลักฐานส่งถึง) (path):
- ลูกค้าคนนี้เคยเคลมมาก่อนไหม:
- กำหนดเวลาตอบข้อพิพาทที่แพลตฟอร์มให้:

### ต้องมีในผลงาน

1. ลำดับเหตุการณ์ตามวันเวลา จากข้อมูลจริงของออเดอร์และพัสดุ
2. ทางที่เลือกตามตารางกรณีของ `returns-and-bad-reviews`: คืนเงิน · ส่งใหม่ · โต้แย้ง พร้อมเหตุผล และเทียบมูลค่าของกับเวลาและคะแนนร้านที่เสีย
3. ถ้าโต้แย้ง: รายการหลักฐานที่ต้องแนบ และร่างข้อความถึงแพลตฟอร์ม
4. ถ้าของหายหรือเสียหายระหว่างส่ง: ขั้นตอนเคลมกับขนส่งตาม `shipping-compare` · เอกสารที่ต้องใช้ · วงเงินเคลมที่ต้องตรวจกับขนส่ง
5. ร่างข้อความถึงลูกค้า สุภาพ ไม่กล่าวหา
6. กำหนดเวลาทุกขั้น เรียงตามวันครบกำหนด
7. กันเกิดซ้ำ 1 ข้อ (อัดวิดีโอแพ็กทุกออเดอร์ · เปลี่ยนวิธีแพ็ก · เปลี่ยนขนส่ง)

### กฎเฉพาะฉบับนี้

- ระยะเวลาคืนสินค้า กำหนดตอบข้อพิพาท และวงเงินเคลม ตรวจกับ Seller Centre และหน้าทางการของขนส่งรอบนี้ ติดวันที่ · ไม่มีข้อมูล → `(รอยืนยัน)`
- สงสัยว่าลูกค้าโกง → เขียนเฉพาะสิ่งที่หลักฐานแสดง ไม่ใส่คำกล่าวหาในข้อความถึงลูกค้า
- ไม่เปิดเผยข้อมูลลูกค้าในข้อความสาธารณะ
