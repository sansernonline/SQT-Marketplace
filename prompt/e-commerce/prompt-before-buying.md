# prompt-before-buying — ก่อนซื้อ: เทียบของชิ้นใหญ่ ตรวจร้านก่อนโอน

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `e-commerce` · ไฟล์นี้รวม prompt 2 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ผู้บริโภค** (โฟลเดอร์เดียวใช้ได้ทุกฉบับ)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางหลักฐาน (ใบเสร็จ แชต รูป) ไว้ใน `evidence/<เรื่อง>/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `e-commerce` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมาย · กฎหมาย เลขสายด่วน ช่องทางร้องเรียน และระยะเวลา ต้องตรวจกับแหล่งทางการรอบนี้ (ติดวันที่ตรวจ) · ส่งข้อความถึงร้าน ยื่นเรื่อง สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) หรือขอ chargeback อยู่ใน "รออนุมัติ" เสมอ · ไม่แต่งหลักฐาน · คดีที่มูลค่าสูงหรือซับซ้อน → แนะนำทนาย

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด (เช่น `warranties.csv`) ไม่กำหนด → ใช้ชื่อในตาราง

| # | งาน | playbook | ได้ไฟล์ |
|---|---|---|---|
| 1 | ตัดสินใจซื้อของชิ้นใหญ่ | `buy-decision` | `purchases/<ปี-เดือน>-<ของ>-compare.md` |
| 2 | ตรวจร้านและสินค้าก่อนโอนเงิน | `buy-decision` (ขั้น 1–2 และ 4–6) | `purchases/<ปี-เดือน>-<ของ>-seller-check.md` |

ใช้ต่อกัน: ซื้อของชิ้นใหญ่จากร้านที่ไม่รู้จัก → 1 → 2 · ซื้อแล้วเก็บประกัน → `prompt-warranty.md` ฉบับ 1 · ตรวจก่อนส่ง → `prompt-complaint.md` ฉบับ 5

## 1. ตัดสินใจซื้อของชิ้นใหญ่

playbook `buy-decision` · agent `consumer-advocate` · skill `buy-compare`
**ผลลัพธ์:** `purchases/<ปี-เดือน>-<ของ>-compare.md` · **รออนุมัติ:** สั่งซื้อ จ่ายเงิน

### ข้อมูล (ผู้ใช้กรอก)

- จะซื้ออะไร / ใช้ทำอะไร / ใช้นานแค่ไหน:
- งบ (รวมค่าติดตั้ง ค่าส่ง):
- ตัวเลือกที่มีในใจ (รุ่น ร้าน ลิงก์):
- ข้อที่ห้ามพลาด (ขนาด · ไฟ · ประกัน · ศูนย์บริการใกล้บ้าน):
- ผ่อนหรือจ่ายสด:

### ต้องมีในผลงาน

1. ตารางเทียบ 2–4 ตัวเลือก ตามเกณฑ์ที่ผู้ใช้ให้น้ำหนัก
2. ต้นทุนรวมตลอดอายุใช้งาน (ราคา + ไฟ/น้ำ/วัสดุสิ้นเปลือง + ซ่อม + ดอกเบี้ยผ่อน) คำนวณซ้ำได้
3. รีวิวที่เชื่อได้ vs ไม่ควรเชื่อ พร้อมเหตุผล
4. เงื่อนไขประกันและการคืนของแต่ละร้าน (ตรวจจากหน้าร้านจริง ติดวันที่)
5. ข้อสรุปซื้ออะไร ที่ไหน และสิ่งที่ต้องเก็บไว้หลังซื้อ (ใบเสร็จ · บัตรประกัน · เลขเครื่อง)

## 2. ตรวจร้านและสินค้าก่อนโอนเงิน

playbook `buy-decision` (ใช้ขั้น 1 เก็บความต้องการ · ขั้น 2 ตรวจราคาจากแหล่งทางการ · ขั้น 4 ตรวจรีวิวปลอม · ขั้น 5 เงื่อนไขรับประกัน · ขั้น 6 สรุป · ขั้น 3 ตารางถ่วงน้ำหนักใช้เมื่อมีหลายร้าน · จดเหตุผลตามหัวข้อ 2 ของ `superuser`) · agent `consumer-advocate` · skill `buy-compare` · `warranty-tracker`
**ผลลัพธ์:** `purchases/<ปี-เดือน>-<ของ>-seller-check.md` · **รออนุมัติ:** โอนเงิน · จ่ายมัดจำ · กดสั่งซื้อ

### ข้อมูล (ผู้ใช้กรอก)

- ซื้ออะไร ราคาเท่าไร:
- ร้านหรือผู้ขาย (ชื่อเพจ · ลิงก์ · ชื่อบัญชีที่ให้โอน · เบอร์โทร):
- ช่องทาง (แพลตฟอร์มซื้อขาย · เพจโซเชียล · LINE · กลุ่มซื้อขายของมือสอง · นัดรับ):
- ร้านขอให้จ่ายแบบไหน (โอนเต็ม · มัดจำ · ปลายทาง · ผ่านระบบของแพลตฟอร์ม):
- ภาพหน้าจอแชต ประกาศ หรือรีวิว (path):

### ต้องมีในผลงาน

1. สัญญาณเสี่ยงที่เจอในเรื่องนี้ เป็นรายการ: ราคาต่ำกว่าตลาดมาก (เทียบราคาจากร้านทางการ ติดวันที่ดู) · เร่งให้โอน · ไม่ยอมจ่ายผ่านระบบแพลตฟอร์ม · ชื่อบัญชีไม่ตรงชื่อร้าน · เพจเพิ่งเปิด · รีวิวไม่ผ่านเกณฑ์ของ `buy-compare`
2. agent ค้นชื่อบัญชีและเบอร์โทรในแหล่งตรวจสอบคนโกงที่เป็นทางการก่อน (ติดวันที่ตรวจ) แล้วบอกว่าอะไรที่มีแค่ผู้ใช้ทำได้ก่อนโอน: ขอดูของจริงหรือวิดีโอคอล · เลขเครื่องหรือเลขทะเบียน
3. ทางจ่ายที่ปลอดภัยกว่าสำหรับกรณีนี้ และสิทธิ์ขอเงินคืนของแต่ละทาง (ผ่านแพลตฟอร์ม · บัตรเครดิต · ปลายทาง · โอนตรง) · เงื่อนไขตรวจกับหน้าเงื่อนไขจริงรอบนี้
4. ของมือสอง: รายการตรวจสภาพตอนรับของ และหลักฐานที่ต้องเก็บ (แชต · สลิป · วิดีโอตอนแกะกล่อง)
5. ข้อสรุป 1 บรรทัด `ซื้อได้` · `ซื้อได้ถ้าจ่ายผ่านระบบ` · `ไม่ควรซื้อ` พร้อมเหตุผล

### กฎเฉพาะฉบับนี้

- ไม่ฟันธงว่าผู้ขายเป็นมิจฉาชีพ · เขียนเป็นสัญญาณเสี่ยงที่ชี้หลักฐานได้
- โอนไปแล้ว → `prompt-money-back.md` ฉบับ 2
