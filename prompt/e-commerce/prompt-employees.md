# prompt-employees — งานพนักงาน: กฎหมายแรงงาน รับคนใหม่ คนออก วันหยุดและวันลา

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `e-commerce` · ไฟล์นี้รวม prompt 4 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์งานบริษัท** (1 บริษัท 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางไฟล์ที่ได้รับ (รายชื่อพนักงาน · statement · หนังสือจากหน่วยงาน) ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 2`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `e-commerce` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ข้อมูลทั่วไป ไม่ใช่คำปรึกษากฎหมายหรือบัญชี · อัตราภาษี เพดานประกันสังคม ค่าแรงขั้นต่ำ กำหนดยื่น และค่าปรับ ตรวจกับกรมสรรพากร สำนักงานประกันสังคม และกรมพัฒนาธุรกิจการค้า (DBD) ในรอบนี้ ติดวันที่ · ข้อสัญญาที่มีความเสี่ยงทางกฎหมาย → ติดป้าย `(ให้ทนายตรวจ)` · การยื่นแบบ จ่ายเงิน ส่งเอกสารถึงลูกค้า broadcast ถึงผู้ติดตาม LINE และกด deploy webhook อยู่ใน "รออนุมัติ" · ใช้ token และ secret ของผู้ใช้จาก environment variable เท่านั้น ไม่เขียนลงไฟล์

**ภาษาและไฟล์:** เขียนตาม `human-writing` · เอกสารถึงลูกค้าหรือหน่วยงานส่งเป็น `.docx` (+ `.pdf` ถ้าขอ) · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 2. รับพนักงานใหม่

playbook `business-doc` (ขั้น 3 ร่างสัญญาจ้าง · ขั้น 5 ตรวจ) · ขั้นขึ้นทะเบียนและเงินเดือนประกอบเองตาม `playbook-template` (skill `superuser` หัวข้อ 2 งานกลาง) · agent `thai-doc-writer` + `tax-helper` · skill `doc-contract-th` · `labour-law-basics` · `social-security-th` · `payroll-th` · `pdpa-workflow` (ประกาศความเป็นส่วนตัวพนักงาน)
**ผลลัพธ์:** `hr/<ชื่อพนักงาน>/` — สัญญาจ้าง `.docx` · รายการวันเริ่มงาน · ข้อมูลกรอกแบบขึ้นทะเบียนผู้ประกันตน · แถวใหม่ในตารางเงินเดือน · **รออนุมัติ:** ลงนามสัญญา · ยื่นขึ้นทะเบียนกับประกันสังคม · เก็บสำเนาบัตรประชาชน

### ข้อมูล (ผู้ใช้กรอก)

- ชื่อ ตำแหน่ง วันเริ่มงาน:
- ค่าจ้าง / สวัสดิการ / ทดลองงานกี่วัน:
- จังหวัดที่ทำงาน:
- ประจำ · สัญญามีกำหนดเวลา · พาร์ตไทม์ · ฟรีแลนซ์:
- เวลาทำงาน / วันหยุดประจำสัปดาห์:
- บริษัทขึ้นทะเบียนนายจ้างกับประกันสังคมแล้วหรือยัง:

### ต้องมีในผลงาน

1. ประเภทการจ้างถูกไหม: ทำงานแบบลูกจ้างแต่จ้างเป็นฟรีแลนซ์ → เตือนพร้อมเหตุผล `(ให้ทนายตรวจ)`
2. สัญญาจ้าง: ข้อบังคับครบ · ทดลองงานและการเลิกจ้างระหว่างทดลองงานตามกฎหมาย · ข้อห้ามแข่งขันหรือรักษาความลับ → `(ให้ทนายตรวจ)`
3. ประกันสังคม: แบบที่ต้องยื่น · ภายในกี่วันนับจากวันเริ่มงาน (ตรวจกับสำนักงานประกันสังคมรอบนี้ ติดวันที่ตรวจ)
4. เงินเดือนงวดแรก: ค่าจ้างไม่ต่ำกว่าค่าจ้างขั้นต่ำของจังหวัดที่ทำงาน (ตรวจกับแหล่งทางการรอบนี้ ติดวันที่ตรวจ) · คิดตามวันทำงานจริง · ภาษีหักแบบคำนวณทั้งปี · ขอแบบแจ้งรายการลดหย่อน (ล.ย.01)
5. รายการวันเริ่มงาน: เอกสารที่ขอจากพนักงาน · ประกาศความเป็นส่วนตัวพนักงาน · บัญชีรับเงินเดือน

## 3. พนักงานลาออก หรือบริษัทเลิกจ้าง

playbook `business-doc` (ขั้น 3 ร่างหนังสือ · ขั้น 5 ตรวจ) · ขั้นคำนวณเงินและแจ้งออกประกอบเองตาม `playbook-template` (skill `superuser` หัวข้อ 2 งานกลาง) · agent `thai-doc-writer` + `tax-helper` · skill `labour-law-basics` · `social-security-th` · `payroll-th` · `doc-thai-official`
**ผลลัพธ์:** `hr/<ชื่อพนักงาน>/exit.md` — เงินงวดสุดท้าย · ค่าชดเชย (ถ้ามี) · รายการแจ้งออก · หนังสือรับรองการทำงาน `.docx` · หนังสือเลิกจ้าง `.docx` (ถ้าเลิกจ้าง) · **รออนุมัติ:** ส่งหนังสือเลิกจ้าง · จ่ายเงินงวดสุดท้ายและค่าชดเชย · ยื่นแจ้งลูกจ้างออกกับประกันสังคม

### ข้อมูล (ผู้ใช้กรอก)

- ชื่อ ตำแหน่ง วันเริ่มงาน วันทำงานวันสุดท้าย:
- ลาออกเอง · เลิกจ้าง · หมดสัญญา · เกษียณ:
- (เลิกจ้าง) เหตุผล · บอกกล่าวล่วงหน้าแล้วหรือยัง · มีหนังสือเตือนก่อนหน้าไหม (path):
- ค่าจ้างล่าสุด / วันลาพักร้อนที่เหลือ / เงินค้างอื่น (OT · คอมมิชชัน):
- ทรัพย์สินบริษัทที่ต้องคืน:

### ต้องมีในผลงาน

1. บรรทัดแรก: กรณีนี้ต้องจ่ายอะไรบ้าง ภายในวันไหน
2. ค่าชดเชย สินจ้างแทนการบอกกล่าวล่วงหน้า ค่าวันหยุดพักผ่อนที่เหลือ คำนวณให้เห็นทีละบรรทัด อ้างมาตรา (ตามอายุงาน)
3. เลิกจ้าง: เหตุที่ไม่ต้องจ่ายค่าชดเชยต้องตรงตามกฎหมายเท่านั้น · เรื่องที่อาจเป็นข้อพิพาท → `(ให้ทนายตรวจ)` ก่อนส่งหนังสือ
4. แจ้งลูกจ้างออกกับประกันสังคม: แบบและกำหนด (ตรวจกับสำนักงานประกันสังคมรอบนี้ ติดวันที่ตรวจ) · บอกพนักงานเรื่องขอรับประโยชน์กรณีว่างงานด้วยตัวเอง
5. หนังสือรับรองการทำงาน: ระบุตำแหน่งและช่วงเวลาทำงานตามจริง ไม่ใส่ความเห็น · 50 ทวิ ของปีนั้นออกให้เมื่อจ่ายงวดสุดท้าย
6. รายการปิดงาน: คืนทรัพย์สิน · ปิดบัญชีระบบ · ลบหรือเก็บข้อมูลตามประกาศความเป็นส่วนตัว

## 4. ประกาศวันหยุดบริษัทประจำปี · สรุปวันลาคงเหลือ

playbook `business-doc` (ขั้น 3 ร่างประกาศและใบลา · ขั้น 5 ตรวจ) · agent `thai-doc-writer` · skill `thai-holidays` · `labour-law-basics` · `doc-leave` · `doc-thai-official`
**ผลลัพธ์:** `hr/<ปี>-holidays.docx` (ประกาศวันหยุดตามประเพณี) · `hr/<ปี>-leave-balance.csv` (วันลาคงเหลือรายคน) · **รออนุมัติ:** ประกาศให้พนักงาน

### ข้อมูล (ผู้ใช้กรอก)

- ปี:
- วันทำงาน / วันหยุดประจำสัปดาห์:
- วันหยุดที่อยากหยุดเพิ่ม (สงกรานต์ยาว · ปีใหม่):
- รายชื่อพนักงาน วันเริ่มงาน วันลาที่ใช้ไปแล้ว (path):
- นโยบายวันลาของบริษัท (ถ้ามี) (path):

### ต้องมีในผลงาน

1. วันหยุดตามประเพณีจากประกาศจริงของปีนั้น ติดวันที่ตรวจ · จำนวนวันขั้นต่ำและวันที่ต้องมีตามกฎหมาย (อ้างมาตรา)

4. วันลาคงเหลือรายคน: ลาพักร้อนตามอายุงาน · ลาป่วย · ลากิจ · สูตรคำนวณซ้ำได้
5. ใครลาเกินสิทธิ์ หรือมีพักร้อนเหลือมากใกล้สิ้นปี → ธงพร้อมทางเลือก (ใช้ · สะสม · จ่ายเงินแทน ตามนโยบายและกฎหมาย)
