# prompt-stock-and-profit — กำไร สต็อก ปิดยอด ภาษี

ใช้คู่กับ plugin `e-commerce` · ไฟล์นี้รวม prompt 5 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ร้าน** (1 ร้าน 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปสินค้า แชตลูกค้า รายงานยอดขาย ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `e-commerce` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ใน skill นั้นที่เดียว ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 2

**ขอบเขต:** ค่าธรรมเนียมแพลตฟอร์ม ค่าส่ง และนโยบายคืนสินค้า เปลี่ยนบ่อย → ตรวจกับ Seller Centre หรือหน้าทางการรอบนี้ ติดวันที่ · คำโฆษณาต้องผ่านกฎ อย. (สำนักงานคณะกรรมการอาหารและยา) และ สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) · ไม่แต่งรีวิว · การลงขายจริง ส่งข้อความถึงลูกค้า คืนเงิน เปลี่ยนราคาบนร้าน อยู่ใน "รออนุมัติ" · เรื่องภาษีเป็นข้อมูลทั่วไป ยืนยันกับนักบัญชี

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. ขายแล้วไม่เหลือกำไร / จัดโปร

playbook `pricing-check` · agent `shop-manager` · skill `marketplace-fees-pricing`
**ผลลัพธ์:** `pricing/<ปี-เดือน>-check.md` · **รออนุมัติ:** เปลี่ยนราคาบนร้าน · เปิดโปร

### ข้อมูล (ผู้ใช้กรอก)

- สินค้าที่สงสัย (หรือ "ทั้งร้าน" + ไฟล์รายการ):
- ราคาขายปัจจุบัน / ต้นทุน / แพลตฟอร์ม:
- รายงานยอดขายหรือ statement จากแพลตฟอร์ม (path):
- โปรที่จะจัด (ลด % · แจกโค้ด · ส่งฟรี · ซื้อ 2 แถม 1):

### ต้องมีในผลงาน

1. กำไรจริงต่อชิ้นต่อแพลตฟอร์ม เทียบกับ statement จริง (ไม่ใช่สูตรอย่างเดียว)
2. สินค้าที่ขาดทุน / กำไรบาง เรียงจากหนักสุด พร้อมสาเหตุ
3. ราคาใหม่ที่ได้กำไรตามเป้า · ราคาต่ำสุดที่ยังไม่ขาดทุน
4. ถ้าจัดโปร: กำไรหลังโปร และยอดขายที่ต้องเพิ่มเพื่อคุ้ม

## 2. ขายหลายแพลตฟอร์มแล้วสต็อกเพี้ยน

playbook `stock-sync` · agent `shop-manager` · skill `multi-shop-stock`
**ผลลัพธ์:** `stock.csv` (สต็อกหลักไฟล์เดียว) · `stock-rules.md` (กฎ sync) · **รออนุมัติ:** แก้ตัวเลขสต็อกบนแพลตฟอร์ม

### ข้อมูล (ผู้ใช้กรอก)

- แพลตฟอร์มที่ขาย:
- ไฟล์ export สต็อกจากแต่ละแพลตฟอร์ม (path):
- นับของจริงล่าสุด (ไฟล์หรือตัวเลข):
- ใช้โปรแกรมจัดการร้านไหม (ชื่อ):
- เคยขายเกินกี่ครั้ง / สินค้าไหน:

### ต้องมีในผลงาน

1. ตารางสต็อกหลัก: SKU (Stock Keeping Unit — รหัสสินค้า) · ชื่อ · ของจริง · จองแล้ว · แต่ละแพลตฟอร์ม · ส่วนต่าง
2. SKU ที่ตั้งชื่อไม่ตรงกันระหว่างแพลตฟอร์ม → ตารางจับคู่
3. กฎ sync: ใครอัปเดต เมื่อไร · กันขายเกินด้วยการกันของ (buffer) เท่าไร
4. จุดสั่งซื้อซ้ำต่อ SKU จากยอดขายจริง

## 3. ของค้างสต็อก อยากระบายออก

playbook `pricing-check` · agent `shop-manager` · skill `marketplace-fees-pricing` · `multi-shop-stock`
**ผลลัพธ์:** `pricing/<ปี-เดือน>-clearance.md` · **รออนุมัติ:** เปลี่ยนราคาบนร้าน · เปิดโปร · ทำชุดสินค้า (bundle) ใหม่บนร้าน

### ข้อมูล (ผู้ใช้กรอก)

- สินค้าที่ค้าง / จำนวนคงเหลือ (หรือ `stock.csv`):
- ต้นทุนต่อชิ้น / ราคาขายปัจจุบัน / แพลตฟอร์ม:
- ขายได้เดือนละกี่ชิ้นช่วง 3 เดือนหลัง:
- สินค้ามีวันหมดอายุ หรือตกรุ่นตามฤดูไหม:
- ต้องการเงินสดคืนภายในวันไหน:

### ต้องมีในผลงาน

1. ตารางของค้าง: SKU · คงเหลือ · ขายต่อเดือน · กี่เดือนจะหมดถ้าขายแบบเดิม · ทุนที่จมอยู่ (บาท)
2. ทางระบาย 2–3 แบบต่อ SKU (ลดราคา · จัดชุดกับสินค้าขายดี · ของแถม · ขายยกล็อต) พร้อมกำไรหรือขาดทุนต่อชิ้นของแต่ละแบบ
3. ราคาต่ำสุดที่ยังไม่ขาดทุน และราคาที่ยอมขาดทุนได้ถ้าต้องการเงินสดคืน (บอกให้ชัดว่าขาดทุนเท่าไร)
4. ข้อสรุปเรียงตาม SKU ที่ควรระบายก่อน
5. ต้นเหตุที่ของค้าง (สั่งเกิน · ราคาสูง · หน้าสินค้าไม่ดี) และจุดสั่งซื้อซ้ำใหม่ตาม `multi-shop-stock`

### กฎเฉพาะฉบับนี้

- ราคาลดที่ต่ำกว่าทุน → ระบุในรายงานว่า "ขาดทุนโดยตั้งใจ" พร้อมยอดรวม ผู้ใช้เป็นคนตัดสิน
- หน้าสินค้าเป็นต้นเหตุ → ชี้ไป `prompt-open-shop.md` ฉบับ 3

## 4. ปิดยอดรายเดือน

playbook `pricing-check` (ขั้น 1–2: ต้นทุนและกำไรจริงต่อชิ้น + ขั้นสุดท้าย reviewer ตัวใหม่ตรวจ) · agent `shop-manager` · skill `marketplace-fees-pricing` · `seller-tax-basics`
**ผลลัพธ์:** `reports/<ปี-เดือน>-summary.md` · ตารางยอดสะสมทั้งปีต่อท้ายในไฟล์เดียวกัน

### ข้อมูล (ผู้ใช้กรอก)

- เดือนที่ปิดยอด:
- รายงานยอดขายหรือ statement ของทุกแพลตฟอร์ม + ยอดขายนอกแพลตฟอร์ม (LINE · Facebook · หน้าร้าน) (path):
- ต้นทุนสินค้าและค่าใช้จ่ายอื่น (ค่าแพ็ก · ค่าโฆษณา · ค่าจ้าง) (path หรือตัวเลข):
- เงินที่โอนเข้าบัญชีจริงเดือนนี้ (ไม่บังคับ):

### ต้องมีในผลงาน

1. ตารางต่อแพลตฟอร์ม: ยอดขาย · ค่าธรรมเนียมแต่ละตัว · ค่าส่งที่ร้านจ่าย · ส่วนลดที่ร้านออก · คืนเงิน · เงินเข้าจริง
2. กำไรจริงของเดือน = เงินเข้าจริง − ต้นทุนสินค้า − ค่าใช้จ่ายอื่น คำนวณซ้ำได้
3. สินค้าขายดี 5 อันดับ และสินค้าที่กำไรต่อชิ้นต่ำสุด 5 อันดับ
4. ยอดขายสะสมทั้งปี เทียบเกณฑ์จดภาษีมูลค่าเพิ่ม (VAT) ตาม `seller-tax-basics` (เกณฑ์ตรวจกับกรมสรรพากรรอบนี้ ติดวันที่)
5. ยอดในรายงานกับเงินเข้าบัญชีไม่ตรงกัน → ตารางส่วนต่าง ไม่ปัดทิ้ง

### กฎเฉพาะฉบับนี้

- ตัวเลขทุกตัวมาจากไฟล์ที่ผู้ใช้ให้ ไม่มีไฟล์ของแพลตฟอร์มไหน → ใส่ `(รอยืนยัน)` ห้ามประมาณ
- ใช้เป็นข้อมูลตั้งต้นของฉบับ 5 ตอนปลายปี

## 5. ภาษีของคนขายออนไลน์

skill `seller-tax-basics` · agent `shop-manager` · งานกลาง ไม่ต้องเปิด playbook
**ผลลัพธ์:** `tax/<ปี>-estimate.md` · ข้อมูลทั่วไป ยืนยันกับนักบัญชี

### ข้อมูล (ผู้ใช้กรอก)

- ขายในนามบุคคล หรือบริษัท:
- ยอดขายทั้งปี (หรือรายเดือน):
- ค่าใช้จ่ายจริงที่มีหลักฐาน (ไม่บังคับ):
- รายได้อื่น (เงินเดือน ฯลฯ):

### ต้องมีในผลงาน

1. ประเภทเงินได้ และหักค่าใช้จ่ายแบบเหมา vs ตามจริง แบบไหนเสียน้อยกว่า (คำนวณให้เห็น)
2. แบบที่ต้องยื่นและเดือนที่ยื่น: บุคคล → ภ.ง.ด. 94 ครึ่งปี · ภ.ง.ด. 90 สิ้นปี · บริษัท → ภ.ง.ด. 51 ครึ่งปี · ภ.ง.ด. 50 สิ้นปี (ติดตั้ง `thai-workplace` ไว้ → ใช้ `prompt-tax-filing.md` ฉบับ 3) · กำหนดยื่นตรวจกับกรมสรรพากรรอบนี้ ติดวันที่ตรวจ
3. ใกล้เกณฑ์ต้องจด VAT แค่ไหน และต้องทำอะไรเมื่อถึง
4. เอกสารที่ควรเก็บตั้งแต่วันนี้
5. อัตราและเกณฑ์ตรวจกับกรมสรรพากรรอบนี้ ติดวันที่
