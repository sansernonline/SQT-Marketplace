# prompt-campaign-live — วันแคมเปญใหญ่ และไลฟ์ขายของ

ยังไม่ได้ทดสอบจริง

ใช้คู่กับ plugin `e-commerce` · ไฟล์นี้รวม prompt 3 ฉบับ · 1 ฉบับ = 1 งาน

## วิธีใช้

1. เปิด Claude Code, Codex CLI หรือ Gemini CLI ที่**โฟลเดอร์ร้าน** (1 ร้าน 1 โฟลเดอร์)
2. กรอกช่อง "ผู้ใช้กรอก" ของฉบับที่จะทำ · วางรูปสินค้า แชตลูกค้า รายงานยอดขาย ไว้ใน `inbox/`
3. วางทั้งไฟล์ แล้วพิมพ์ต่อท้ายว่าจะทำฉบับไหน เช่น `ทำข้อ 1`

**กฎการทำงาน (agent ต้องทำตาม):** เปิด skill `superuser` ของ plugin `e-commerce` ก่อนเริ่ม แล้วทำตาม playbook ที่ฉบับนั้นระบุทุกขั้น · กฎร่วม (อ่าน `.claude/superuser/CONTEXT.md` ก่อนเริ่ม · ถามแบบเลือกคำตอบตอนเริ่มและตอนจบ ไม่หยุดถามกลางทาง · บันทึกการตัดสินใจ · รายการ "รออนุมัติ" · รอบเรียนรู้ · สรุปงานตอนจบ) อยู่ในแกนของ plugin `superuser` ที่ skill นั้นใช้ร่วม ไม่เขียนซ้ำที่นี่ · ช่อง "ผู้ใช้กรอก" ที่ยังว่างและจุดที่ต้องเลือก → ถามรวมครั้งเดียวก่อนเริ่ม แบบเลือกคำตอบ ทุกตัวเลือกมีหลักฐาน ไม่ได้คำตอบ → ใส่ `(รอยืนยัน)` แล้วทำต่อ · skill ที่อ้างข้าม plugin (ชื่อ plugin อยู่ในวงเล็บ) ไม่ได้ติดตั้ง → ข้ามแล้วบอกในรายงาน · เปิดผ่านคำสั่ง skill ไม่ได้ → อ่าน `skills/<ชื่อ>/SKILL.md` ในโฟลเดอร์ plugin แทน · ไม่มี agent ที่อ้าง → ใช้ agent ทั่วไปพร้อมเปิด `agents/<ชื่อ>.md` · หาไม่เจอทั้ง 2 ทาง → ข้ามชิ้นนั้น ทำส่วนอื่นให้จบ แล้วรายงานว่าติด

**วนจนเสร็จ (agent loop):** ทุกฉบับวน ทำ → ตรวจ → แก้ → ตรวจซ้ำ จนผ่านทุกข้อที่ฉบับนั้นต้องมี · ตรวจด้วยหลักฐานจริง (เปิดไฟล์ · รันคำสั่ง · เทียบแหล่ง) ไม่ใช่คำบอกของตัวที่ทำ · รอบตรวจใช้ `reviewer` ตัวใหม่ทุกรอบ · ไม่ผ่าน → แก้ที่ต้นเหตุแล้วตรวจซ้ำทั้งข้อเดิมและจุดที่แก้ · เหลือแค่ข้อระดับต่ำ → ปิดได้แล้วลงรายงาน · ครบเพดานรอบ (งานกลาง 3 · งานใหญ่หรืองานเสี่ยง 5) ยังไม่ผ่าน → ติดป้าย `ติด` ทำส่วนอื่นให้จบ แล้วรายงานข้อที่เหลือ · รายละเอียดอยู่ใน skill `superuser` กฎข้อ 3

**ขอบเขต:** ค่าธรรมเนียมแพลตฟอร์ม ค่าส่ง และนโยบายคืนสินค้า เปลี่ยนบ่อย → ตรวจกับ Seller Centre หรือหน้าทางการรอบนี้ ติดวันที่ · คำโฆษณาต้องผ่านกฎ อย. (สำนักงานคณะกรรมการอาหารและยา) และ สคบ. (สำนักงานคณะกรรมการคุ้มครองผู้บริโภค) · ไม่แต่งรีวิว · การลงขายจริง ส่งข้อความถึงลูกค้า คืนเงิน เปลี่ยนราคาบนร้าน อยู่ใน "รออนุมัติ" · เรื่องภาษีเป็นข้อมูลทั่วไป ยืนยันกับนักบัญชี

**ภาษาและไฟล์:** เขียนตาม `human-writing` · ชื่อไฟล์ตามที่ skill กำหนด ไม่กำหนด → ใช้ชื่อในตาราง

## 1. เตรียมวันแคมเปญใหญ่

playbook `pricing-check` (ราคาและเพดานส่วนลด) · agent `shop-manager` · skill `marketplace-fees-pricing` · `multi-shop-stock`
**ผลลัพธ์:** `campaigns/<ปี-เดือน-วัน>-plan.md` · **รออนุมัติ:** สมัครเข้าร่วมแคมเปญของแพลตฟอร์ม · ตั้งราคาโปรบนร้าน · สั่งของเพิ่ม

### ข้อมูล (ผู้ใช้กรอก)

- แคมเปญ / วันที่ / แพลตฟอร์ม:
- เงื่อนไขแคมเปญที่แพลตฟอร์มแจ้ง (ค่าธรรมเนียมเพิ่ม · ส่วนลดขั้นต่ำ · โค้ดส่งฟรี) (วาง หรือ path):
- สินค้าที่จะเข้าแคมเปญ / ต้นทุน / ราคาปกติ:
- สต็อกตอนนี้ (หรือ `stock.csv`) / สั่งของเพิ่มได้ภายในกี่วัน:
- ยอดขายแคมเปญเดียวกันปีที่แล้ว (ถ้ามี):

### ต้องมีในผลงาน

1. ตารางราคาแคมเปญต่อ SKU (Stock Keeping Unit — รหัสสินค้า): ราคาโปร · ค่าธรรมเนียมทุกตัวรวมค่าแคมเปญ · ส่วนลดที่ร้านออก · กำไรต่อชิ้น · ราคาต่ำสุดในแคมเปญ (campaign floor)
2. SKU ที่ไม่ควรเข้าแคมเปญเพราะขาดทุน พร้อมตัวเลข
3. สต็อกที่ต้องมีช่วงแคมเปญ คิดจากยอดปีที่แล้ว ไม่ใช่ยอดเดือนนี้ (ตาม `multi-shop-stock`) · ของที่ต้องสั่งเพิ่มและวันที่ต้องสั่ง
4. กันของ (buffer) ต่อแพลตฟอร์มกันขายเกิน
5. ปฏิทินงาน: วันสมัคร · วันตั้งราคา · วันล็อกสต็อก · วันไลฟ์ (ถ้ามี) · วันแพ็กของ

### กฎเฉพาะฉบับนี้

- เงื่อนไขและค่าธรรมเนียมแคมเปญตรวจกับ Seller Centre รอบนี้ ติดวันที่ · ไม่มีข้อมูล → `(รอยืนยัน)`
- ไม่มียอดปีที่แล้ว → บอกว่าใช้ตัวเลขอะไรแทนและเสี่ยงอย่างไร

## 2. เตรียมไลฟ์ขายของ

playbook `live-session` · agent `live-seller` · skill `live-selling-script`
**ผลลัพธ์:** `live/<ปี-เดือน-วัน>-runsheet.md` พิมพ์หรือเปิดข้างจอระหว่างไลฟ์ได้

### ข้อมูล (ผู้ใช้กรอก)

- แพลตฟอร์ม / วันเวลา / ความยาว (นาที):
- สินค้า ราคา สต็อก ที่จะขาย:
- ดีลพิเศษ (flash deal · โค้ด · ของแถม):
- คนไลฟ์กี่คน / มีผู้ช่วยตอบแชตไหม:
- ไลฟ์ครั้งก่อนเป็นอย่างไร (ยอดคนดู · ยอดขาย ถ้ามี):

### ต้องมีในผลงาน

1. run sheet รายนาที: ช่วง · สินค้า · สิ่งที่พูด · ดีล · คำชวนซื้อ

4. ผลตรวจคำพูดต้องห้าม (เกินจริง · อ้างรักษาโรค · เทียบคู่แข่งแบบผิดกฎ)
5. เช็กลิสต์ก่อนกดไลฟ์ (สต็อก · ลิงก์สินค้า · แสง เสียง)

## 3. สรุปหลังไลฟ์

playbook `live-session` (ขั้น 1: เลือกสินค้าและดีลรอบหน้า + ขั้นสุดท้าย reviewer ตัวใหม่ตรวจ) · ส่วนสรุปตามข้อ "After the live" ของ skill `live-selling-script` · agent `live-seller` · skill `chat-reply-templates`
**ผลลัพธ์:** `live/<ปี-เดือน-วัน>-recap.md` · ร่างตอบคำถามที่ค้างในแชต · **รออนุมัติ:** ส่งข้อความตอบลูกค้า

### ข้อมูล (ผู้ใช้กรอก)

- ไลฟ์วันไหน / run sheet ที่ใช้ (path):
- ตัวเลขจากแพลตฟอร์ม: คนดูรวม · คนดูสูงสุด · ออเดอร์ · ยอดขาย (ภาพหน้าจอหรือไฟล์):
- คำถามที่ลูกค้าถามบ่อยในไลฟ์ / คอมเมนต์ที่ยังไม่ได้ตอบ:
- ช่วงที่คนดูหลุดเยอะ (ถ้าจำได้):

### ต้องมีในผลงาน

1. ตารางผล: คนดูรวม · คนดูสูงสุด · ออเดอร์ · ยอดขาย · ยอดต่อคนดู เทียบไลฟ์ครั้งก่อน
2. ช่วงไหนในรายการ (run sheet) ที่ขายได้ และช่วงไหนคนหลุด
3. คำถามที่ถามบ่อย → ใส่ไว้ในบทพูดรอบหน้า และร่างตอบคำถามที่ค้าง
4. บทเรียน 3 ข้อสำหรับรอบหน้า
5. สินค้าและดีลที่เสนอสำหรับไลฟ์ครั้งถัดไป

### กฎเฉพาะฉบับนี้

- ตัวเลขมาจากแพลตฟอร์มเท่านั้น ไม่มี → ใส่ `(รอยืนยัน)` ห้ามเดา
